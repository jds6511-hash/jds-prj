## 1. 반드시 고쳐야 할 것

### 1-1. α 식 방향 — 문서 오류 확정

`src/m5_search.py:39`:

```python
return alpha * s_sub_n + (1 - alpha) * s_cap_n   # 4) 가중합
```

**α는 자막(subtitle)에 붙는다.**

```
score = α · subtitle + (1−α) · caption
α = 0.0 → 캡션 단독 / α = 1.0 → 자막 단독
```

`docs/tutor/자문요청_캡션모델선택_2026-08-17.md` §1에 `α·caption + (1−α)·subtitle`로
적혀 있었다 — **틀렸다.** 뒤에서 α=0.0을 캡션 단독으로 쓴 서술이 맞다.

*판정에는 영향 없다(코드는 처음부터 일관).* 문서 표기만 고친다.

### 1-2. `+0.0377`은 model+prompt bundle 효과다

`docs/probes/aihub_model_confirm.py:56-57`:

```python
CONTROL   = ("qwen25_3b_4bit", "P0")   # 현행 설정 그대로
CANDIDATE = ("qwen3vl_4b",     "P1")   # dev 1단계 격자의 승자
```

bf16 맞춤 재실행의 arm 이름도 `qwen25_3b/**P0**` vs `qwen3vl_4b/**P1**`
(`_scratch/aihub_confirm_bf16matched.json`).

**두 arm의 프롬프트가 다르다.** 따라서 AI Hub 1,086의
캡션 단독 **+0.0377 CI[0.0134, 0.0608]**는

- ~~"4B가 3B보다 낫다"(모델 효과)~~
- **"4B/P1 구성이 3B/P0 구성보다 낫다"(model+prompt bundle 효과)**

로만 읽어야 한다.

**이건 I1 실패의 프롬프트 교락과 같은 뿌리다**(마감 문서 §2-2). 그때는 오염 검출에
국한된 문제로 봤는데, **주 판정 지표에도 걸려 있다.**

> **다만 이것이 "4B가 안 좋다"는 뜻은 아니다.** 프롬프트도 후보의 일부로 함께
> 선택된 구성이므로, 배포 관점에서는 bundle 비교가 오히려 실무적으로 옳다.
> 문제는 **"모델 효과"라고 부른 표기**다.

**분리하려면** `3B/P1` arm이 필요하다. 현재 없다.

## 3. 새로 드러난 결함 — per_query 미저장

**AI Hub 산출물 7개 전부에 `per_query`가 없다.** 집계값(mrr·hit@k·by_type)만 저장했다.

`src/m6_evaluate.py:186`:

```python
idx_b = rng.integers(0, n, size=(B, n))   # n = len(dev_queries)
```

**부트스트랩 재표집 단위가 질의다.** AI Hub는 **194영상에 1,086질의가 중첩**돼 있어
같은 영상의 질의가 상관될 수 있고, 그러면 CI가 실제보다 좁게 나온다.

**재표집 단위를 바꾼 재분석에는 질의별 순위가 필요한데 저장돼 있지 않다.**
"생성물 전량 저장" 규약을 캡션에는 지켰고 **지표에는 안 지켰다.**

**복구 경로는 있다.** 서버에 arm별 캡션이 남아 있다
(`_scratch/aihub_confirm_captions/qwen25_3b__P0.json`, `qwen3vl_4b__P1.json`).
**재임베딩(KURE-v1, 약 2,300구간 + 1,086질의)만 하면 per_query를 복원**할 수 있다.
VLM이 아니라 임베더라 수 분이다.

### 3-1. 해소됨 (2026-08-17 당일) — 판정은 바뀌지 않았다

복구했고 재분석했다. 상세: **`docs/재분석_전달분해_2026-08-17.md`**,
스크립트 `docs/probes/aihub_transfer_decomp.py`, 결과
`_scratch/aihub_transfer_decomp{,_bf16}.json`.

자기검증 게이트 통과 — 질의 단위 재집계가 두 arm 짝 모두에서 저장값과
소수 4자리까지 일치(0.0342/0.0233, 0.0377/0.0187).

| | 결과 |
|---|---|
| **주지표 `+0.0377`** | query · video-cluster · video-macro **세 방식 전부 0 배제** |
| **융합 `+0.0187`** | 세 방식 전부 **0 포함** |
| **video-cluster CI** | 질의 단위보다 **좁거나 같다.** 넓어지지 않음 |
| **ICC(1)** | 네 측정 전부 **음수**(−0.020~−0.032), **설계효과 < 1** |

**클러스터 보정은 필요 없었다.** 쌍체 차이에서는 영상 수준 효과가 상쇄돼
영상내 양의 상관이 남지 않는다. 질의 단위 CI는 반보수적이 아니라 약간 보수적이었다.

남는 민감성은 **재표집 단위가 아니라 가중(estimand)** 쪽이다 — 배포 4bit 짝에서만
video-macro가 0을 포함한다(+0.0342 → +0.0201). 사전등록 주지표는 질의가중이므로
판정은 유지된다.

**`per_query` 미저장 자체는 여전히 결함이다** — 이번엔 캡션이 보존돼 있어 복구됐을
뿐이다. `m6_evaluate`가 항상 저장하도록 고치는 일은 §6-4로 남아 있다.
