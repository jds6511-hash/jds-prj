## 2. 산술적 진단 — **원인 확정 아님**

아래는 §1 수치의 산술 분해다. **새 지표를 만들지 않았다.**

| 영상 | 길이 | 생성 사건 | reference | 차이 | 기각 |

**두 영상의 평균 배수는 정의하지 않았다** — 개별 값으로만 쓴다.

사람 reference span 중앙값은 두 영상 모두 대략 6~7구간(30~35초)이다.

### coarse granularity 가설

세 사실이 같이 선다.

1. reference 53건 대비 **생성 사건 수가 적다**
2. `timeline_span_coverage`는 **0.87~0.96으로 높다**
3. 1:1 matching 때문에 threshold recall의 최대치가 생성 사건 수에 제한된다

따라서 **"타임라인을 못 본다"보다 "넓은 span 몇 개로 여러 인간 사건을 묶는다"가
우선 가설**이다.

**낮은 temporal recall의 주요 설명은 생성 사건 수가 reference보다 크게 적다는
점이다.** 생성 사건의 대부분은 적어도 하나의 reference와 시간적으로 겹치지만
(`gwaktube` 12건 중 10건, `kheritage` 8건 전부), 일부는 IoU가 낮다
(`kheritage`는 8건 매칭 중 `IoU>=0.3`을 만족한 것이 6건). **정확한 실패 유형은
개별 사례 열람 전에는 확정하지 않는다.**

> **"위치 오류가 아니다"라고 쓰지 마라.** 지금 지표가 지지하는 것은
> **입도 부족이 주요 병목**이라는 것까지다.

## 3. 다음 단계 — 탐색적으로 분리한다

개별 사건을 열어 실패 유형 빈도만 기술한다. **새 threshold·새 지표를 만들지
않는다.** 분류는 다음으로 고정한다.

```
overmerge          여러 human event를 하나의 generated event로 묶음
boundary_too_wide
boundary_shift
missed_event
spurious_event
reasonable_match
```

`overmerge`가 대부분이면 다음 M8 개선 방향은 프롬프트·모델 교체보다
**event granularity 규칙**이다.

**표본은 소비됐다**(§5-6). `gwaktube`·`kheritage`는 이후 metric·threshold·
event-unit 규칙 변경의 확증 표본으로 재사용하지 않는다. semantic rubric을 새로
만들 경우 이 두 영상에서 확증하지 않는다.
