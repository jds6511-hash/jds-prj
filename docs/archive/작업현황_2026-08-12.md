## 2. 환경 효과는 허구였다

### 무엇을 믿고 있었나

dev 96건에서 **같은 모델·같은 설정인데 노트북 생성분이 서버 생성분보다 0.093 높다**는
결과가 나왔다(8/7 −0.0879와 일치해 재현으로 판단). 그 전제가 아래를 전부 규정했다.

```
환경 효과 0.09 → 노트북 생성 필수 → 6GB 제약 → 후보 4B 이하 + 4bit 강제 → 이득 소멸
```

### 검증 (AI Hub A 절반, 97영상·562질의)

같은 모델·같은 4bit·같은 프롬프트로 노트북에서 캡션을 새로 만들어 저장된 서버
캡션과 쌍체 비교했다. 판정 규칙은 결과 전 확정.

```
서버 0.4872 · 노트북 0.4826 · 완전일치 23.2%
Δ(노트북−서버) −0.0046  CI[−0.0267, +0.0174]  p=0.6844
```

**"못 쟀다"가 아니다.** n=562의 MDE는 ±0.036인데 **CI 상한이 +0.017**이다. 0.09는
물론이고 0.02 넘는 노트북 우위도 배제된다.

### 왜 dev에서는 나왔나

dev 96건의 검출 한계가 **±0.086**이다. 0.09는 정확히 그 노이즈 최대값 크기다.
8/7과 8/10 두 번 "재현"된 것도 **같은 dev 96건**을 두 번 본 것이라 독립 증거가
아니었다.

### 사전 등록한 해석 규칙이 걸린 지점

§7-d(8/10)에 이렇게 적어뒀다 — *"재현 안 되면 노트북에 유리한 편향이 있는데도
안 나온 것이라 단순 음성보다 강한 증거다."* config(`caption_prompt`·`rep_penalty`·
`max_pixels`)가 전부 노트북 캡션을 보고 튜닝됐는데도 효과가 없었다.
**편향 분리 실험(§7-e, 노트북 GPU 15시간)은 불필요해졌다** — 분리할 효과가 없다.

### 부수 사실

기계를 건너면 캡션 문장의 **77%가 실제로 달라진다**(완전일치 23.2%). 그런데

## 3. 캡션 모델 — 정밀도를 맞춰도 이긴다

### 왜 다시 쟀나

8/10의 독립 확증은 **현행 4bit vs 후보 bf16**이었다. 6GB 노트북이 배포 조건이던
때는 맞는 대조였지만, 서버 통일이 가능해지면 현행도 bf16으로 돈다. 그러면
+0.0342 중 얼마가 모델이고 얼마가 정밀도인지 갈리지 않는다.

무시할 수 없는 크기였다 — 후보 모델의 4bit 손실이 **−0.0604**로 실측됐기 때문이다.

### 결과 (AI Hub 194영상·1,086질의, 둘 다 bf16)

| arm | 길이 | 오염 | 캡션단독 | 융합 | hit@1 |
|---|---|---|---|---|---|
| qwen25_3b/P0 (현행) | 131.4 | 22 | 0.4773 | 0.4741 | 0.2864 |
| **qwen3vl_4b/P1 (후보)** | 97.6 | 19 | **0.5150** | 0.4928 | **0.3287** |

| 지표 | Δ | 95% CI | 판정 |
|---|---|---|---|
| **캡션단독** (사전 등록 주 지표) | **+0.0377** | [0.0134, 0.0608] | **통과** |
| hit@1 (캡션단독) | +0.0424 | [0.0092, 0.0764] | 통과 |
| 융합 α=0.5 | +0.0187 | [−0.0019, +0.0395] | **비유의** |

**교란은 해소됐다.** 3B의 bf16(0.4773)은 4bit(0.4808)와 사실상 같다 — 오히려 미세하게
낮다. 즉 8/10의 +0.0342는 정밀도 효과가 아니었고, 정밀도를 맞추니 **+0.0377로 오히려
커졌다.** 3B에서 양자화가 공짜라는 8/7 관측이 독립 표본에서 확인된 셈이다.

### 그런데 융합에서는 유의하지 않다 — 이걸 어떻게 읽나

**두 가지를 같이 말해야 한다.**

**(1) 채널 희석.** 후보는 캡션 채널만 바꾸는데 융합은 자막 채널을 절반 섞는다.
규약 1항(채널 격리)이 존재하는 이유가 이것이고, 그래서 주 지표를 캡션 단독으로
**결과 보기 전에** 정해뒀다.

**(2) α가 현행에 맞춰져 있다.** 융합은 α=0.5에서 쟀는데, 이 값은 **현행 캡션으로
dev에서 튜닝된 값**이다. 규약 3항(현행 전용 설정 재탐색)이 겨냥하는 상황이다.

**그런데 dev로는 후보의 α를 다시 정할 수 없다.** dev α 곡선은 이렇다.

```
현행 qwen25_3b_4bit/P0   점추정 최고 α=0.5   융합 0.6164   규칙상 α*=0.5
후보 qwen3vl_4b/P1       점추정 최고 α=0.4   융합 0.6791   규칙상 α*=0.6
                         (α=0.5에서 0.6663 · α=0.6에서 0.6183)
```

`alpha_star`는 점추정 1위를 기준으로 **쌍체차 CI가 0을 포함하는 α들(tie_set)** 중
큰 값을 고른다(자막 우선, DESIGN_SPEC 8-1). 후보의 점추정 최고는 0.4인데 규칙이
고른 값은 **0.6**이다. 즉 **0.4와 0.6이 dev에서 구분되지 않는다** — n=96, MDE ±0.086인데
곡선의 이 구간 차이가 0.06이다.

**따라서 "α를 재탐색하면 융합 이득이 커진다"고 말할 근거가 없다.** 규칙대로 α*=0.6을
쓰면 dev 점추정은 오히려 α=0.5보다 낮다. 융합 비유의를 α 탓으로 돌리지 않는다.

AI Hub에서 α를 다시 골라 최고값을 보고하는 것도 안 된다 — 확증 표본에서 고르는
것이 되기 때문이다. **α 문제는 dev 규모(96건)로는 풀리지 않는다는 것이 결론이고,
이건 융합 이득의 크기를 확정할 수 없다는 한계로 남는다.**

## 5. M9 판정자 — 지표가 아니라 심판이 부족했다

정답을 아는 문항(캡션을 그대로 옮긴 양성, 다른 영상 세그먼트인 음성)으로 판정자를
검정했다. 통과선은 양성·음성 **둘 다 ≥0.75**.

| 판정자 | groundedness (양성/음성) | coverage (양성/음성) | 판정 |
|---|---|---|---|
| Qwen2.5-7B (현행, bf16) | 0.817 / 1.000 | **0.550** / 0.983 | 탈락 |
| kanana-1.5-8B (다른 계열, bf16) | 0.850 / 1.000 | **0.417** / 1.000 | 탈락 |
| **Qwen2.5-14B (같은 계열, 4bit)** | 1.000 / 1.000 | **0.767** / 0.933 | **통과** |

**패밀리 축은 답이 나왔다** — 다른 계열로 바꾸면 오히려 나빠진다. 자기평가 편향
문제가 아니다. **용량 축이 원인**이었다.

두 가지 단서를 병기한다.

- 14B는 통과선 0.75를 **0.767로 겨우 넘겼다.** 셀당 60문항이라 여유가 작다.
- 14B만 VRAM 때문에 **4bit로 돌았다.** 양자화는 보통 불리하게 작용하므로, 불리한
  조건에서도 통과한 것은 결론을 약화시키지 않는다.

**영향.** M9는 이미 test에서 두 번 돌았다(공식 평가 7회 중 리포트 2회). 그 coverage
수치는 **탈락한 판정자가 매긴 점수**다. 재산출하거나 한계를 명시해야 한다.
groundedness는 현행 판정자도 통과했으므로 영향 없다.

## 6. 남은 결정과 제안

### 6-a. 결정 지점 — 캡션 모델을 채택할 것인가 (승인 필요)

**채택 근거는 갖춰졌다.**
- dev에서 선별 → 제3자 데이터에서 확증, 규칙은 결과 전 커밋
- 정밀도까지 맞춘 대조에서 주 지표 통과 (+0.0377)
- 채택을 막던 유일한 사유(환경 효과)가 소멸

**대가.**
```
M3 재생성(7편, 서버 bf16) → m4 → α 재탐색 → τ 재캘리브레이션
→ M8/M9 재실행 → test 재평가 (접촉 8회차)
```

**재평가 전에 고정할 것** — 결과를 보기 전에 문서화한다.
서버 통일 여부 · 모델 · 프롬프트 · α 재탐색 격자 · τ 재캘리브레이션 규칙 ·
성공/실패 판정 기준.

### 6-b. α 재탐색은 답이 아니다 (정정)

융합 비유의를 "α가 현행에 튜닝돼서"로 설명하려 했으나, **dev로는 후보의 α를 정할
수 없다**(§3). tie_set이 0.4~0.6에 걸쳐 있고 규칙이 고르는 값은 0.6인데 그 점추정은
α=0.5보다 낮다. n=96·MDE ±0.086으로는 이 구간을 가르지 못한다.

**남는 서술은 이것이다** — 후보는 **캡션 채널에서 확실히 이기고**(+0.0377, CI가 0
배제), **융합에서의 이득 크기는 현재 평가 규모로 확정할 수 없다**(+0.0187, CI가 0을
아슬아슬하게 포함). 이건 후보의 결함이 아니라 **평가 규모의 한계**이며, 채널 격리
지표를 주 지표로 미리 정해둔 이유이기도 하다.

### 6-c. 별개 안건

- **M9 판정자 14B 교체** — 근거 생김. test coverage 수치 재산출 여부 결정 필요
- **더 큰 캡션 모델(14B·32B)** — 6GB 해제로 후보 복귀. 다만 모델마다 프롬프트
  재탐색이 필요해 비용이 크다. 8B는 이미 AI Hub에서 탈락(−0.0044)
- **dev 확장 3편** — 인덱싱 검증 완료(§7), 질의·라벨 미작성
- **GLM-4.1V 재시도** — `<think>` 제거 + 한국어 강제 필요. 조건이 달라져 별도 판단

## 8. 이번 기간에 낸 실수 (재발 방지)

전부 **프로세스 위생** 문제다. 실험 설계가 아니라 실행 환경을 안 확인한 것이다.

| 사고 | 결과 | 고친 방식 |
|---|---|---|
| 영상마다 모델 재적재(97회) | GPU를 5배 느리게 씀 | `load_once` 1회 적재 |
| `close()`가 `nonlocal` 없이 `del model` | 캡션 1,164장 만들고 채점 못 함 | `nonlocal` 선언 |
| 한 프로세스에 임베더 5종 | 첫 CUDA 오류가 뒤 4개 전멸 | `--only`로 프로세스 분리 |
| `make_llm`이 모델을 안 놓음 | 14B가 VRAM 부족으로 실패 | 판정자별 프로세스 + 결과 누적 |
| venv 아닌 `python3` | 야간 체인 둘 다 0초 즉사 | 절대 경로 인터프리터 |
| 서버 scp 누락 | 6 arm이 `KeyError`로 즉사 | 커밋과 동기화를 한 동작으로 |
| `q4` 플래그 무시 | 4bit arm이 bf16으로 돎 | 로더 분기 수정 |
| 문서 수치가 로컬 근거 파일에 없음 | 8B arm 2개·판정자 결과가 서버에만 | 서버에서 받아 동기화 |
