## 0. 왜 이 문서가 필요한가

test 39건은 확정 config로 공식 평가가 끝났고 **접촉 7회 · 튜닝 0회**다. 이번에
바꾸는 것이 많다(생성 기계·정밀도·캡션 모델·평가 표본·M9 판정자). 결과를 본 뒤에
기준을 정하면 "결과 보고 맞춘 것 아니냐"에 답할 수 없다.

**이 문서의 목적은 성공을 보장하는 게 아니라 판정 기준을 결과보다 먼저 고정하는 것이다.**

## 2. 실행 순서 (고정)

```
1. 캡션 재생성    서버 bf16, Qwen3-VL-4B/P1, 10편(기존 7 + 신규 3), 약 2,173 세그먼트
2. m4 재임베딩    text_hash 변경 감지로 자동 재생성
3. α 재탐색       dev 96건에서만. 규칙은 현행 그대로(tie_set + tiebreak=larger)
4. τ 재캘리브레이션 dev 96 + 무관 20. 규칙은 현행 그대로
5. test 병합      queries_new.jsonl 33건 → queries.jsonl (39 → 72)
6. M6 재평가      ← test 접촉 8회차
7. M8 재생성      10편
8. M9 재평가      14B 판정자 ← 같은 8회차로 계산(연속 실행 1회)
```

**3·4는 dev에서만 한다.** test를 보고 α나 τ를 고르면 그 순간 튜닝이 된다.
**5는 6 직전에 한다.** 병합해 두고 다른 걸 재면 접촉이 늘어난다.

### 소요 추정 (실측 기반, 2026-08-13)

| 단계 | 근거 | 소요 |
|---|---|---|
| 1 캡션 재생성 | 2.5초/장 실측(서버 qwen3vl_4b/P1 655장 1,644초) × 2,173 | **90분** |
| 2 m4 | ~2분/편 × 10 | 20분 |
| 3 α 재탐색 | dev 96 × α 11점 | 20분 |
| 4 τ 재캘리브레이션 | 계산만 | 10분 |
| 6 M6 재평가 | 실측 ~2분 | 2분 |
| 7 M8 재생성 | **161초/149세그 실측** → 적재 50초 + 0.74초/세그 | **35분** |
| 8 M9 재평가 | 판정 3.25초/콜 실측(14B 4bit) × 2,037콜 | **1.8시간** |
| **합계** | | **약 4.5시간** |

*M9가 가장 길다 — groundedness는 문장당, coverage는 세그먼트당 판정하므로
test 7편 1,518 세그먼트가 그대로 콜 수가 된다.*

**M8 재현성 확인:** 같은 config·같은 서버로 재생성한 리포트가 8/6 산출물과
**51문장 전부 문자 단위 동일**했다. M8은 같은 환경에서 결정적이다.

## 3. 사전 등록한 판정 규칙

### 3-1. 주 지표와 baseline

- **주 지표: 융합 MRR** (α는 3에서 dev로 재탐색한 α*)
- **baseline: 자막 단독 α=1.0** — 현행 정의 그대로
- 병기: hit@1 · hit@5 · hit@10 · IoU@0.5/0.3 · 유형별 분해
- 채널 격리 병기 필수(규약 1항): 캡션 단독 α=0.0, 자막 단독 α=1.0

### 3-2. 헤드라인은 72건 재산출로 대체한다

확장된 72건에서 baseline과 proposed를 다시 재고 **그 값을 대표 수치로 쓴다.**
기존 39건 수치(MRR 0.649 → 0.829)는 **이력으로만 남기고 헤드라인에서 내린다.**

*결과를 보고 39건과 72건 중 좋은 쪽을 고르지 않는다. 72건이 대표라고 지금 정한다.*

### 3-3. 나쁘게 나와도 그대로 보고한다

**채택 판단은 이미 끝났다** — dev에서 선별하고 AI Hub 독립 표본에서 확증했다.
test는 **최종 보고용이지 선택용이 아니다.**

따라서 새 설정의 test 수치가 기존보다 낮게 나와도:

- **채택을 철회하지 않는다.** 철회하면 test로 고르는 것이 되어 "튜닝 0회"가 깨진다
- **"독립 표본에서는 이겼으나 최종 평가에서는 재현되지 않았다"로 보고한다**
- 그 경우 원인 분석은 별도 작업이며, 그 분석 결과로 이 판정을 되돌리지 않는다

*이 항목이 이 문서에서 가장 중요하다. 결과를 보고 나면 되돌리고 싶어진다.*

### 3-4. 성공/실패의 정의

이번 재평가는 **가설 검정이 아니라 보고**다. 그래도 해석을 미리 고정한다.

| 결과 | 서술 |
|---|---|
| proposed가 baseline을 유의하게 이김 | 기존 주장이 확장 표본에서 유지됨 |
| 이기지만 비유의 | **표본을 72로 늘렸는데도 유의하지 않다**는 사실을 그대로 적는다 |
| baseline과 같거나 나쁨 | 주장 철회. 두 채널 융합의 이득을 최종 평가에서 확인하지 못했다고 적는다 |

**신·구 설정 비교(0.829 대 새 수치)는 다중성 보정 대상이 아니다** — 가설 검정이 아니라
설정 변경 전후의 기술 통계다. 이 비교로 유의성을 주장하지 않는다.

### 3-5. 유형별 분해의 한계를 함께 적는다

신규 3편은 유형과 영상이 상관된다(평가확장_계획 §3-4). softyeon_ceramics는 장면형
10/11, baekmansonghee_jirisan은 말 기반 9/11이다. 따라서 확장 후 by_type 결과에서
**유형 효과와 영상 효과를 분리해 주장하지 않는다.** 표와 함께 이 상관을 명시한다.

### 3-6. M9

- 판정자를 **Qwen2.5-14B(4bit)** 로 교체하고 test coverage·groundedness를 재산출한다
- 기존 수치(7B 판정자)는 **탈락한 계측기의 출력**이므로 폐기하고, 문서에 그 사유를 남긴다
- 14B가 통과선 0.75를 **0.767로 겨우 넘겼고 셀당 60문항**이라는 한계를 병기한다
- groundedness는 7B도 통과했으므로 신·구 값을 함께 실어 판정자 교체 영향을 보인다

## 4. 검증 절차 (완료 주장 전)

`.claude/skills/pipeline-verify` 체크리스트를 그대로 적용한다.

1. 오염 캡션 전수 스캔 — 잔존 0 확인
2. `text_hash` 대조 — 10편 전부 meta.json과 일치
3. emb shape — (n, 1024) × 2
4. **per_query 순위 전건 대조** — 어떤 질의가 왜 움직였는지 규명 후 보고
5. provenance 필드 — static_threshold·α·모델명이 실효값으로 기록됐는지
6. 전체 테스트 통과 + 브라우저 E2E

**무단 "개선됐다" 금지.** 순위가 움직인 질의는 개별로 설명한다.

## 6. 롤백 조건 (성능과 무관한 것만)

아래는 성능이 아니라 **무결성** 문제이므로 롤백한다.

- 캡션 재생성 후 오염 캡션이 잔존한다
- text_hash 불일치가 남는다
- 신규 3편 중 인덱싱이 깨진 영상이 있다
- 브라우저 E2E가 깨진다

**성능 저하는 롤백 사유가 아니다**(§3-3).
