## 1. 결정

```
채택   ① M8의 보고서 생성·HWPX 골격을 유지하고,
         WVR을 M8의 차세대 영상 이해 입력(upstream)으로 흡수한다.

기각   ② WVR을 새 본선으로 승격하고 M8을 레거시화
         이유 — 이미 동작하는 M8 → HWPX · M9 평가 인터페이스 · 제출 baseline을
                전부 다시 지어야 한다.
기각   ③ 두 계보 병존 유지
         이유 — "어느 보고서 파이프라인이 본선인가"가 계속 미해결로 남는다.
                ③은 지금까지의 과도기 상태였고, 목표 상태가 아니다.
```

### 유지할 것 (M8 자산)

```
report orchestration · section generation 구조 · map-reduce 검증분
citation/report object 구조 중 재사용 가능한 것 · HWPX 생성 계층
제출 baseline · M9와 연결 가능한 평가 인터페이스
```

### 교체할 것

```
보고서가 "무엇을 보고" 생성되는가
  현재    M3 text segments(5초 자막·캡션) → M8
  차세대   Qwen3-VL broad visual understanding → M8 vNext
```

**M8 = 보고서 생성 엔진. WVR = 영상 이해 엔진.** WVR을 M10·M11로 번호를 늘리지 않는다.


근거(repo 실측):

```
Conservative Event Map              CLOSED / CONSERVATIVE_EVENT_MAP_PASS
Semantic Chapter Shadow             CLOSED / SEMANTIC_CHAPTER_SHADOW_HOLD
Semantic Chapter Boundary Repair    CLOSED / SEMANTIC_CHAPTER_REPAIR_HOLD
```

Conservative Event Map 연구가 아니면 나오지 않았다.

## 5. 통합 계약 — WVR 출력이 M8에 들어가려면

M8의 실제 입력 계약(`m8_report.py:693` · `common.load_segments`):

```python
doc = common.load_segments(wdir / "segments.json",
                           require=["subtitle", "caption"],
                           seg_len=cfg["seg_len_sec"])
```

`load_segments`가 강제하는 불변식:

```
segments[i].idx   == i                 (0부터 연속 정수)
segments[i].start == i * seg_len       (seg_len은 config에서 온다)
필수 필드          subtitle · caption
```

`_fmt_seg`가 만드는 프롬프트 한 줄:

```
[seg#{idx}] MM:SS-MM:SS  자막: …  장면: …
```

### 결론 — 코드 변경 없이 들어갈 수 있다

WVR 창은 **48초 window · 24초 stride**라 `start = idx × 24`가 정확히 성립한다.
따라서 `seg_len_sec: 24`로 둔 **config 사본**을 쓰면 `load_segments` 불변식을 통과한다.

WVR이 내보내야 할 형태:

```
segments[i] = {
  idx      : i                          (S01 → 0, S02 → 1, …)
  start    : i * 24                     (0, 24, 48, …)
  end      : start + 48                 (load_segments는 end를 검사하지 않는다)
  caption  : 해당 window의 broad activity 요약 텍스트
  subtitle : 해당 window 구간의 STT 텍스트 (아래 장애물 ② 참조)
}
```

이 형태면 **M8 · HWPX · M9를 건드리지 않고** 입력만 갈아끼울 수 있다.

## 6. 계획에 빠져 있던 장애물 4개

### ① 인용 입도가 바뀐다

`[seg#N]`이 5초 구간이 아니라 48초 window를 가리키게 된다. 영향 범위:

```
M9 groundedness judge   인용↔내용 일치 검증의 대상 단위가 바뀐다
HWPX 레이아웃           seg 시각 표기(MM:SS-MM:SS)가 48초 폭이 된다
```

Track A의 `gt_seg_idx`·라벨 도구는 **영향 없다** — 별도 파일·별도 work dir이고,
CLAUDE.md 절대규칙 3의 allowlist 경로를 그대로 탄다. 섞이지 않게 유지할 것.

### ② WVR에는 subtitle이 없다

WVR 경로는 `track_a_used: false`로 STT를 쓰지 않는다. 그런데 M8은 `subtitle`을
필수 필드로 요구한다. 선택지:

```
(a) M3 STT를 window 구간으로 재집계해 채운다     권장 — 정보 손실 없음
(b) 빈 문자열로 채운다                          M8 동작이 바뀐다(무발화 취급)
```

`is_corrupted_caption` · `strip_residual_cjk`는 caption에만 걸린다 — subtitle은
`_sanitize`만 통과한다. (b)를 고르면 리포트가 시각 정보만으로 생성된다.

### ③ 겹침 구간이 중복 입력된다

48초 window에 24초 overlap이므로 모든 순간이 두 번 등장한다. M8의 chunk coverage
계산·reduce 단계의 시간순 정렬이 중복을 어떻게 다루는지 **미검증**이다.
회피안: stride 폭(24초)만 대표로 쓰는 비중복 뷰를 따로 만들어 M8에 넘긴다.

### ④ 현재 WVR은 C01뿐이다

```
C01 [0,600)   실행 완료 (V2 GENERATED / REVIEW_REQUESTED)
C02~C05       NOT YET EXECUTED
```

2424초 전체 보고서를 만들려면 C02~C05 실행이 선행되어야 하고, 그것은 GPU 배치라
**별도 승인 사건**이다.

### 격리 의무

CLAUDE.md 규칙 4에 따라 **config 사본에 `paths.work`·`paths.results`를 동시 분리**한다.
본 config·본 인덱스·제출 baseline artifact를 실험으로 오염시키지 않는다.
