## 1. PRIMARY — `I_pool` 양방향 모두 예측 방향

```
I_pool = D_large − D_small          사전 예측: I_pool < 0
```

| 표본 | 조작 방향 | `D_small` (12) | `D_large` (전체) | **`I_pool`** | 예측 |
|---|---|---|---|---|---|
| dev 96 | 축소 149~314 → 12 | −0.0559 | −0.0903 | **−0.0344** | 일치 |
| AI Hub 1,086 | 확대 12 → 2,328 | +0.0340 | +0.0112 | **−0.0228** | 일치 |

**두 데이터셋에서 조작 방향이 반대인데 `I_pool` 부호가 같다.** 보충1 §1-1의 판정표에
따르면 이것은 **양방향 조작 증거**다.

> **풀이 커지면 4B가 3B보다 상대적으로 더 손해를 본다** — dev를 줄였을 때도, AI Hub를
> 늘렸을 때도 같은 방향으로 움직였다.

## 2. **그러나 어느 조작도 자기 표본의 부호를 뒤집지 못했다**

이것이 P1의 가장 중요한 제한이다.

| 풀 크기 | dev Δ (96질의) | AI Hub Δ (1,086질의) |
|---|---|---|
| 12 | **−0.0559** | **+0.0340** |
| 24 | −0.0747 | +0.0532 |
| 48 | −0.0831 | +0.0452 |
| 96 | −0.1170 | +0.0374 |
| 192 | — | +0.0294 |
| 384 | — | +0.0200 |
| 768 | — | +0.0169 |
| 2,328 | — | **+0.0112** |
| 전체 (149~314) | −0.0903 | — |

```
dev를 AI Hub 크기(12)로 줄여도      Δ = −0.0559   (여전히 음수, +0.0310과 멀다)
AI Hub를 dev보다 크게(2,328) 늘려도  Δ = +0.0112   (여전히 양수, −0.0903과 멀다)
```

**남은 격차는 약 0.067**(−0.0559 vs +0.0112)이고, 이것은 풀 크기로 설명되지 않았다.

> **따라서 "후보 풀 크기가 부호 역전의 원인"이라고 쓰면 안 된다.** 풀 크기는 격차를
> 양쪽에서 압축하지만 **0을 건너지 못한다.** 두 표본의 차이에는 풀 크기 밖의 요인이
> 남아 있다.

### 2-1. dev 곡선은 단조가 아니다

`96`(−0.1170)이 `전체 149~314`(−0.0903)보다 더 음수다. **풀 크기가 커질수록 단조로
악화되는 함수가 아니다.** AI Hub 쪽은 24 이후 단조 감소(+0.0532 → +0.0112)지만
`12 → 24`에서 한 번 커진다. 두 곡선 모두 국소 비단조가 있으므로 `I_pool`을
"풀 크기 반응 기울기"로 해석하지 않는다.

## 3. locality 기여분 — 작다

보충1 §2에서 조작을 둘로 나눈 이유는 연속 창이 풀 크기와 **negative의 시간적
locality**를 동시에 바꾸기 때문이다. 같은 95질의에서 두 규칙을 비교한다.

| 규칙 | `D_small` | `D_large` | `I_pool` |
|---|---|---|---|
| `P1a_pool_size_random_negatives` (PRIMARY) | −0.0617 | −0.0926 | −0.0308 |
| `P1a_local_window_12` (SECONDARY) | −0.0697 | −0.0926 | −0.0229 |
| 차 (window − random) | **−0.0080** | 0 | +0.0079 |

**연속 창에서 4B가 0.008 더 불리하다.** 인접 세그먼트가 negative일 때 4B가 조금 더
약하다는 기술값이고, **인과로 주장하지 않는다.** 크기는 `I_pool`(−0.03)의 1/4 수준이다.

AI Hub 쪽 대응 관측 — 원 조건(영상 자체 12개, 연속)은 `+0.0310`, 해시 무작위 12개
(영상 간)는 `+0.0340`. **차 +0.0030으로 같은 방향**이고 역시 작다.

## 4. 판정 — 보충1 §1-1 표 그대로

```
두 데이터셋 모두 I_pool < 0  →  양방향 조작 증거
```

쓸 수 있는 최대치는 이것이다.

> **두 기존 표본에서 candidate-pool manipulation이 사전 예측 방향으로 4B−3B contrast를
> 이동시켰다. 이는 pool-size sensitivity를 sign reversal의 plausible contributor로
> 지지하며, fresh long-form confirmation에서 검증할 조건을 구체화한다.**

**쓰면 안 되는 문장** — "풀 크기가 원인으로 확정됐다", "유일한 원인이다",
"이로써 4B를 채택/기각한다". §2가 그 주장을 직접 반증한다.

### 4-1. P2 확증 설계에 반영할 것

```
1  후보 풀 크기를 **설계 변수로 기록**한다 — 영상 길이·세그먼트 수를 표본 기술에 넣는다
2  풀 크기를 dev와 비슷한 범위(150~400 세그먼트)로 맞춘다. 그러면 P1이 압축한
   0.03 정도는 통제되고, 남은 0.067을 재는 설계가 된다
3  locality는 통제 대상이 아니다 — 기여분이 0.008로 작다
4  남은 후보(query type 구성·도메인·캡션 길이)를 층으로 유지한다
```

**P2 규모(16~53편)는 이 결과로 바꾸지 않는다.** 검출 목표는 여전히 `+0.031`과 `−0.090`을
가르는 것이고, P1은 그 격차의 일부만 설명했다.

## 5. 절차와 이탈

```
사전등록 98d4efa → 보충1 cb16697 → 코드·TDD 63e7195 → 재현 게이트 → 실행
```

**이탈 1 — `wl_q03` 제외 (연속 창 변형만).** `gt_seg_idx = [132, 133, 134, 312]`로
비연속이고 범위가 181세그먼트다. 어떤 12-창도 gold 전체를 담을 수 없다. 보충1 §2-4는
`|gold| > pool_size`만 fail-closed로 선언했고 **범위 초과는 예상하지 못했다.**

처리 방식 — 코드가 알아서 버리지 않게 하고, **명령줄에 이름을 적는 명시 제외**만
허용하도록 고쳤다(`--exclude wl_q03`). 산출물에 `excluded_queries`와 사유가 기록된다.
비교 가능성을 위해 **두 규칙을 같은 95질의로 다시 계산**했다(§3). `wl_q03`은 GT 파생
규칙의 유일한 문서화된 예외이고(CLAUDE.md·DESIGN_SPEC 8-6), **성능을 보고 고른 제외가
아니다.** §1의 PRIMARY 수치는 96질의 전량이다.

**이탈 2 — 재현 게이트가 확대 조작에서 FAIL했다.** global 모드의 `full`은 2,328이라
저장값(영상 내 12)과 다르다. 게이트를 끄는 대신 **원 실험 조건을 명시로 받는
`gate_universe`를 추가**했다. 그래서 확대 조작에서도 게이트가 살아 있다(§0).
이것은 게이트가 의도대로 작동한 사례다 — 조작이 원 조건을 덮어쓸 때 FAIL했다.

**소비 선언** — dev 96·AI Hub 1,086은 이 조작으로 다시 사용됐다. **P2의 확증 표본으로
쓸 수 없다.** 새 표본이 필요하다는 결론은 P1 결과와 무관하게 유지된다.
