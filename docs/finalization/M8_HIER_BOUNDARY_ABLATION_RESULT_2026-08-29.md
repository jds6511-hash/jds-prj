## 2. 그러나 기전이 예상과 다르다 — 가장 중요한 부분

효과가 채널 전반에 고르게 퍼져 있지 않다. **거의 전부 chunk5 하나다.**

```
chunk5(220~279) 안     full 42  →  caption-only 12
chunk5 제외             full 24  →  caption-only 20
```

chunk5를 빼면 경계 수는 사실상 그대로다(24 → 20).

원인은 full-input chunk5의 **원본 출력** 하나로 드러난다.

```json
["220", "224", "226", "228", "230", ... , "254",
 "255", "256", "257", ... , "277", "278", "279"]
```

간격 4 → 2를 16회 → **1을 25회**, 그리고 허용 범위의 끝 번호(279)에서 멈춘다.
이건 내용 판단이 아니라 **번호 목록 이어쓰기(열거 degeneracy)**다.

caption-only 같은 청크의 출력.

```json
["220", "227", "229", "238", "249", "256", "261", "266", "271", "278"]
```

출력 길이도 306자 → 70자다.

```
연속 정수 군집(≥5)
  full          [254~279] 26개
  caption-only  없음
```

chunk3에서도 full은 `[110,120,130,140,150,165]` — **정확히 간격 10**의 등차수열이었고
caption-only에서는 `[110,169]`로 사라졌다.

즉 관측된 것은 "자막이 바뀌니 경계가 하나씩 늘었다"는 **점진적 효과가 아니라**,
자막이 실린 입력에서 모델이 **열거 모드로 무너진 것**이다.

## 3. 위치는 채널을 바꾸면 크게 달라진다

개수가 같은 청크에서도 위치는 같지 않다.

```
청크          full  caption  shared
  0~59         5      5        3
 55~114        5      5        4
110~169        6      3        2
165~224        9     10        3
220~279       42     12        8
275~326       10      6        2

chunk5 제외    24     20        8
```

**개수가 24 → 20으로 거의 같은데 공통 위치는 8개뿐이다.** 경계 선택이 입력 채널에
robust하지 않다 — 내용에 단단히 고정돼 있지 않다는 뜻이다.

## 4. 가설 판정

```
H1  자막 입력이 과도한 경계 생성에 기여한다
    → 지지. 단 기전은 점진적 효과가 아니라 특정 청크의 degeneracy 유발이다.

H2  경계 과다는 채널과 무관한 열거 degeneracy다
    → 부분 지지·부분 반증. degeneracy는 실재했으나 자막 제거로 사라졌다.
       채널과 무관하지 않다.

H3  경계 과다는 화면 설명 불안정에서 온다
    → 미지지. caption 단독 입력에서 조각화가 재현되지 않았다.
```

## 5. 하지 않은 말

```
caption-only가 더 낫다      말하지 않는다 — 채점하지 않았다(라벨 은퇴)
32가 옳은 사건 수다         말하지 않는다 — 정답 개수 기준이 없다
자막을 빼야 한다            말하지 않는다 — 서술 품질은 자막에서 나왔다(대조 결과 §2)
다른 영상도 그렇다          말하지 않는다 — 1편 · 6호출 · 1회 실행
```

greedy(`do_sample=False`)라 같은 조건에서 결정적이지만, **반복 실행으로 확인하지는
않았다.**

특히 **`wonyi_geoje` 서술 품질(EVENT_LIKE 95%)은 자막이 있었기 때문에 나온 것**이다.
이 ablation은 구조 층에 대한 진단이지 자막 제거 권고가 아니다.

## 6. 이것이 Dual-stream에 주는 함의

Dual-stream의 전제 — **대화의 의미와 사건의 시간 경계를 분리한다** — 는 지지를 받는다.
자막을 경계 입력에서 빼자 조각화가 사라졌고 서술에 필요한 자막은 서술 pass에 그대로
남길 수 있다.

**다만 발견된 기전은 설계가 가정한 것보다 조야하다.** "대화 주제가 바뀌어서 경계가
생긴다"가 아니라 "긴 자막 목록 입력에서 모델이 번호를 열거한다"였다. 그렇다면 훨씬
싼 대안이 존재한다.

```
A  경계 pass 입력에서 자막 제외        이번에 실측한 조작. 코드 한 줄
B  출력에 경계 수 상한 · 연속 정수 run 거부   결정적 후처리
C  경계를 코드가 계산 (STEP A 신호)     LLM 경계 선택 자체를 없앤다
D  Dual-stream 전면 구현               가장 비싸다
```

§3(위치가 채널에 흔들린다)은 **C 쪽 근거**다 — STEP A에서 결정적 caption 거리 신호가
uniform baseline을 이겼고(0.55 vs 0.25), LLM 경계는 등차수열에 가까운 행동을 보였다.

**어느 쪽을 고를지는 사용자 판단이다. 자동으로 진행하지 않는다.**
