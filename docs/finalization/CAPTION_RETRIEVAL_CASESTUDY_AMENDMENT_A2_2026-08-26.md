# 케이스 스터디 amendment A2 — Scene01 재지정 (2026-08-26)

**이 amendment는 `outcome_blind: false`다.** A1(2026-08-25)과 성질이 다르다. A1은 캡션·검색
결과를 열람하기 전에 만들었고, A2는 **15질의 결과와 두 arm의 캡션 395건을 전부 읽은 뒤**에
만든다. 그 사실이 이 문서의 첫 줄에 있어야 한다.

**사용자 승인 사건.** 2026-08-26 대화에서 Scene01 대표 프레임의 중앙 오버레이 문제를
제기받고, 세 가지 선택지(로고를 설명 근거로 사용 / Scene01 카드 제외 / 장면 재지정)를
제시했으며 **사용자가 장면 재지정을 선택**했다. 이어 재지정 후보 기준에서
seg1(규칙 그대로) vs seg2(중복 배제 기준 추가) 중 **seg2를 선택**했다.

---

## 1. 무엇이 문제였나

`docs/finalization/CAPTION_TO_RETRIEVAL_INTEGRITY_AUDIT_2026-08-26.md` §C MEDIUM-1에서
발견한 것이다.

```
Scene01 target = seg0 = 영상 0:00~0:05 = 인트로 구간
프레임 seg_0000.jpg 중앙에 불투명 "Plan:D VLOG" 타이틀 로고가
팬 안의 새우를 상당 부분 덮는다.
```

원래 제외 기준은 `black frame · transition/fade · severe blur · decoding failure ·
거의 동일한 정지화면 · 화면 내용 식별 불가` 여섯이었고 **인트로 타이틀 가림 항목이
없었다.** 규칙 위반이 아니라 규칙의 공백이다. 그 공백 때문에 seg0이 적격 판정을 받았다.

이 상태로는 3B의 seg0 오서술(`"노란색 그릇 … 작은 크림 요리"`)을 캡션 품질만으로 설명할
수 없다 — 입력 프레임의 가림이 함께 작용했을 수 있다. 발표 자료로 쓰기에 부적절하다는
판단을 사용자가 내렸다.

## 2. 제외 기준 두 개를 추가한다

```
추가 E7   인트로/아웃트로 타이틀 또는 오버레이 그래픽이 핵심 피사체를 가린다
추가 E8   이미 선정된 다른 장면과 같은 작업·장소다 (장면간 target 모호성 방지)
```

**E8을 추가하는 이유.** E7만 추가하면 "첫 적격 segment" 규칙에 따라 seg1이 선정되는데,
seg1은 공업용 재봉틀 작업 장면이고 **Scene05(seg316)와 같은 장소·같은 작업**이다.
Scene05의 동결 질의 두 개가 `"재봉틀 앞에서 천을 손으로 잡고 있는 장면"`,
`"작업대 위에 재봉틀과 가위가 놓인 작업 공간"`이므로, seg1이 Scene01이 되면
**두 장면의 target이 서로의 질의에 정당하게 걸린다.** "내가 고른 장면이 몇 위인가"라는
측정 자체가 모호해진다 — 해결하려던 문제보다 큰 결함이다.

**E8의 대가를 숨기지 않는다.** E7은 프레임만 보고 판정되는 시각 기준이지만, E8은
"이미 선정된 다른 장면"을 참조하므로 **선정 순서에 의존하는 기준**이다. 그리고 둘 다
결과를 본 뒤에 추가했다. 이것이 A2가 outcome-blind가 아닌 이유다.

## 4. 질의는 내가 쓰지 않는다

동결 계획의 질의 작성 규칙은 이렇다.

> `"원본 대표 프레임만 보고 작성. 3B/4B 캡션과 검색 결과를 열람하기 전에 작성·동결했다."`
> `"모델 캡션 어휘를 베끼지 않는다. 캡션을 읽지 않았으므로 베낄 수도 없다."`

**나(작업 에이전트)는 두 arm의 395구간 캡션 전문과 15질의 검색 결과를 이미 전부 읽었다.**
따라서 내가 새 질의를 쓰면 그 규칙을 만족할 수 없고, 케이스 스터디의 핵심 강점인
"사전 동결된 blind 질의"가 사라진다.

```
새 Scene01 질의 3개   사용자가 seg_0002.jpg 프레임만 보고 작성한다
                    유형은 기존과 같다 — Q1 사물/장면 · Q2 행동 · Q3 관계/맥락
Scene02~05 질의 12개  기존 동결본 그대로 재사용
```

**부분 오염은 남는다 — 기록한다.**

| 항목 | 상태 |
|---|---|
| 새 target(seg2)의 3B·4B 캡션 | **미열람** (길이 128자·67자만 확인, 내용 미출력) |
| distractor 풀(다른 394구간)의 캡션 | 상당수 열람했다 — 내가 아니라 사용자가 질의를 쓰는 이유 |
| Scene02~05 질의·순위 | 이미 열람 — 그래서 그 12개는 새로 쓰지 않고 원본을 재사용한다 |
| 새 Scene01 3질의의 검색 결과 | 질의 동결 후에만 연다 |

## 5. 무엇을 다시 돌리고 무엇을 안 돌리는가

```
재캡셔닝        하지 않는다 — 395구간 캡션이 두 arm 모두 이미 있다
재임베딩·재색인   하지 않는다 — 같은 캡션이므로 text_hash가 그대로다
프롬프트 변경     하지 않는다
모델 실행        하지 않는다 (GPU 불필요)
다시 돌리는 것     검색뿐이다 — 기존 인덱스에 새 질의 3개 + 기존 12개를 α=0으로 조회
```

즉 A2는 **generation 사건이 아니라 retrieval 재실행 사건**이다.

## 7. 방법론 비용 — 숨기지 않는다

```

   "scene/query를 교체하지 않고 정성 관측으로만 기록한다"고 명시했고, A2는 그 조항을
   사용자 승인으로 넘어선 것이다. 규칙을 몰랐던 것이 아니라 알고 넘어섰다.

## 10. 질의 작성 기록 (절차 6)

사용자가 프레임만 보고 작성했고, 동결 전에 두 건을 조정했다.

```
Q1  다지기 통 안에 재료가 들어있는 장면                        (사물/장면)
    입력 "다기지 통 …" → 오타 정정 "다지기 통 …"  · plan의 query_authoring_log에 기록

Q2  손으로 음식 다지는 기구를 눌러 재료를 다지는 장면            (행동)
    무수정

Q3  주방 조리대에서 투명한 다지기 용기에 새우와 마늘을 넣어 손질하는 장면  (관계/맥락)
    첫 입력 "주방 조리대 위에서 기구로 재료를 손질하는 장면"은 **동결 전 철회**했다 —

    두 장면의 target이 서로의 질의에 걸린다. 사용자가 다시 작성.
    재작성본은 "투명한 다지기 용기"·"마늘"이 seg2 고유 요소라 구분된다.
