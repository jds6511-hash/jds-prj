## 검증 중 발견 — A-11 REG-007의 구멍

Gate D를 세우면서 **A-11의 M9 검사가 파일 이름만 본다**는 것을 발견했다.

```
잡힌다   runs/some_run/M9_dryrun.json          이름에 M9
놓친다   runs/m9_official/report.json          디렉터리에만 표시
```

실제 M9 실행은 후자 형태로 남을 가능성이 높다. **A-11을 고치지 않았다** — 연구
경계 가드를 이 시점에 손대는 것 자체가 별도 사건이기 때문이다. 대신 Gate D에서
경로 수준으로 한 겹 더 본다(`check_no_m9_execution`).

```
m9_not_executed = A-11 REG-007 (이름)  +  D-01 경로 검사 (디렉터리 포함)
```

A-11이 이 형태를 놓친다는 사실 자체를 테스트로 고정해 뒀다 — 나중에 A-11을 강화하면
그 테스트가 먼저 깨져 재확인을 강제한다.

## 두 신규 검사의 원칙 — "있으면 실패"가 아니다

과거 진단 산출물은 **보존 대상이지 위반이 아니다.** `Qwen 문자열이 하나라도 있으면
실패` 같은 검사는 역사를 지우게 만든다. 그래서 A-11이 gyeongju에서 쓴 방식을 그대로
쓴다 — **기록에 없던 것이 생기면 실패**다.

```
기록된 모델 대조 산출물 3건 (전부 과거 것)
  results/m8_redesign_r2/threeway.json                       M8 redesign 3-way
  runs/casestudy_caption_retrieval/.../step7_target_vs_top1.json  케이스 스터디
  runs/m8_hier/m8_hier_boundary_ablation/compare_wonyi_geoje.json 경계 ablation

기록된 C0 tuning 산출물 0건
```

세 가지를 함께 잡는다.

```
추가   기록에 없던 산출물이 생김            NEW_MODEL_COMPARISON · C0_TUNING_ARTIFACT
변경   기록된 산출물의 내용이 바뀜           …_MODIFIED   ← 역사를 다시 쓰는 것도 위반
삭제   기록된 산출물이 사라짐               …_MISSING
```

### C0는 두 층으로 본다

```
채택 여부   default provider == fixed_window_v1               REG-009 · BPI-004
튜닝 여부   threshold · smoothing · min-gap · peak 탐색 흔적    D-01 신규
```

**채택하지 않았다는 것만으로는 부족하다.** 채택하지 않은 채로 파라미터만 계속
탐색하는 것도 금지 대상이기 때문이다.

## 검증 방식

문서를 읽고 PASS하지 않는다. **합성 트리에 위반을 실제로 넣어** 검사가 깨지는지
본다. 실제 연구 기록은 건드리지 않는다.

```
가짜 M9 result 추가                  RED
official test 결과 수정               RED
동결된 BCS 파일 한 줄 변경             RED
새 human GT 파일 추가                 RED
새 모델 대조 산출물 추가               RED
기록된 진단 산출물 내용 변경            RED
default provider를 change-point로     RED
C0 threshold sweep 산출물 추가         RED
smoothing grid search 추가            RED
```

첫 실패에서 멈추지 않는다 — 두 조건을 동시에 위반시키면 둘 다 보고된다.

## 남은 하나 — REG-010 (Gate D 밖의 문제)

```
frozen matrix   REG-010 | P0 | push | NO 유지
실제            2026-08-31 사용자 명시 승인 이후 origin/master로 push 수행
```

이것은 Gate D 조건이 아니지만 **전체 final acceptance의 P0**다. 조용히 PASS로
처리하지 않는다. 다음 단계에서 **frozen matrix를 수정하지 않고** authorization
addendum으로 supersede하는 절차를 밟아야 한다.

```
waiver        원 규칙은 그대로이고 실패를 예외적으로 수용한다
supersession  후속 명시적 결정이 운영 규칙 자체를 바꾼다      ← 이번 경우
```
