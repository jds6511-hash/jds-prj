## 1. 무엇을 했는가

```
SPARSE_V1   split_evidence(episode, timeline)의 claim이 정확히 1건
            + content_status == VALID_PARSE + summary가 있다
```

```
SPARSE_V1이면   정본 summary := 그 근거의 저장 원문 (strip만)
                summary_mode := SPARSE_EVIDENCE_DETERMINISTIC
아니면          기존 경로 그대로 · summary_mode := MODEL_ABSTRACTIVE
```

**모델 요약과 근거를 비교하지 않는다.** 같은 문장을 냈든 지어냈든 정본은 근거 원문이다
(`test_the_model_summary_is_never_compared_with_the_evidence`). 비교를 시작하면 C2의
축소판이 되고, GRD-004 waiver가 거부한 경로로 돌아간다.

사전등록 §3은 결합 형태(`" / ".join`)로 규칙을 적었으나, **승인 지시에 따라 v1은
결합조차 하지 않는다** — eligible이 정확히 하나이므로 단일 근거의 원문 표현이 정본이다.
좁은 쪽으로만 벗어났고, 넓힌 것은 없다.

```
접속어·도입구 삽입   없음 (근거에 따르면 · 영상에서는 · 그리고 · 그 후 · 따라서 …)
문법 교정           없음 — 어색한 발화도 그대로 옮긴다
raw 모델 출력        보존 (raw-before-parse 그대로)
grounding 판정       불변 — safe mode는 판정을 다시 하지 않는다
구조                 불변 — episode_id · span · 시간 · 순서 · 개수
```

`summary_mode`는 **provenance이지 판정이 아니다.** 이 값 때문에 grounding이 새로
PASS되거나 기존 FAIL이 덮이지 않는다(`test_safe_mode_does_not_re_judge_grounding`).
직렬화·역직렬화에서 값이 보존되고, 모르는 값은 조용히 기본값으로 떨어지지 않고
`validate_aar`가 거절한다.

## 2. counterexample 실측 — 전후

```
sparse admissible evidence   구간 9 ASR "남성이 문을 연다."   (유효 1건)

이전                                                          이후
summary "…건물에 들어가 물건을 훔친 뒤 달아난다."  PASS         "남성이 문을 연다." · SPARSE_EVIDENCE_DETERMINISTIC
summary "남성이 문 3개를 연다."                 PASS         "남성이 문을 연다." · SPARSE_EVIDENCE_DETERMINISTIC
summary "남성이 문을 연다."                     PASS         "남성이 문을 연다." · 그대로 (과잉 격리 없음)
```

두 strict xfail은 구현과 함께 **XPASS로 실패**했고, 그 시점에 marker를 제거해 평범한
회귀 테스트로 승격했다. XPASS를 남긴 채 닫지 않았다.

## 4. mutation

```
M1  sparse인데 모델 요약을 정본에 유지            RED   12 failed
M2  긴 문장만 막고 수량 발명은 통과               RED    4 failed (T2 · counterexample)
M3  SUSPECT까지 정본 문장에 결합                 RED    T4
M4  sparse면 summary를 무조건 None               RED   12 failed (과잉 격리 방지)
M5  claim+context에서 무작위 선택                GREEN  ← 아래 사유
M5' 재실행마다 문장이 흔들리게 변형               RED   11 failed (T7 포함)
M6  safe mode가 support_span을 바꾼다            RED    T6
M7  raw 모델 출력을 삭제                        RED    raw 보존 테스트
```

**M5가 GREEN인 이유를 기록한다 — 가드 구멍이 아니라 구조적 성질이다.**

```
SPARSE_V1은 claim이 정확히 1건인 상태다.
따라서 선택·정렬의 자유도가 0이고, "무작위 선택" mutation은 사실상 같은 값을 고른다.
v1에서 결합 규칙이 dormant인 것과 같은 이유다.
```

그래서 결정성 가드는 선택 순서가 아니라 **문장 자체의 재실행 안정성**으로 잰다(M5').
결합·정렬 규칙이 실제로 살아나는 것은 eligible 2+를 다루는 확장 때이고, 그때 다시
mutation을 설계해야 한다.

산출물: `mutation_tri005.json` · `mutation_m5b.json`(작업 트리 임시 파일, 커밋하지 않음).
