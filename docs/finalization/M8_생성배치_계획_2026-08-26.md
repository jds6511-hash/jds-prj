D6 = GO. 이 문서는 **PLAN**이고, CANARY·FULL은 각각 별도 게이트를 지난다.
결정 근거: [M8_M9_DECISIONS_2026-08-26](M8_M9_DECISIONS_2026-08-26.md) §D6.

```
승인된 순서   1 결정 고정 → 2 selection manifest → 3 사람 라벨링(blind)
            4 dev CANARY(7B) → 5 FULL → 6 judge dev 실행 → 7 judge validation
```

## 배치 A — 신규 3편 M1~M4 인덱싱 (로컬 · 배포 구성)

취득·provenance 기록은 **완료**했다(2026-08-26).

```
wonyi_gyeongju   4m9eLr-NofA  1722초  sha256 209974b0…  개인 채널
wonyi_geoje      OrCOflk2QmQ  1632초  sha256 182a7fd1…  같은 채널
kbs_banff        F46FVgLr3eQ  1575초  sha256 935c6f72…  KBS 방송물
```

구성은 배포 그대로다 — `Qwen2.5-VL-3B` / P0 / 4bit / seg 5s / KURE-v1. 신규 영상은
**그 영상만** 돌린다(기존 인덱스 재생성 금지).

```
예상 구간 수    345 + 327 + 315 = 987
M1             수 초
M2 키프레임      약 22분/편 × 3 ≈ 66분
M3 STT+캡션     약 0.19분/구간 × 987 ≈ 187분
M4 임베딩       약 2분/편 ≈ 6분
────────────────────────────────
합계            약 4.5시간 (로컬 GPU 점유)
```

승인 게이트: **장시간 배치라 본 실행 전 사용자 승인이 필요하다.** 계획 → 1편 canary →
검증 → 나머지 2편 순서로 한다.

완료 후 검증(`.claude/skills/pipeline-verify`):

```
1  단계 마커 확인 — 수치는 로그가 아니라 UTF-8 JSON에서 읽는다
2  오염 스캔 — common.is_corrupted_caption 전수. 신규 3편만 대상
3  text_hash 대조 — meta.json == common.index_text_hash(segments.json)
4  emb shape — emb_sub / emb_cap == (n_segments, 1024)
5  기존 11편 text_hash 불변 확인 — 신규 추가가 확정 인덱스를 건드리지 않았음을 증명
```

**이 배치는 dev·test 질의가 없는 영상만 만든다 — 절대규칙 1이 발동하지 않는다.**
평가 수치에 영향이 없으므로 재평가도 필요 없다.

## 배치 B — M8 dev CANARY (서버 7B)

기존 계획·스크립트를 그대로 쓴다. 새로 만들지 않는다.

```
plan      planning/exp_plans/m8_dev_pilot.json
script    scripts/m8_dev_pilot.py     기존 report.json을 덮지 않는다(report_pilot_<run_id>)
launcher  scripts/exp_launcher.py     precheck → canary → validate
config    config_server.yaml          본 config를 편집하지 않는다
저장       /ssd · HF_HOME=/ssd/$USER/cache  (비대화형 SSH는 .bashrc를 읽지 않는다)
canary    --limit-videos 1 --limit-chunks 2
```

CANARY가 답하는 것은 하나 — **7B가 구조 산출물을 안정적으로 내는가.** Event Recall과
C1~C3는 여기서 산출하지 않는다(판정 표본이 아니다).

확인 항목:

```
구조 validator PASS            aar_view 기준. D4 이후 인용 없는 evaluable 문장은 INVALID다
uncited_evaluable_sentences    structural_summary에 0으로 나와야 한다 ← D4의 실질 위험
provenance 요청·실효값 기록      report_provenance
chunk_retries · rejected        재시도·거부 사유 분포
```

**`uncited_evaluable_sentences`가 0이 아니면 FULL로 넘어가지 않는다.** D4로 기준을
통일했으므로, 생성기가 인용 없는 문장을 흘리면 그 리포트는 구조적으로 무효다. CANARY의
목적 절반이 이 확인이다.

## 배치 C — M8 FULL 생성 (판정 표본 8편)

**차단 상태.** 두 가지가 선행한다.

```
① fixed_N=8 selection manifest 동결   현재 확보 가능 6편 (2편 부족)
② 사람 reference-event labeling 완료   라벨러는 M8 산출물을 보지 않는다
```

②가 ③(생성)보다 먼저다. 순서를 뒤집으면 reference 사건이 M8 출력에 끌려간다 —
이것이 승인된 순서에서 3번과 5번을 갈라 둔 이유다.

FULL 실행 시:

```
launcher  full --approve-full <run_id>          FULL 자동 진입 없음
검증       validate → RUN_COMPLETE 마커 뒤에만 REPORT
판정       C1 catastrophic 0편 · C2 Event Recall 중앙값 ≥ 0.70 · C3 Compression ≤ 2.0
결과       0.70 미만이면 그대로 C2 FAIL. 기준을 낮추지 않는다
```

## 배치 D — dev judge 실행 + judge validation (D3 선행 절차)

```
대상       dev 영상 (test 접촉 없음)
목적       ① judge가 실제로 작동하는지 ② groundedness 분포 sanity check
방법       frozen M8 generator 산출물 + 실제 judge(스텁 아님) + 사람 spot-check
금지       dev 분포에 맞춰 threshold를 optimize하는 것
```

M9 코드는 `split=="test"` 하드코딩이라 **그대로 쓸 수 없다.** dev judge validation은
`m9_report_eval.eval_report`를 dev 질의로 호출하는 별도 경로가 필요하다 — 그 경로는
`--test-opening` 게이트를 우회하는 것이 아니라 **test를 읽지 않는다는 것을 코드로
보이는** 별도 스크립트여야 한다. 아직 없다(작성 대상).
