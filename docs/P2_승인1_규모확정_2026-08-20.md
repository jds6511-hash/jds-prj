# P2 승인 ① — 규모·집중도·질의 배정 확정 (2026-08-20)

**영상을 고르기 전에 커밋한다.** 모델 산출물은 하나도 생성·열람하지 않았다.
근거 문서: 사전등록 보충2(`58de1bf`) §4 · 보충3(`e878a4d`) §4~5 ·
보충4(`172f988`). **사전등록은 수정하지 않는다** — 이 문서는 그 규칙 아래에서
사용자 결정을 기록하는 결정 문서다.

## 0. 확정값

```
EBS 집중도 상한  c = 0.80
target_k         35        (EBS 28 · 비-EBS 7)
영상당 질의 수   9         → 총 315질의
유형 target quota 복합형 111 · 자막형 79 · 장면형 125
seed             20260820
```

## 1. `c = 0.80` · `target_k = 35` — **통계적 optimum이 아니다**

필요 cluster 추정이 `16`(dev 스케일링) ~ `53`(AI Hub 스케일링)으로 3배 어긋나고
(보충2 §4-1), 현재 reservoir 천장은 37이다.

> **따라서 어떤 선택도 `half-width ≤ 0.04`를 보장하지 못한다.** AI Hub 스케일링이
> 맞다면 35도 부족하다. **검정력 계산 결과가 아니라 천장에서 상한 규칙만큼 내려온
> 값이다.**

그 조건에서 실질 실패 모드는 하나 — `판정 불가`. `k`가 그 레버의 전부다. 그래서
도달 가능 범위 상단을 택했다.

### 1-1. `c = 0.80`을 고른 이유 둘

```
① 상한이 규칙으로 존재한다 — 선택 전에 고정된 수이고, pool이 허용하는 대로
   결정되는 것이 아니다 (무상한 = 규칙 없음)
② EBS 28/30은 거의 전수라 seed 추출의 재량이 2편뿐이다 — 선택 편향 여지 최소
```

**정직하게 적는다 — `c = 0.80`은 상한이 2편만큼만 구속한다.** 무상한이 0.811이다.
상한이 실질적으로 일하기 시작하는 지점은 `0.75`다(EBS 30→21, 9편 탈락).

### 1-2. 대안 대비 tradeoff

| `c` | `k` 상한 | EBS 추출 | CI 영향(1/√k 기준) |
|---|---|---|---|
| 0.70 | 23 | 16/30 — 14편 버림, seed 의존 큼 | 약 +23% |
| 0.75 | 28 | 21/30 — 상한이 처음으로 실질 구속 | 약 +12% |
| **0.80** | **35** | **28/30 — 재량 2편** | **기준** |
| 상한 없음 | 37 | 30/30 | −3% |

`k = 53`은 **현재 reservoir로 도달 불가**다(12편 추가 확보 선행). 이 문서에서
확보 확장을 승인하지 않는다.

## 2. `achieved_k` — 검증 뒤에 결정된다

```
N = 검증 통과 비-EBS 편수 (kbs · other · 기확보 FREE 4)
E = 검증 통과 EBS 편수
achieved_k = min(35, N + min(4N, E))
```

`c = 0.80`에서 `E ≤ 4N`이므로 **비-EBS 1편 탈락은 EBS 1편 제거로 못 메운다** —
4편을 빼야 하고 `k`가 35→30이 된다(보충4 §2).

```
target_k     35 — 지금 고정
achieved_k   검증 pool이 실제로 지원하는 값. 둘을 나란히 보고한다
```

**이것은 결과를 보고 표본 크기를 바꾸는 것이 아니라 사전 정의된 eligibility에 따른
표집틀 축소다.**

## 3. `9 queries/video` — precision cost가 0이라고 가정하지 않는다

> **9 queries/video는 independent cluster 수를 보존하면서 labeling workload를
> 제한하는 resource choice다. 다만 within-video effect estimation의 측정오차를
> 늘릴 수 있으므로 precision cost가 0이라고 가정하지 않는다.**

`53 → 477`(보충2 스케일링) 비율에서 온 값이고, `target_k = 35`면 **315질의**다.
`9 × achieved_k`가 라벨 노동량의 상한이다.

## 4. 유형 quota — **일반식이 먼저, 숫자는 그 결과다**

### 4-1. 규칙 (모든 `achieved_k`에 적용)

```
1  총 질의 = 9 × achieved_k
2  frozen dev 비율 34:24:38 (dev 96질의 실측 분포)을 그 총량에 적용
3  largest remainder (Hamilton)로 정수화
4  fractional remainder 순위는 **그 achieved_k에서 기계적으로 계산**한다
5  remainder 동률이면 사전 고정 tie-break order: mixed > scene > subtitle
```

> **`achieved_k`가 줄면 `111/79/125`의 뒤를 잘라 쓰지 않는다.** 새 총량에 Hamilton을
> 처음부터 다시 적용하고, 배정 알고리즘도 처음부터 다시 돌린다(보충4 §3-1).

> **모든 `achieved_k`에 걸쳐 고정된 것은 tie-break order 하나다.** 아래 §4-2의
> remainder 순위는 `achieved_k = 35`의 계산 결과일 뿐이며, **다른 `k`에 그 순서를
> 그대로 쓰지 않는다.** 이것은 결과 기반 변경이 아니라 이미 정해진 Hamilton
> 알고리즘의 정상 적용이다.

### 4-2. `achieved_k = 35`(총 315)의 계산 결과

```
복합형 34/96 × 315 = 111.5625  →  111
자막형 24/96 × 315 =  78.75    →   79
장면형 38/96 × 315 = 124.6875  →  125
                                  ───
                                  315

remainder 순위(이 k에서만)  자막 0.75 > 장면 0.6875 > 복합 0.5625
```

**결과를 보기 전에 계산돼 있다.** 판정 시점에 순위를 정하는 일이 없다.

### 4-3. 영상별 최초 배정

```
1  모든 영상에 mixed 1 + subtitle 1 + scene 1 (3 × achieved_k)
2  잔여 6 × achieved_k의 유형 라벨 목록을 만든다
3  seed 20260820으로 결정적 순열
4  seed-order 영상에 앞에서부터 6개씩
```

`achieved_k = 35`면 잔여가 `복합 76 · 자막 44 · 장면 90 = 210 = 35 × 6`이다.

기본 배정은 **어느 `achieved_k`에서도 성립한다** — 최소 지분 `24/96 = 0.25`이고
`0.25 × 9k = 2.25k ≥ k`다. 분기가 없다.

### 4-4. `type_unavailable`

swap + 종단 조항은 보충4 §3-3 그대로다. `target type quota`와
`achieved type quota`를 둘 다 보고하고, 차이가 있으면 **달성이 아니라 deviation으로
적는다.**

## 5. 선택 절차 — 승인 ① 안에서 끝나는 것

```
1   주 표집틀 33편 ID + metadata freeze
2   33편 전량 다운로드 (모델 실행 없음) · 파일 sha256 기록
3   FREE 4편 재현 게이트 4/4 통과                     ← 실패 시 중단
4   production 함수로 n_segments 실측 → 상태 3분류
5   verified pool → N · E → achieved_k
6   방송사 쿼터 → 프로그램 계열 비례 배분 (largest remainder)
7   계열 내 seed 20260820 단순무작위
8   선정 목록 + 질의/유형 배정표 + provenance 커밋      ← 승인 ① 종료
```

> **2~4단계는 승인 ② 의 모델 실행을 연 것이 아니다**(보충4 §1-5). sampling-frame
> verification을 위한 승인 ① 작업이다. **"다운로드했으니 FULL 실행도 승인된 것"이
> 아니다.**

**금지**(보충3 §5)

```
제목·썸네일·내용을 보고 개별 영상을 고르거나 빼는 것
"이 영상은 캡션이 잘 붙을 것 같다"는 판단
인덱싱한 뒤 캡션·점수를 보고 영상을 교체하는 것
뽑힌 영상이 마음에 안 들어 seed를 바꾸는 것
```

### 6-1. 외적 타당도 진술 (보충3 §6 그대로)

> **P2의 결론은 "장편 방송 다큐 중심 표본에서 `4B − 3B` 효과의 부호"다.** 배포 대상
> 전체로 일반화하지 않는다. dev(크리에이터 콘텐츠)에서 관측된 −0.090과 방향이 같아도
> **같은 모집단에서 재현된 것이 아니다.**

### 6-2. cluster bootstrap의 범위

> **동일 publisher의 제작·자막 관행에서 오는 source-level correlation을 video-only
> cluster bootstrap이 모델링하지 않는다. 따라서 얻은 CI는 realized broadcast-heavy
> sample에 대한 uncertainty로 해석하며, broader deployment population에 대한
> source-level uncertainty를 포함한다고 보지 않는다.**

**PRIMARY bootstrap 규칙은 그대로 cluster = 영상이다.** 이 문단은 해석 제한이고
추정량 변경이 아니다.
