## 4. 색인 배치 — 두 arm이 caption_model만 다르게

```
arm         3b = Qwen/Qwen2.5-VL-3B-Instruct (base) · 4b = Qwen/Qwen3-VL-4B-Instruct
            둘 다 4bit
단계        m1 → m2 → m3(base arm 전체) → mirror_frames → m3 --captions-only(4b)
            → m4(양 arm)
왜 이 순서   `m3 --subtitles-only`는 기존 캡션을 **보존만 하고 만들지 않는다**(8-5(7)).
            신규 색인에서 거부된다. 그래서 base arm을 정식으로 돌리고 프레임·자막을
            미러링한 뒤 후보 arm은 캡션만 생성한다 — STT는 한 번, 자막은 바이트 동일
```

**이 순서는 성능 최적화 대상이 아니다 — 비교가능성 불변식이다.** 다음 세션이 "arm별로
독립 실행하면 병렬화된다"는 이유로 순서를 되돌리지 않게 이유를 남긴다.

```
STT를 arm별로 두 번 돌리면   Whisper 출력이 arm 간에 달라질 수 있고, 그러면 두 arm이
                          caption_model **말고도** 자막에서 달라진다. PRIMARY Δ에
                          캡션 모델 효과와 자막 차이가 섞여 귀속이 불가능해진다
프레임을 arm별로 추출하면    같은 근거로 시각 입력이 갈릴 수 있다. 그래서 미러링한다
게이트가 실제로 막는다       검증 훅이 자막 sha256 동일·프롬프트 해시 동일·구간 수
                          사전등록 일치를 요구한다. 순서를 바꾸면 통과하지 못한다
격리        config_p2_{arm}.yaml을 config.yaml에서 재생성.
            paths.work=work_p2_{arm} · results_p2_{arm}
검증 훅      scripts/hooks/p2_index_hook.py — 비교가능성 12게이트
            (모델 id·양자화·프롬프트 동일·자막 동일·구간 사전등록 일치·
             캡션 결측 0·text_hash·emb shape)
```

`index_text_hash`는 구간별 자막+캡션만 해싱하므로 provenance 같은 최상위 키를 넣어도
색인이 무효화되지 않는다.

## 5-3. 운영 결함 1건 — CANARY 마커가 같은 run 디렉터리에 남는다

```
증상        CANARY가 STAGE_m1..m4_index_DONE을 쓰고, 같은 run_id로 FULL을 돌리면
            그 마커가 FULL 시작 시점에 이미 존재한다. 상태를 사람이 잘못 읽는다
            (2026-08-22 실제로 오독했다 — FULL이 m2 중인데 m4까지 끝난 것으로 보였다)
영향 범위    **판정·수치에는 섞이지 않는다.** 확인한 것 셋:
            ① 단계 소요는 배치 안의 time.time()에서 나온다 — 마커를 읽지 않는다
            ② 마커는 기록일 뿐 건너뛰기 근거가 아니다. FULL은 전 단계를 다시 돈다
            ③ validator hook은 *_full.json을 *_canary.json보다 우선한다

FULL 이후     마커 이름을 stage_mode로 분리(CANARY_STAGE_* / FULL_STAGE_*)하거나
            마커 안에 stage_mode·created_at·산출물 해시를 넣어 status reader가
            현재 실행의 것인지 확인하게 한다
```

## 7. 판정 규칙 — 결과를 보기 전에 고정된 것

```
PRIMARY     Δ_deploy = MRR_cap(4B q4) − MRR_cap(3B 4bit), caption-only α = 0.0
단위        paired video-cluster bootstrap, cluster = 영상 (k = 35)
판정 불가    achieved CI half-width > 0.04 → "이 규모로는 판정 불가"로 멈춘다
```

`k = 35`는 통계적 optimum이 아니다 — 필요 cluster 추정이 16~53으로 3배 어긋나고
reservoir 천장이 37이라 **어떤 선택도 half-width ≤ 0.04를 보장하지 못한다.** 즉
"판정 불가"는 실패가 아니라 사전등록된 정상 출구다.
