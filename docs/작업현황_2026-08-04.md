3. **비-hf 저장소**: `Qwen/Qwen3-ASR-1.7B`를 transformers로 로드하면
   `multi_modal_projector` 가중치가 **랜덤 초기화**된다(경고 확인). `-hf`가 정본.
4. **정규화 파손**: 수사를 음절 단위로 지우면 `사람들이`→`람들이`, `공사는`→`는`로

5. **Windows VRAM spill = 조용한 43배 지연**: 6GB VRAM이 일부 점유된 상태에서 모델을
   올리면 WDDM이 OOM 없이 시스템 RAM으로 넘긴다. 에러도 경고도 없고 결과도 동일한데
   속도만 수십 배 느려진다(arm C 실측 89.97초 vs 2.11초, 전사문 200/200 동일).
   → **속도 수치는 `nvidia-smi`로 VRAM 0MiB 확인 후 단독 실행으로만 측정**한다.
   배치 스크립트에서 arm을 연달아 돌리면 앞 arm의 잔존 점유가 뒤 arm 시간을 오염시킨다.

### 환경 제약 (Windows)

- `torchcodec` **제거 상태로 유지**. 설치하면 `backend="auto"`가 그걸 우선 선택하는데
  FFmpeg 공유 라이브러리가 없어 `libtorchcodec_core{4..8}.dll` 로드가 전부 실패한다.
  제거하면 librosa로 정상 폴백. `datasets`도 `Audio(decode=False)`+soundfile로 우회.
- `.venv_qwen3asr` = Qwen3-ASR 전용 격리 venv(transformers 5.14.1).
  **시스템 transformers는 5.9.0 그대로 유지** — 올리면 Qwen2.5-VL 캡션 출력이 바뀌어
  확정 인덱스 재현성이 깨질 수 있다.
- Qwen3-ASR 호출: `apply_transcription_request(audio=np배열, language="ko",
  processor_kwargs={"pad_to_multiple_of":100})`. 인코더가 feature length를 100프레임
  배수로 요구하고, `**kwargs`로 주면 무시된다(경고 확인). 출력 접두
  `language Korean<asr_text>`는 파싱으로 벗긴다.

근거 미달**이다. 다만 경계선이므로 표본을 늘리면 뒤집힐 수 있다(아래 후속).

**정정 (2026-08-05, 같은 날 앞선 판단 철회)**: A_prod를 넣기 전에는 기준선이
`A_native`였고 그때 나온 결론 두 개 — ① "C가 현행을 15%p 유의하게 이긴다",
② "모델 교체 없이 청킹만 바꿔도 유의한 개선(+9.5%p)이다" — 는 **모두 무효**다.
`A_native`가 운영 설정이 아니었기 때문이다. `condition_on_previous_text=False`가
바로 A_native에서 관측된 반복 루프(최대 14회, 중복률 0.071)를 막는 장치이고,
켜면 중복률이 0.026으로 전 arm 최저가 된다. 즉 **현행 파이프라인의 환각 방지 설정은
이미 잘 잡혀 있었고**, 청킹 이득은 그 설정을 뺀 arm과 비교했을 때만 생긴 착시였다.
교훈: 후보 모델을 현행과 비교할 때 **현행 arm은 운영 코드의 호출 인자를 그대로
복사**해야 한다. 라이브러리 기본값으로 세운 기준선은 허수아비다.
