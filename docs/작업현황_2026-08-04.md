   `multi_modal_projector` 가중치가 **랜덤 초기화**된다(경고 확인). `-hf`가 정본.

   속도만 수십 배 느려진다(arm C 실측 89.97초 vs 2.11초, 전사문 200/200 동일).
   → **속도 수치는 `nvidia-smi`로 VRAM 0MiB 확인 후 단독 실행으로만 측정**한다.
   배치 스크립트에서 arm을 연달아 돌리면 앞 arm의 잔존 점유가 뒤 arm 시간을 오염시킨다.

### 환경 제약 (Windows)

- `torchcodec` **제거 상태로 유지**. 설치하면 `backend="auto"`가 그걸 우선 선택하는데
  FFmpeg 공유 라이브러리가 없어 `libtorchcodec_core{4..8}.dll` 로드가 전부 실패한다.
  제거하면 librosa로 정상 폴백. `datasets`도 `Audio(decode=False)`+soundfile로 우회.

  **시스템 transformers는 5.9.0 그대로 유지** — 올리면 Qwen2.5-VL 캡션 출력이 바뀌어
  확정 인덱스 재현성이 깨질 수 있다.
- Qwen3-ASR 호출: `apply_transcription_request(audio=np배열, language="ko",
  processor_kwargs={"pad_to_multiple_of":100})`. 인코더가 feature length를 100프레임
  배수로 요구하고, `**kwargs`로 주면 무시된다(경고 확인). 출력 접두
  `language Korean<asr_text>`는 파싱으로 벗긴다.

#### 통제 결과 — 교란 5건 전부 측정했고, 결론을 바꾸지 않았다

   `temperature` fallback이 발동하지 않는다. → 단일 실행 비교가 유효했다.
2. **길이 편향: 존재하지만 작다.** 미끼(해당 회의에서 발화되지 않은 다른 회의 타깃)
   550건으로 우연 수준을 재니 우연정확률 c26 2.3~3.6% / c20 9.9% / c13 7.9~9.0%.
   전사가 가장 긴 C가 c26에서 가장 높다(0.036 vs 0.023). 보정 후 **순서가 바뀌지 않는다**
   — 다만 hit 기준으로는 A_chunked가 1위가 된다(0.7172 vs C 0.7129).
   *미끼는 회의록 요약에 없어도 실제로는 발화됐을 수 있으므로 오탐률은 상한이다.
   같은 미끼 집합을 쓰는 arm 간 비교가 유효한 부분이다.*
3. **숫자 표기: 영향 0.** Phase 1에서 결론을 뒤집었던 교란인데 고유명사 타깃에 숫자가

4. **참조 문체(개조식 조사 압축): 내 가설이 틀렸다.** "축자에 가까운 C가 다어절에서

#### 부수 소견 (2편 시점 기록 — 1번은 3편에서도 재현, 2번은 미검증)

1. **현행 설정은 전사를 가장 적게 뽑는다.** A_chunked 대비 길이비 c26 0.885 / c20 0.916,
   C 대비로는 0.77 / 0.85. `condition_on_previous_text=False` +
   `hallucination_silence_threshold=1.0`은 환각을 줄이지만 **실제 발화도 함께 버린다.**
   불일치 항목에서 A_prod만 놓친 것이 `영국`·`프랑스`·`일본`·`카타르`처럼 어렵지 않은
   단어라는 점이 방증이다(누락이지 오인식이 아니다).
2. **`place` 범주에서 A_prod가 약하다** (2편 합산 0.769 vs A_chunked·C 0.923).
   ⚠ **3편 재판정에서 범주별 검정을 하지 않았다**(사후 부분집합 검정 = 다중비교 문제).
   근거로 쓰지 마라. 청킹 자체는 전체 주지표에서 비유의(+0.0052 [−0.0069, 0.0179])이고
   환각을 늘리므로 **도입하지 않는다**.

#### 부호를 만든 것 — 불일치 항목 원인 분석

c20에서 A_prod가 0.8%p 앞선 것은 **5승 6패 = 순 1건**이다. 그 개별 항목의 원인:

**C가 진 이유 4가지**
1. **계통적 외래어 음소 오류**(유일한 진짜 모델 결함). 같은 오디오·같은 구절에서
   `A_prod: 청년 뉴딜 방안을 추진하여` vs `C: 청년 유딜 방안을 추진하여`.
   `K-뉴딜 아카데미`→`k유딜 아카데미`에서도 재현 — **1개 오류가 2개 타깃을 깎았다.**
2. **청킹 경계 중복**(모델 결함 아님, 실험 설계 탓). `…추진하여 약 방안을 추진하여 약
   10만여…` — 25초 창 2초 겹침 산물. A_prod는 long-form, C는 chunked라 **C만** 이
   불이익을 진다. 조건을 맞춘 A_chunked vs C_chunked는 +0.010 CI [−0.045, 0.065] 동률.
3. **우연 매칭이 만든 허수**. `아세안`이 C 전사의 `아예 안 되거나`에, `AA`(S&P 등급)가
   `ai기술`에 걸렸다. C가 해당 고유명사를 아예 안 적었는데 근사 매칭이 무관한 단어를
   물어 near로 완화됐다 — 지표 한계이고 양쪽 arm에 대칭으로 작용한다.
4. ~~**다어절 조사 차이 — 축자에 가까운 쪽이 불리**~~ → **3편 규모에서 반증됨.**
   c20 단독(다어절 24건)에서 A_prod 0.792 vs C 0.750으로 보였으나, 3편 합산(다어절 58건)
   에서는 **C가 가장 좋다**(d=0.0460 vs 0.0659/0.0675, hit 0.828 vs 0.724/0.741).
   회의 1편의 부분집합 관측을 일반화한 내 오류다.

**A_prod가 진 이유는 산발적 오인식이 아니라 누락이다** — 위 부수 소견 1번. 즉 두 arm의
실패 서명이 다르다: A_prod는 누락+자막 환각(두 회의 재현, 구조적),
C는 특정 외래어 음소 오류(소수, 계통적). 부호는 소수 개별 항목이 결정하고
두 arm은 측정 오차 안에서 동등하다.

#### 사고 3건 — 재발 방지

1. **기준선을 라이브러리 기본값으로 세웠다(c26 1차).** 그때 "C가 현행을 15%p 유의하게

   비유의가 된다. → **현행 arm은 운영 코드의 호출 인자를 복사할 것.**
2. **우연 기저 보정식을 잘못 세웠다.** hit(d==0)에서 빼는 기저를 `fp_attempt`(d<=τ,

   한다 — hit의 기저는 `fp_exact`(우연한 정확일치)다. 고친 뒤 순서가 원래대로 복귀했다.
   → **보정은 같은 사건 정의끼리만.**
3. **산출물 접미를 회의별로 안 붙였다.** c26만 하위호환으로 접미를 비워뒀더니

   **c26 타깃을 c20 전사문으로 채점**했다. 첫 `--pool` 결과가 여기 걸렸다
   (run 메타의 `audio_sec`가 두 회의 모두 9906초로 찍힌 것이 단서). 접미를 항상
   붙이도록 고치고 재채점했다. → **glob 기반 수집에서 접미 없는 키를 만들지 말 것.**

#### 설계 (스크립트 docstring에 상세)

- **타깃 사전 동결**: 회의록의 **발화 단락**에서만 추출하고 전사 **전에** 동결
  (sha256 기록). 범위 개회~의안심의, 그 안에서 문서기호(□▷◆※❶…) 시작 단락과
  개조식 종결 없는 표 조각을 단락 단위로 제외. 화자 라벨은 인명 표기 출처로 보존
  (단 `ㅇ (109전화…)` 같은 첨부문이 `ㅇ`를 공유하므로 "직책 접미 + 끝에 2~4자 한글
  이름"으로 좁힘). c26 제외 1건(`특명전권대사`), c20 제외 4건 — 전부 첨부문에만 존재.
  **규칙 교체 검증**: 단락 규칙을 c26에 적용해 기존 98타깃이 누락 0건으로 재현되는 것을
  확인한 뒤 c20에 적용했다.
- **지표**: 타깃별 근사 부분열 편집거리 d(시작·끝 자유). d=0 hit / 0<d≤τ near /
  d>τ absent. **분모 = 어느 arm이라도 d≤τ인 attempted 집합**(발화되지 않은 항목이
  분모를 오염시키는 것을 막는다). τ=0.40 사전 고정, 0.34/0.50 민감도 병기.

## 3. 전면교체 시 주의 (결론은 "교체 안 함" — 아래는 향후 교체 시 대비 기록)

STT 교체는 **확정 config 변경**이다. `subtitle`이 바뀌면 `text_hash` 불일치로 M5가
`ValueError`로 막고, 재임베딩+test 재평가가 필요하다(CLAUDE.md 절대규칙 1 — dev 완료 후
사용자 승인). 또한 기존 7영상에 M1 `--force`를 쓰면 `audio.wav` mtime이 바뀌어 STT
캐시가 무효화되고 재전사되므로 **금지**.

*Whisper 전사는 완전 결정적이지 않다: `temperature` 기본값이 fallback 리스트
`[0.0, 0.2, ..., 1.0]`이라 임계값 미달 구간은 샘플링으로 재시도된다. 평소에는
`stt_cache.json`이 재전사를 막아 결과가 고정된다.*

**교체를 안 하기로 했으므로 지금 할 일은 두 가지뿐이다**(둘 다 확정 config를 안 건드림):
1. **자막 크레딧 환각 후처리 필터** — `한글자막 by …` / `자막 제공 …` 패턴. 현행
   `A_prod`에서도 나오므로 교체와 무관하게 필요하다. 다만 `subtitle` 텍스트를 바꾸면
   `text_hash`가 달라져 재임베딩·test 재평가가 걸린다 — **dev에서 영향 범위를 먼저 재고**
   사용자 승인 후 적용(CLAUDE.md 절대규칙 1).
2. **청킹 검토** — `place` 범주 개선이 두 회의에서 재현됐지만 전체 hit은 비유의이고
   청킹이 환각을 늘린다(c26 A_prod 0건 → A_chunked 7건). 순이득이 불분명하므로
