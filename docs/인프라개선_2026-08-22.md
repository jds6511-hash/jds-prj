# 인프라 개선 4건 — 준비 완료, 통합은 HOLD (2026-08-22)

**연구 결과·모델 성능·사전등록 규칙을 바꾸지 않는다.** 목적은 재현성·관찰가능성·입력

연결하지 않았다.

```

           금지 토큰(caption·mrr·recall·score·rank·segments.json) 0
호환성      기존 launcher·plan·hook을 건드리지 않는다. 새 검사만 추가된다

```

**한계 — marginal이고 interaction이 아니다.** 현재 검사는 축별 marginal coverage를
보장한다. 모든 클래스 조합까지 보장하지 않는다 — `legacy × transcoded_h264 ×
cli_sensitive`가 존재해도 각 클래스가 서로 다른 영상에서 한 번씩 커버되면 통과한다.
전 조합(Cartesian product)을 요구하면 CANARY가 FULL만큼 커지므로 기본값은 비워 두고,
**사고가 실제로 난 조합만** `REQUIRED_COMBINATIONS`로 승격하는 확장점을 뒀다. 결과
JSON에 `coverage_kind: marginal_per_axis`와 `coverage_limit`을 박아 오해를 막는다.
FULL 입력에 없는 조합을 요구하면 설정 오류로 거부한다(영원히 통과 못 하는 요구).

**실측 1건.** 이번에 실제로 돌린 CANARY(`OBxKlA5rxjQ`, `baekmansonghee_jirisan`)를
넣으면 10개 클래스 중 **2개 미포함**이다.

```
missing   duration:longest · id_shape:cli_sensitive
제안 표본  -_mgcIUbbX4 · JPaaxxI3CEY · OBxKlA5rxjQ · baekmansonghee_jirisan  (4편, 10/10)
```

미포함 하나가 **사고 ①의 원인 영상 그 자체**다. 즉 이 검사가 있었다면 사고 ①은
CANARY에서 걸렸다.
