**표집을 시작하기 전에 커밋한다.** candidate는 이미 고정됐다

## 0. 평가 대상 — 세 규칙을 같은 표본에서 동시에 잰다

```
현행      is_corrupted_caption                        (CJK 규칙 OR 반복 규칙)
primary   (longest_cjk_run >= 2) OR (cjk_ratio > 0.02)  OR 반복 규칙
fallback  (longest_cjk_run >= 2)                        OR 반복 규칙
```

**반복 규칙은 세 규칙 모두에서 동일하고 변경하지 않는다.** 그래서 이 비교는 CJK 축의
비교다.

**"개선"이라는 말은 이 표본에서 동시에 잰 뒤에만 쓴다**(본 사전등록 §3).
development set 수치(0.7704 / 0.7692 / 0.0815)는 **여기서 판정 근거로 쓰지 않는다.**

## 1. 모집단과 표집틀

### 1-1. 모집단

```
출처       AI Hub 2×2 캡션 산출물 (4 arm × 194영상 × 12구간 = 9,312 arm-instances)
           docs/probes/_scratch/aihub_2x2_captions/full_2026-08-17/
arm        qwen25_3b/P0 · qwen25_3b/P1 · qwen3vl_4b/P0 · qwen3vl_4b/P1
제외       A116에 이미 표집된 116 unique frames — **전량 제외**
```

**A116/B24와 프레임이 겹치면 development set 재사용이다.** 제외는
`(video_id, seg_idx)` 단위로 하고, 제외 건수를 산출물에 기록한다.

> **새 영상·새 캡션 생성이 없다.** 같은 모집단에서 **겹치지 않는** 새 표본을 뽑는다.
> 그래서 GPU·라벨 도구 외의 자원을 쓰지 않는다.

### 1-2. 층 — development과 같은 셀 정의를 쓴다

셀 정의는 `scripts/i1_sample_sheet.py`의 것을 **그대로** 쓴다. 정의를 바꾸면
development의 모집단 수와 비교가 끊긴다.

| 셀 | 정의 | 이 표집에서의 역할 |
|---|---|---|
| C0 | CJK 0 · 현행 미적중 | 기저율. **human label 생략**(보충2 방식 유지) |
| C1 | CJK 0 · 현행 적중 | 반복 규칙 성분 |
| C2 | CJK 1–2 · 현행 미적중 | **핵심 층.** 세 규칙이 갈리는 곳 |
| C3 | CJK 1–2 · 현행 적중 | development에서 모집단 0이었다 |
| C4 | CJK 3–9 | 현행·후보 모두 적중 예상 |
| C5 | CJK 10+ | 심각 사례 |

**층 정의·셀 경계를 결과 보고 바꾸지 않는다.**

### 1-3. 쿼터 — 지금 고정한다

```
C2   60   (development 24보다 크게. 모집단 800 규모에서 세 규칙이 갈리는 층)
C4   40
C5   전수 (상한 24)
C1   전수 (상한 24)
C3   전수 (상한 24)
C0   24   human label 생략. cjk_count == 0 파생 규칙으로 처리
seed 20260820
```

**표집은 층 내 단순무작위**이고, seed와 제외 목록을 산출물에 기록한다.
**쿼터를 결과 보고 늘리지 않는다.** 층이 모집단보다 크면 전수를 쓰고 그 사실을 적는다.

### 1-4. C2 쿼터 60의 근거

development에서 C2 20건 중 20건이 drift였고 후보가 15건에 발동했다. 그 비율
(0.75 부근)에서 **Wilson 반폭이 60건이면 ±0.11, 24건이면 ±0.17** 수준이다.
**정밀도를 크게 끌어올리는 규모가 아니라 development보다 넓히는 규모다** — 그 한계를
결과 문서에 적는다.

> **60이 어떤 검정력 목표를 달성한다고 주장하지 않는다.** 라벨 노동량과 층 대표성
> 사이의 선택이고, 달성된 CI 폭은 결과에 그대로 적는다.

## 2. 라벨 절차 — development와 동일

```
A단계   프레임만 보고 화면 글자 판정 — no_text · korean_text_only ·
        cjk_text_present · unclear
B단계   A가 cjk_text_present인 것만 — matches_screen · drift_despite_text ·
        drift_no_text · unclear
도구    scripts/label_contact_sheet.py (프레임+시각만) · scripts/label_intake.py
금지    m5_search·m6_evaluate import · docs/probes/frame_human_kit.py
금지    캡션·자막을 라벨 시트에 노출하는 것
숨김    arm · 현행 적중 여부 · 셀 · 후보 발동 여부 — **전부 시트에서 가린다**
```

**후보 발동 여부를 시트에서 가리는 것이 특히 중요하다.** 후보가 발동한 프레임을 알면
라벨이 후보 쪽으로 끌린다.

**라벨은 사용자가 쓴다.** 참 라벨 도출은 `i1_stage_b_analysis.true_label`을 그대로
재사용하고 **새 규칙을 만들지 않는다.**

## 3. 판정식 — 표집 전에 고정

### 3-1. 주 지표

```
precision_weighted   세 규칙 각각. 셀 모집단 가중
recall_est           세 규칙 각각. est_TP / est_drift_total
단위                 셀 모집단 가중. **전수 셀은 스케일링하지 않는다**
                     (development에서 이 결함이 recall을 0.0815→0.0919로 부풀렸다)
CI                   Wilson. 표본이 프레임 클러스터임을 명시 — 실제 폭은 더 넓을 수 있다
보고                 precision_sample도 함께 낸다. 비가중은 전수 셀이, 가중은 C2가 지배한다
```

### 3-2. 판정

```
primary 또는 fallback이 현행 대비
  recall CI가 겹치지 않고 더 높으면서 precision_weighted >= 0.95  → 우세 관측
  recall이 더 높으나 CI가 겹치면                                  → 방향 관측, 판정 보류
  precision_weighted < 0.95                                       → 채택 후보 아님
현행이 더 높으면                                                  → 재설계 기각, 그대로 기록
```

**"비유의"를 "차이 없음"으로 쓰지 않는다.** CI가 겹치면 겹쳤다고 적는다.

**primary와 fallback 중 하나를 사후에 고르지 않는다.** 둘 다 보고하고, 둘 다 조건을
만족하면 **보충1 §5의 동률 규칙**(단순한 규칙 우선)을 적용한다 — development에서
recall 우선 정렬이 만든 artifact를 여기서 반복하지 않는다.

### 3-3. 부수 보고

```
셀별 precision·recall — 특히 C2를 분리해 낸다
FP 범주: scene_text · 선언 범주 밖(개수와 참 라벨을 그대로 적는다)
longest_cjk_run == 1(단일 CJK 문자) 구간의 미탐 — 후보가 원리상 못 잡는 영역
제외된 A116 프레임 수 · unclear 수 · 층별 실제 표집 수
```

## 4. 하지 않는 것

- **hard gate 승격을 이 단계에서 하지 않는다.** 재캡셔닝 트리거로 만드는 것은 확정
  인덱스에 영향을 주는 변경이라 **사용자 승인 + 별도 사전등록**이 필요하다
  (본 사전등록 §4).
- **candidate를 바꾸지 않는다.** freeze된 두 규칙만 잰다. 결과를 보고 R·T를 조정하는
  것은 이 문서가 금지한다.
- **격자를 다시 돌리지 않는다.** 재탐색이 필요하면 새 사전등록이고, development set
  재사용이라는 사실을 명시해야 한다.
- **캡션을 내용 보고 고치지 않는다.** 어떤 규칙이든 자동 판정만이다(CLAUDE.md 절대
  규칙 2).
- **test를 건드리지 않는다.**
- **비-CJK drift로 확장하지 않는다.** 반복 규칙은 이 사이클 범위 밖이다.
- **P2 트랙을 바꾸지 않는다.** P2 PRIMARY는 fresh `Δ_deploy`, cluster = 영상 그대로다.

## 5. 절차와 승인 지점

```
이 문서 커밋
  → 표집 코드 · TDD 커밋 (시트 생성 전)
  → 표집 실행 → 시트 생성 (A116 제외 검증 · seed 기록)
  → [사용자 작업] A 라벨 → B 라벨
  → 분석 1회 — 세 규칙 동시 평가
  → 결과 문서
  → [사용자 승인] hard gate 승격 여부
```

**라벨 노동량이 사용자 부담이므로 쿼터 조정이 필요하면 표집 전에 말한다.**
`C2 60 · C4 40 · C0 24 · 전수 셀`이면 A 라벨 대상은 대략 **150~190 프레임**이고,
B 라벨은 그중 A가 `cjk_text_present`인 것만이다.

**표집 전 확인 1건** — 이 쿼터가 부담이면 `C2 40 · C4 24`로 줄이는 선택지가 있다.
줄이면 CI가 넓어지고, 그 사실을 결과에 적는다. **어느 쪽이든 표집 전에 확정하고 이후
바꾸지 않는다.**
