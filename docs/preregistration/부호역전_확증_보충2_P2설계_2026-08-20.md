# 부호역전 확증 보충 2 — P2 estimand·표집틀·판정식 (2026-08-20)

**이 문서는 결과를 본 뒤 고치지 않는다.** 본 사전등록
(`부호역전_확증_사전등록_2026-08-18.md`, `98d4efa`)과 보충1(`cb16697`)은 **수정하지
않고**, P2의 정밀화를 여기에 적는다.

**표집·라벨·인덱싱을 시작하기 전에 커밋한다.** 규모(cluster 수) 확정과 신규 인덱싱은
이 문서 다음의 별도 승인 지점이다.

## 0. P1이 남긴 것 — 무엇이 통제됐고 무엇이 안 됐나

```
제거됨   서로 다른 가중치 스냅샷·프롬프트 때문이라는 설명
         model_revision(4B ebb281ec… / 3B 66285546…)과 prompt_sha256이 두 표본에서 동일
지지됨   candidate-pool size가 4B−3B contrast에 영향을 주는 plausible contributor
         dev I_pool −0.0344 · AI Hub I_pool −0.0228 (반대 방향 조작, 같은 부호)
미해결   sign reversal 자체
         dev를 12로 줄여도 −0.0559, AI Hub를 2,328로 늘려도 +0.0112. 남은 격차 약 0.067
```

**따라서 P2가 모델 채택 판단의 핵심 병목이다.** P1은 후보를 좁혔을 뿐이다.

## 1. P2의 질문 — 결과 보기 전에 문장으로 고정

> **"candidate-pool scale을 장편 dev와 겹치는 범위로 통제한 fresh long-form sample에서도
> `4B − 3B` effect가 음수인가, 그리고 그 효과가 영상·질의 유형에 따라 어떻게
> 이질적인가?"**

두 부분이다 — **부호**와 **이질성**. 이질성은 부호 판정을 대체하지 않는다.

## 2. PRIMARY estimand — 하나만 둔다

```
PRIMARY   Δ_deploy = MRR_caption(qwen3vl_4b_q4/P0) − MRR_caption(qwen25_3b_4bit/P0)
          캡션 단독 α=0.0. α는 개입하지 않는다
단위      paired video-cluster bootstrap. **cluster = 영상**
표본      fresh long-form sample (§3). dev·AI Hub는 쓰지 않는다
```

**배포 경로 정밀도(4bit)로 양쪽을 잰다.** AI Hub 2×2는 bf16 arm이었고 `Δ_quant = +0.0091`
(CI가 0을 포함)이 그 차이를 무시할 근거처럼 보이지만, **P2는 자기 표본에서 자기 대비를
낸다** — 과거 수치를 끌어와 대체하지 않는다.

### 2-1. 설계 변수 — 사전 고정

| 변수 | 성격 | 처리 |
|---|---|---|
| **후보 풀 크기** (영상별 세그먼트 수) | 연속 | **연속 변수로 그대로 기록.** 구간으로 뭉개지 않는다 |
| **query type** (장면형·자막형·복합형) | 범주 | 병합 전 층별 목표 수 사전등록 |
| 영상 도메인 | 범주 | 기록만. 층으로 쓰지 않는다 (dev·AI Hub와 대조 불가) |
| 캡션 길이·오염 수 | 연속 | 기록만. exploratory |

**풀 크기 목표는 `150~400` 세그먼트다.** 근거는 **dev의 operational regime과 겹친다는
것 하나**다.

> **`150~400`을 P1이 증명한 최적·안정 구간으로 쓰지 마라.** P1이 보인 것은 풀 크기가
> contrast를 움직인다는 것뿐이다. 그리고 dev 곡선은 비단조였다(96이 전체보다 더 음수).
> **`I_pool`을 slope나 dose-response로 해석하지 않는다** — "풀이 커질수록 매 N개마다
> 4B가 일정하게 악화된다"는 종류의 증거가 아니다.

**151짜리와 397짜리를 같은 조건으로 취급하지 않는다.** 그렇게 뭉개면 P1에서 찾은 효과를
다시 지운다.

## 4. cluster 수 결정 규칙 — **숫자가 아니라 규칙을 지금 고정한다**

실제 cluster 수는 라벨 노동량이 걸린 사용자 결정이다. 그래서 **선택 절차와 판정 결과의
취급**만 여기서 못박는다.

### 4-1. 목표

```
목표          paired video-cluster CI half-width ≤ 0.04
              (구분해야 하는 두 점추정이 +0.031과 −0.090이다)
필요 cluster  16 (dev 실측 스케일링) ~ 53 (AI Hub 실측 스케일링)
              두 추정이 3배 어긋난다 — 표본 구조가 달라서다. 하나로 못 박지 않는다
```

### 4-2. 규칙

```
1  cluster 수 k를 표집 전에 확정하고 별도 문서로 커밋한다
2  k를 확정한 뒤에는 결과를 보고 늘리지 않는다
3  달성된 CI half-width가 0.04를 넘으면 **"이 규모로는 판정 불가"로 보고하고 멈춘다**
   — 유의성을 쫓아 추가 표집하지 않는다
4  그래도 추가 표집이 필요하다고 판단되면 **새 사전등록**이 필요하고, 결합 분석임을
   명시한다 (두 번 본 것을 한 번 본 것처럼 쓰지 않는다)
5  k < 16이면 **판정용이 아니라 기술용**이라고 문서에 적고 PRIMARY 판정을 하지 않는다
```

**3번이 이 절의 핵심이다.** "표본이 작아서 애매하다"를 사후에 "차이 없음"으로 바꾸지
않기 위한 조항이다.

## 5. exclusion 규칙 — `wl_q03` 사례를 일반화한다

P1에서 `wl_q03`의 `gt_seg_idx = [132, 133, 134, 312]`(비연속, 범위 181)가 연속 창 규칙과
구조적으로 양립 불가능했다. 보충1은 `|gold| > pool_size`만 예상했다.

> **gold span이 candidate-construction rule과 구조적으로 양립 불가능한 경우, 자동
> 수정·축약하지 않고 사전 정의된 exclusion reason으로만 제외하며 exclusion count를
> 보고한다.**

```
금지    코드가 알아서 gold를 자르거나 창을 늘려 맞추는 것
금지    조용히 분모에서 빼는 것
필수    명시 목록으로만 제외 (--exclude), 산출물에 query_id + 사유 기록
필수    변형 간 비교는 **같은 common support**에서 다시 계산 (P1의 95질의 방식)
필수    "라벨 안 함"과 "분모에서 제외"를 구분해 적는다
```

**사전 정의 exclusion reason 목록** — 이 목록 밖의 사유로 제외하지 않는다.

```
gold_count_exceeds_pool          |gold| > pool_size
gold_span_incompatible_with_rule gold 범위가 규칙(연속 창 등)에 담기지 않음
caption_missing                  해당 arm에 캡션 누락 (arm 무효 판정과 별개)
```

## 6. 기록 요구사항

```
필수  model_id · model_revision · prompt_sha256 · attn_implementation · dtype
      requested_quantized / effective_quantized / quantization_mismatch
      vlm_max_pixels · max_new_tokens · rep_penalty
필수  영상별 세그먼트 수 (연속) · 질의당 후보 풀 정의
필수  embedder · evaluator commit · seg_len
필수  generation 실패 수와 사유. 한 arm이라도 완주하지 못하면 PRIMARY를 계산하지 않는다
      (성공 부분집합 비교 금지, RR=0 대입 금지)
필수  기록이 없는 parity 필드는 `unknown_not_recorded` — PASS도 FAIL도 아니다
```

**두 arm을 같은 하드웨어·같은 commit·같은 코드 경로에서 함께 생성한다**
(CLAUDE.md 후보 검증 규약 4번, 동시점 대조군).

## 7. 판정식 — 표집 전에 고정

```
PRIMARY  Δ_deploy의 paired video-cluster CI
         CI가 0을 배제하고 음수  → dev 방향 재현
         CI가 0을 배제하고 양수  → AI Hub 방향 재현
         CI가 0을 포함            → 이 규모로는 판정 불가. 규모를 적고 멈춘다 (§4-2)

부수     층별(query type) Δ와 영상별 Δ를 함께 보고한다. **판정은 전체 Δ로 한다**
부수     세그먼트 수와 Δ의 관계를 산점으로 보고한다 — 기술값이고 판정에 쓰지 않는다

금지     α·τ 재탐색으로 부호를 구제하는 것
금지     "비유의"를 "차이 없음"으로 쓰는 것
금지     P1의 I_pool을 adoption gate로 승격하는 것 — P1은 새 표본이 아니다
금지     층별 결과 중 유리한 층을 골라 판정하는 것
```

- **`results/alpha_search_dev.json`·`eval_test.json`에 쓰지 않는다.**
- **확정 인덱스를 덮어쓰지 않는다.** 신규 영상은 그 영상만 인덱싱한다.
- **P1 결과를 보고 이 문서의 판정식을 고치지 않는다.** P1은 이미 끝났고, 여기서 P1이
  정한 것은 §2-1의 설계 변수 목록뿐이다.
