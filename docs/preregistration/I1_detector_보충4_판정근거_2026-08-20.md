**첫 A 라벨 입력 전에 커밋한다.** `label_kit/i1_validation/labels_v.csv`의 83행이

## 0. 왜 이 문서가 필요한가 — 소진이 만든 공백

보충2 §3-2의 판정식은 **`C4 40`·`C5 전수`가 fresh로 들어올 예정일 때** 쓰였다.
보충3 §1에서 그 셀들의 잔여 모집단이 0임이 확인됐고, 그래서 `precision_weighted`를
전체 모집단 가중으로 내는 계산은 **`combined_with_carried_over` 블록에만 존재한다.**

보충3 §6은 "판정식 보충2 §3 그대로"라고 적었을 뿐 **어느 블록에서 계산하는지를
지정하지 않았다.** 그 공백을 라벨 0건 상태에서 닫는다.

> **이것은 판정식을 바꾸는 것이 아니라 판정식이 적용될 블록을 지정하는 것이다.**

## 1. 판정 근거는 `fresh_strata_only`다

```
verdict 근거   fresh_strata_only (C0 · C2)
verdict 밖     combined_with_carried_over — 전체 모집단 문맥용 보고
```

이유 둘이다.

**(1) 순환이다.** carried-over census는 **후보를 고른 데이터**다. primary와 fallback을
갈랐던 C4 인스턴스 1건이 바로 거기 있다(보충3 §2-3). 선정에 쓴 표본을 판정의
분자·분모에 넣으면 선정 데이터로 선정 결과를 검증하는 것이 된다.

**(2) 편향 방향이 판정 기준으로 쓸 수 없는 성질이다.** carried 셀은 세 규칙이 거의
일치하는 구역이다(현행 68/68 · primary 68/68 · fallback 67/68 / C5 3/3 전부).

```
combined recall      세 규칙에 같은 양을 더해 **대비를 희석**한다 (후보에게 불리)
combined precision   carried TP가 분자·분모에 같이 들어가 **올라간다** (후보에게 유리)
```

**즉 combined는 recall에서는 후보를 깎고 precision 하한에서는 후보를 밀어준다.**
어느 쪽도 판정에 쓸 성질이 아니다.

> **fresh-only는 보수적 방향이다.** precision 하한 0.95를 더 좁은(더 엄한) 분모에서
> 재고, recall 대비는 희석 없이 본다. 결과를 보지 않은 상태에서 고정하므로 소급
> 완화가 아니다.

## 2. precision 정의 — **estimated totals의 ratio**

```
Precision_fresh = Σ_s est_TP_s / Σ_s est_Fired_s        (s ∈ {C0, C2})
```

**층별 precision의 가중평균이 아니다.** C0은 `n_fired = 0`이므로 층별 precision이
`0/0`이고, 그것을 1이나 0으로 대입해 평균을 만들면 판정치가 대입값으로 결정된다.

**ratio 형태에서는 C0이 분자·분모에 각각 0을 기여하고 끝난다.** 대입 경로가 없다.

동결된 코드가 이미 이 형태다(`docs/probes/i1_validation_analysis.py`, `c4e0f05`에서
라벨 도착 전 커밋):

```python
est_tp = sum(c["est_tp"] for c in by_cell.values())
est_fired = sum(c["est_fired"] for c in by_cell.values())
"precision_weighted": (round(est_tp / est_fired, 4) if est_fired else None),
```

> **이 절은 구현을 바꾸지 않는다.** 이미 그런 형태임을 명문화하고, 층별 평균으로
> 바꾸는 것을 금지한다.

전수 셀 스케일링 금지도 그대로다(보충2 §3-1) — fresh 층 C0·C2는 둘 다 표집 층이고
`pop ≫ sampled`이므로 스케일링 대상이다. development에서 이 결함이 recall을
0.0815에서 0.0919로 부풀렸다.

## 3. 명칭 — 이 수치를 무엇이라 부르는가

```
명칭    freshly sampled rule-expansion region precision
        (freshly sampled rule-expansion region recall)
금지    whole-detector fresh precision
금지    fully fresh · all fresh (코드가 문자열로 금지)
```

**의미를 정확히 적는다.** fresh 층에서 후보가 발동하는 곳은 C2뿐이고(C0은 발동 0),
C2는 **새 규칙이 현행보다 새로 건드리는 구역**이다. 따라서 이 precision은
**규칙 확장분의 precision**이다.

> **현행 detector 전체의 fresh precision은 이 모집단에서 측정 불가다.** precision의
> 분모는 규칙이 발동한 인스턴스이고, 현행 규칙의 발동 층(C1·C4·C5) 잔여가 0이다
> (`docs/I1_모집단소진_설계결과_2026-08-20.md` §1).

## 4. `combined_with_carried_over` 블록의 출력

```
제거    precision — carried 셀의 정확한 fired accounting을 복원하기 전에는 내지 않는다
유지    recall — carried-over development evidence가 섞인 **descriptive context only**
불변    contains_carried_over: true · carried_over_strata 목록 ·
        "이번에 재검증되지 않았다" 주석
```

**precision을 제거하는 이유는 현재 구현이 carried 셀 FP를 0으로 가정하기 때문이다.**
`_combine`이 carried 기여를 `est_fired += tp`로 놓는데, development에서 C1에 선언범주
밖 FP 1건이 있었다(반복 규칙 발동). 방향이 세 규칙 모두 **유리한 쪽**이다.

> **숫자를 고쳐서 남기지 않고 지운다.** carried census가 `fired`를 기록하지 않으므로
> 정확한 값을 복원할 수 없고, 부정확한 precision은 오해만 만든다. 복원이 필요하면
> 새 사전등록이다.

`combined recall`은 판정에 쓰지 않는다는 조건에서만 남긴다. 전체 모집단 규모를
기술하는 용도다.

## 5. 판정식 — 보충2 §3-2를 fresh 블록에 적용한 형태

```
primary 또는 fallback이 현행 대비, fresh_strata_only에서
  recall CI가 겹치지 않고 더 높으면서 precision >= 0.95   → 우세 관측
  recall이 더 높으나 CI가 겹치면                          → 방향 관측, 판정 보류
  precision < 0.95                                        → 채택 후보 아님
현행이 더 높으면                                          → 재설계 기각, 그대로 기록
```

**"비유의"를 "차이 없음"·"동등"으로 쓰지 않는다.** CI가 겹치면 겹쳤다고 적는다.
Wilson은 descriptive다(보충3 §5) — 폭이 좁아졌다고 정밀도가 충분하다고 선언하지
않는다.

둘 다 조건을 만족하면 보충1 §5 동률 규칙(단순한 규칙 우선)에 따라 **`R_only(R=2)`**다.
development의 0.0012 차이를 validation에서 "확인"하려 하지 않는다(보충3 §2-3).

**우세 관측이 나와도 그것은 hard gate 승격이 아니다.** 재캡셔닝 트리거로 만드는 것은
확정 인덱스에 영향을 주는 변경이라 사용자 승인 + 별도 사전등록이다(본 사전등록 §4).

## 6. 왜 첫 A 라벨 **전에** 이 문서를 커밋하는가

**라벨러와 설계자가 같은 사람이다.** 83프레임의 A 라벨을 채우는 동안 C2에서
`cjk_text_present`가 얼마나 나오는지는 집계를 돌리지 않아도 들어온다.

이 문서는 **어느 evidence block이 verdict를 결정하는지**를 정하므로 결과와 직접
연결된다. 라벨을 한 장이라도 쓴 뒤에 정하면 순서가 뒤집힌다.

> **"지표를 계산하지 않았다"는 "결과를 보지 않았다"와 다르다.**

## 7. 바뀌지 않은 것

```
평가 대상   현행 · primary R_or_T(2, 0.02) · fallback R_only(2) — freeze 그대로
표집        C2 60 · C0 24 = 84 인스턴스 / 83 프레임, seed 20260820
불변식      C0 3-규칙 fail-closed · n_fired − n_tp == FP_declared + FP_outside
재현 게이트 carried-over census가 development 공표값과 불일치하면 중단
라벨 절차   A → B. 시트에서 arm·셀·현행 적중·후보 발동·A 라벨 전부 가린다
금지        candidate 변경 · 격자 재실행 · R=1 추가 · 임계 재조정 ·
            C4 census 재사용 · hard gate 승격 · test 접촉
P2 트랙     불변. 이 결과로 P2 estimand·CI 규칙·표집 규칙을 수정하지 않는다
```

**B 단계 blindness 제한을 미리 적는다.** B의 질문 자체가 캡션의 CJK와 화면 글자의
관계를 묻기 때문에 **캡션 노출이 필수**고, `fallback = longest_cjk_run >= 2`이므로
캡션에서 후보 발동 여부가 상당 부분 도출된다. **완전한 candidate-blind를 주장하지
않는다.** 목표는 avoidable leakage 차단이다.

```
A CSV sha256을 B 시작 전에 동결   캡션 본 뒤 A를 고치는 경로 차단
B 선정은 A 라벨만 사용            A == cjk_text_present 단독 (true_label 도출 규칙)
B 시트에서 숨김                   arm · 셀 · i1a_hit · 후보 발동 · **A 라벨**
결과 문서에 명기                  캡션 노출로 후보 발동에 대한 블라인드는
                                  유지되지 않았다
```
