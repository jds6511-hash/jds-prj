## 3. 판정 기준 — **성공/실패 판정을 두지 않는다**

이 실행에는 관문이 없다. **관측값을 기록하고 그대로 보고한다.**

다만 다음 셋은 관측되면 **다음 단계를 멈추는 사유**로 미리 적는다.

| # | 관측 | 뒤따르는 것 |
|---|---|---|
| S1 | `catastrophic` ≥ 1편 | 원인 규명 전에는 표본 확대로 넘어가지 않는다 |

같은 한계다. 결과와 함께 병기한다. **관측 후 임계를 고치지 않는다.**

## 4. 오염 경계 — 순서를 고정한다

```
event inventory 작성 → --freeze  ──┐
                                   ├→ M8 예비 실행 결과 **열람**
              M8 예비 실행 (GPU) ──┘
```

**M8 실행 자체는 목록 동결 전에 해도 된다**(사람이 안 보면 영향이 없다).
**열람은 동결 후에만 한다.** 사람이 M8이 제안한 사건 단위를 먼저 보면, 목록을
만들 때 그쪽으로 끌려가 분모가 오염된다.

- 실행은 서버에서, 산출물은 `/ssd` 밑에 둔다.
- **동결 전에 결과 파일을 열지 않는다** — 요약 수치도 보지 않는다.
- `event_inventory_kit.load_reference`가 동결 여부를 코드로 확인한다.

*더 안전한 쪽은 목록을 먼저 끝내는 것이다. GPU 대기를 줄이려 병렬로 두되,
열람 시점만 지킨다.*
