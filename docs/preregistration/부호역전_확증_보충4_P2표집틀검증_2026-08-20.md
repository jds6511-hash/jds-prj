# 부호역전 확증 보충 4 — P2 표집틀 검증과 질의 배정 (2026-08-20)

**이 문서는 결과를 본 뒤 고치지 않는다.** 본 사전등록(`98d4efa`)·보충1(`cb16697`)·
보충2(`58de1bf`)·보충3(`e878a4d`)은 **수정하지 않는다.**

**영상을 고르기 전에 커밋한다.** 모델 산출물은 하나도 생성·열람하지 않았다.

## 0. 이 문서가 닫는 공백 셋

```
① eligibility 정의가 둘이었다 — metadata 기반 vs production segment-count 기반
② 질의 유형 총량은 정해졌지만 **영상별 최초 배정**이 없었다
③ 다운로드 실패와 segment 탈락이 같은 상태로 기록될 뻔했다
```

## 1. eligibility — **2단계. 최종 판정은 production 규칙이다**

```
1차 (완료)   yt-dlp metadata duration → ceil(duration/5). 후보 62건 → 적격 39
최종         **실제 다운로드 파일**에 production 함수를 적용한 n_segments
판정식       150 <= n_segments <= 400
```

> **metadata duration은 provisional screening에만 쓴다. 최종 표집틀은 모델 산출물을
> 생성하기 전에 production segment-count rule로 검증한다. 이 단계에서 caption ·
> embedding · retrieval score를 생성하거나 열람하지 않는다.**

### 1-1. 검증기는 production 함수를 **그대로 호출한다**

```
사용   src/m1_preprocess.get_video_info(video)  →  make_segments(duration, 5)
근거   m1_preprocess.py:54가 len(segs) == ceil(duration / seg_len_sec)를 assert한다
금지   별도 ffprobe 파서·재구현 — ceil/floor·소수 처리에서 갈릴 여지를 남긴다
금지   M1 실행. 배포 work/에 아무것도 쓰지 않는다. 함수만 호출한다
```

### 1-2. 재현 게이트 — 신규 파일 건드리기 전에 먼저 통과시킨다

기확보 FREE 4편은 이미 production이 세그먼트를 냈다.

```
baekmansonghee_jirisan 183 · jissi_farm 211 · softyeon_ceramics 192
pland_costco_hosting 395
```

같은 함수를 그 로컬 파일에 돌려 `work/*/segments.json`의 `n_segments`와 **4/4
정확히 일치**해야 한다. 불일치면 검증기가 production과 다른 것이므로 **중단한다.
허용 오차를 만들지 않는다.**

### 1-3. 상태 3분리 — **다운로드 실패를 segment 탈락으로 기록하지 않는다**

```
verified_eligible        production n_segments가 150~400
segment_ineligible       production n_segments가 범위 밖
verification_unavailable 다운로드·probe 실패로 **검증 자체를 수행할 수 없었다**
```

`verification_unavailable`은 verified pool에 들어가지 않지만 **판정 기준에서
탈락한 것이 아니다.** 개수와 사유를 따로 보고한다.

### 1-4. 다운로드는 **한 번만** 하고 그 파일을 승인 ②가 쓴다

```
필수   다운로드 후 파일 sha256 기록. 인덱싱 시점에 대조한다
금지   승인 ② 때 다시 내려받는 것 — 재업로드·편집으로 duration이 달라지면
       검증한 표집틀과 인덱싱한 영상이 달라진다
```

### 1-5. **이 단계는 승인 ① 작업이다**

> **33편 다운로드와 production segment 검증은 승인 ②의 모델 실행을 연 것이
> 아니다. sampling-frame verification을 위한 승인 ① 작업이다.**

경계를 다시 적는다.

```
승인 ①   표집틀 검증 (다운로드 · segment 실측) + 표본 선정 (seed 추출 · 목록 커밋)
승인 ②   모델 실행 자원 개방 — caption · STT · VLM · embedding · indexing · search
```

**"다운로드했으니 FULL 실행도 승인된 것"이 아니다.**

## 2. `achieved_k` — 분기 없는 한 식

```
N = 검증 통과 비-EBS 편수 (kbs · other · 기확보 FREE 4)
E = 검증 통과 EBS 편수
achieved_k = min(target_k, N + min(4N, E))          target_k = 35
```

`c = 0.80`에서 `E/(E+N) ≤ 0.8 ⟺ E ≤ 4N`이다. 따라서:

| 검증 통과 비-EBS `N` | EBS 상한 `4N` | `achieved_k` 상한 |
|---|---|---|
| 7 | 28 | **35** |
| 6 | 24 | 30 |
| 5 | 20 | 25 |
| 4 | 16 | 20 |

> **비-EBS 1편 탈락은 EBS 1편 제거로 메울 수 없다.** 4편을 빼야 하고 `k`가 35→30이
> 된다. 이것은 결과를 보고 표본 크기를 바꾸는 것이 아니라 **사전 정의된 eligibility에
> 따른 표집틀 축소**다.

```
target_k     35 — 사전 고정
achieved_k   검증 pool이 실제로 지원하는 값
보고         둘을 나란히 적는다. achieved < target이면 축소 사유와 편수를 적는다
achieved_k < 16   기술용. PRIMARY 판정을 하지 않는다 (보충2 §4-2 규칙 5)
half-width > 0.04 "이 규모로는 판정 불가"로 보고하고 멈춘다
금지         결과를 보고 reservoir를 늘리는 것
```

## 3. 질의 배정 — 총량·영상별 배정·결손 처리를 전부 지금 고정한다

### 3-1. 총량과 유형 쿼터

```
영상당 질의 수   9
총 질의          9 × achieved_k
유형 비율        dev 96질의의 동결 분포 — 복합형 34 · 자막형 24 · 장면형 38
정수화           largest remainder (Hamilton)
```

`achieved_k = 35`, 총 315일 때:

```
복합형 34/96 × 315 = 111.5625  →  111
자막형 24/96 × 315 =  78.75    →   79
장면형 38/96 × 315 = 124.6875  →  125
                                  ───
                                  315
```

> **`achieved_k`가 줄면 `111/79/125`의 뒤를 잘라 쓰지 않는다.** 새 총량
> `9 × achieved_k`에 **Hamilton을 처음부터 다시 적용**한 뒤, 아래 배정 알고리즘도
> 처음부터 다시 돌린다.

### 3-2. 영상별 최초 배정 — 결정적

```
1  모든 영상에 mixed 1 + subtitle 1 + scene 1을 먼저 배정한다 (3 × achieved_k)
2  남은 quota(= 6 × achieved_k)의 유형 라벨 목록을 만든다
3  그 목록을 seed 20260820으로 결정적 순열한다
4  seed-order 영상에 앞에서부터 6개씩 배정한다
```

`achieved_k = 35`면 2단계 잔여가 `복합 76 · 자막 44 · 장면 90 = 210 = 35 × 6`이다.

**기본 배정은 어느 `achieved_k`에서도 성립한다** — 최소 지분이 자막형
`24/96 = 0.25`이고 `0.25 × 9k = 2.25k ≥ k`이므로 세 유형 모두 영상 수보다 큰
쿼터를 갖는다. **분기가 필요 없다.**

결과: 영상당 정확히 9질의 · global quota 정확히 일치 · 가능하면 모든 영상에 세 유형
최소 1개 · **사람이 영상을 보고 배정을 조정할 재량 없음**.

### 3-3. `type_unavailable` — swap 규칙과 **종단 조항**

어떤 영상에서 특정 유형의 질의를 만드는 것이 구조적으로 불가능할 수 있다. 그때
결손을 다음 영상에 그냥 더하면 그 영상이 10질의가 되어 `9 queries/video`가 깨진다.

```
swap   영상 A에서 유형 T가 불가능하면, A의 그 slot을 A에서 가능한 유형 T'로 채우고,
       seed 순서상 다음 영상 B의 T' slot 하나를 T로 교환한다.
       → 영상당 9 · global quota · seed determinism이 동시에 보존된다
```

**종단 조항** — 이것이 없으면 순회가 끝나지 않는다.

> **한 바퀴 전체를 순회해도 그 유형을 배치할 수 없으면 그 1건을
> `global_type_deficit`으로 기록한다.** 총 9 queries/video를 유지하기 위해 다른
> 유형으로 재배정하되, **현재 `achieved_k`에서 계산된 Hamilton fractional
> remainder가 큰 유형부터** 선택하고, 동률이면 사전 고정 순서
> `mixed > scene > subtitle`을 쓴다. **`target type quota`와
> `achieved type quota`를 둘 다 보고한다.**

```
target type quota    Hamilton으로 사전 계산한 값
achieved type quota  구조적 type_unavailable 때문에 실제로 생성된 값
차이가 있으면        "quota를 달성했다"고 쓰지 않고 **deviation으로 보고**한다
```

`achieved_k = 35`에서의 fractional remainder 순서는 `자막 0.75 > 장면 0.6875 >
복합 0.5625`다. **이 값도 결과를 보기 전에 계산돼 있다.**

### 3-4. `type_unavailable` 판정 자체의 재량 차단

이 판정은 사람이 영상을 보고 한다. 그래서 escape hatch가 될 수 있다.

```
필수   사유를 기록하고 건수를 보고한다
금지   검색 결과·캡션·모델명·3B/4B 산출물을 보고 판정하는 것
       (CLAUDE.md 절대규칙 3 — 라벨 작성 시 검색 결과 참조 금지)
금지   특정 유형을 만들기 위해 영상을 표본에서 빼는 것
금지   복합형이 −0.2407이었다는 이유로 복합형을 늘리는 것
```

## 4. 선택 절차 — 보충3 §5를 이 검증 단계로 정밀화한다

보충3 §5 step 1("적격 pool을 확정한다")의 **측정 방법**을 바꾸는 것이고, step 2~5의
순서는 그대로다.

```
1   주 표집틀 33편 ID 목록 + metadata를 freeze
2   33편 전량 다운로드 (모델 실행 없음). 파일 sha256 기록
3   FREE 4편 재현 게이트 4/4 통과 확인          ← 실패 시 중단
4   production 함수로 n_segments 실측 → 상태 3분류
5   verified pool 확정 → N · E → achieved_k
6   방송사 쿼터 계산 → 프로그램 계열 비례 배분 (largest remainder)
7   계열 내 seed 20260820 단순무작위 추출
8   선정 목록 + 질의/유형 배정표 + provenance를 커밋      ← 승인 ① 종료
9   caption · embedding · indexing                        ← 승인 ②
```

**금지**(보충3 §5 그대로)

```
제목·썸네일·내용을 보고 개별 영상을 고르거나 빼는 것
"이 영상은 캡션이 잘 붙을 것 같다"는 판단
인덱싱한 뒤 캡션·점수를 보고 영상을 교체하는 것
뽑힌 영상이 마음에 안 들어 seed를 바꾸는 것
```

## 5. provenance — 신규 영상은 기록한다

```
필수   source_url · source_id · file_sha256 · verified_n_segments를 meta에 기록
       **인덱싱 전에 코드에 들어가야 한다** — 사후에 붙일 수 없다
불변   기존 11편은 출처 ID가 없어 ID 단위 중복 대조가 불가능하다.
       `id_level_verified: false`를 유지한다 (보충3 §7)
```

**이 공백을 "확인했다"로 쓰지 않는다.**
