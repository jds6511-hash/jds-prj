남음     후보 풀 크기(12 vs 149~314) · query type 구성 · 도메인 · 영상 길이 · 캡션 길이/오염

## 1. P1 — 후보 풀 크기 가설. **새 라벨·GPU 없이 표본 내에서 조작한다**

두 표본의 가장 큰 비교 가능성 결함은 **질의당 후보 세그먼트가 12개 대 149~314개**라는
것이다. 이것은 교차표본 관측이므로 통제되지 않았다. 그러나 **풀 크기는 기존 캡션
산출물만으로 양방향 조작이 가능하다.**

```
P1-a  dev 축소   각 dev 질의의 후보를 GT를 포함하는 12세그먼트 창으로 제한하고
                 4B·3B 캡션 단독 MRR을 다시 잰다 (캡션 재생성 없음)
P1-b  AI Hub 확대  AI Hub 검색을 영상 내 12개에서 전체 2,328세그먼트 풀로 바꿔
                 4B·3B 캡션 단독 MRR을 다시 잰다 (캡션 재생성 없음)
```

**두 조작 모두 캡션·index·evaluator·질의를 그대로 두고 후보 집합만 바꾼다.**
그래서 모델 효과와 풀 크기 효과가 같은 표본 안에서 교차된다.

### 1-1. 창 선택 규칙 — 결과 보기 전에 고정

```
창 크기        12 (AI Hub와 동일)
창 위치        GT 세그먼트를 포함하도록, seed 고정 난수로 시작점 표집
GT가 여러 개   전부 포함되지 않으면 그 질의는 제외하고 제외 수를 보고한다
seed           20260818, 창 표집 반복 20회 — 창 위치 우연을 평균한다
경계 영상      12세그먼트 미만 영상은 없다(최소 149) — 예외 처리 불필요
```

### 1-2. P1 판정식 — **결과 보기 전에 고정**

| 조건 | 읽는 방식 |
|---|---|
| P1-a에서 Δ가 **양수로 뒤집힌다** | 풀 크기가 부호를 뒤집기에 **충분하다**. 두 표본은 다른 과제를 재고 있었다 |
| P1-a에서 Δ가 **음수로 유지된다** | 풀 크기로는 설명되지 않는다. 남은 후보(type·도메인·길이)로 넘어간다 |
| P1-b에서 Δ가 **음수로 뒤집힌다** | 위와 같은 방향의 독립 증거 |
| P1-a·P1-b가 **서로 반대를 가리킨다** | 판정 보류. 두 조작이 같은 축을 재지 않았다는 뜻이므로 그 이유를 규명한다 |

**"뒤집힘"은 점추정 부호로 판정한다.** dev는 3 cluster이므로 CI를 formal gate로
쓰지 않는다(기존 제약 유지). AI Hub는 194 cluster이므로 P1-b에는 video-cluster CI를
같이 보고한다.

> **P1은 기전 검증이지 채택 판정이 아니다.** dev·AI Hub는 둘 다 소진된 표본이므로
> P1 결과로 캡션 모델을 채택하거나 기각하지 않는다. P1은 **P2를 어떻게 설계할지**를
> 정한다.

### 1-3. P1이 하지 않는 것

- **캡션을 재생성하지 않는다.** 저장된 산출물만 쓴다(`prec3_0818b` FULL · AI Hub 2×2).
- **α·τ를 건드리지 않는다.** 캡션 단독(α=0)만 본다.
- **`results/alpha_search_dev.json`·`eval_test.json`에 쓰지 않는다.**
- **test를 건드리지 않는다.**
- **12 이외의 창 크기를 결과 보고 추가하지 않는다.** 곡선이 필요하다고 판단되면
  별도 문서로 사전등록한다.

## 2. P2 — 새 표본 확증. **P1 결과에 따라 규모가 갈린다**

### 2-1. 표본 출처

**AI Hub 예비분이 0이므로 새 장편 영상 + 새 라벨뿐이다.**

```
1순위   미사용 인덱싱 4편 (baekmansonghee_jirisan · jissi_farm ·
        pland_costco_hosting · softyeon_ceramics)
2순위   신규 영상 인덱싱 (M1~M4) — cluster 수가 부족하면
```

**라벨은 사용자가 쓴다.** 도구는 `scripts/label_contact_sheet.py`(프레임+시각만)와
`scripts/label_intake.py`만 쓰고, **`m5_search`·`m6_evaluate`를 import하지 않는다**
(CLAUDE.md 절대 규칙 3). `docs/probes/frame_human_kit.py`는 쓰지 않는다.

### 2-2. 필요 규모 — 두 추정을 같이 적는다

구분해야 하는 두 점추정이 `+0.031`과 `−0.090`이므로 **목표는 video-cluster CI
half-width ≤ 0.04**다.

| 기준 | 계산 | 필요 cluster |
|---|---|---|
| AI Hub 실측 스케일링 | half-width 0.021 @ 194 cluster, `k = 194·(0.021/0.04)²` | **≈ 53** |
| dev 실측 스케일링 | half-width 0.092 @ 3 cluster, `k = 3·(0.092/0.04)²` | **≈ 16** |

**두 추정이 3배 이상 어긋난다** — 표본 구조(영상 길이·클러스터 내 분산)가 다르기
때문이다. 그래서 규모를 하나로 못 박지 않고 **16~53편 구간으로 등록하고, 실제 값은
P1 이후·표집 전에 별도 문서로 확정한다.** 확정 전에 표집하지 않는다.

> **cluster는 영상이다.** 한 영상에서 질의를 더 뽑아도 cluster는 늘지 않는다.
> 질의당 라벨 비용보다 **영상 편수**가 판정력을 정한다.

### 2-3. 통제할 조건 — parity audit에서 나온 항목

```
필수 기록  effective_model_id · effective_model_revision   ← 이번 조사에서 어느 arm에도
                                                             기록돼 있지 않았다
필수 기록  prompt_sha256 · attn_implementation · dtype ·
           vlm_max_pixels · max_new_tokens · rep_penalty ·
           requested_quantized / effective_quantized / quantization_mismatch
필수 동일  embedder · evaluator commit · seg_len · 후보 풀 정의
필수 층    query type (장면형 · 자막형 · 복합형) — 층별 목표 수를 병합 전 사전등록
필수 보고  질의당 후보 세그먼트 수 분포
```

**층을 반드시 유지한다.** 조사에서 층별 Δ가 `장면형 +0.0132` ~ `복합형 −0.2407`로
갈렸다. 새 표본이 한 층에 치우치면 부호가 재현되지 않아도 그것을 모델 효과로 오독한다.

### 2-4. P2 판정식 — **표집 전에 고정한다**

```
주 지표   캡션 단독(α=0) MRR의 4B − 3B, paired video-cluster bootstrap CI
판정      CI가 0을 배제하고 부호가 양수      → AI Hub 방향 재현
          CI가 0을 배제하고 부호가 음수      → dev 방향 재현
          CI가 0을 포함                      → 이 규모로는 판정 불가. 규모를 적고 멈춘다
부수      층별 Δ를 함께 보고한다 (판정은 전체 Δ로 한다)
금지      α·τ 재탐색으로 부호를 구제하지 않는다
금지      "비유의"를 "차이 없음"으로 쓰지 않는다
```

**두 arm을 같은 하드웨어·같은 commit·같은 코드 경로에서 함께 생성한다**
(CLAUDE.md 후보 검증 규약 4번 — 동시점 대조군).

## 3. 절차와 승인 지점

```
이 문서 커밋
  → P1 분석 코드 · TDD 커밋            (결과 보기 전)
  → P1 실행 (라벨·GPU 불필요)
  → P1 결과 문서
  → [사용자 승인] P2 규모·영상 편수 확정 문서 커밋
  → [사용자 작업] 라벨 작성 (필요하면 신규 영상 M1~M4 인덱싱 — GPU 배치 승인 별건)
  → P2 실행 · 한 번만 평가
  → P2 결과 문서
```

**승인이 필요한 지점 2곳**

1. **P2 규모 확정** — 16~53편 중 어디로 갈지는 라벨 노동량을 정하므로 사용자 결정이다.
2. **신규 영상 인덱싱** — 장시간 GPU 배치이므로 PLAN → CANARY → FULL 3단 승인이다.

**P1은 승인 없이 진행해도 되는 범위다** — 저장된 산출물만 읽고, 새 캡션·새 라벨·GPU가
없고, 확정 파일에 쓰지 않는다.

## 4. 이 문서가 하지 않는 것

- **어느 표본이 맞는지 미리 정하지 않는다.**
- **캡션 모델을 채택·기각하지 않는다.** P2가 부호를 확정해도 남은 장벽(I1 detector
  재설계)은 별건이다.
- **test를 건드리지 않는다.** P1·P2 모두 dev·AI Hub·신규 표본만이다.
- **P1 결과를 보고 P2 판정식을 고치지 않는다.** P2에서 정하는 것은 **규모**뿐이다.
