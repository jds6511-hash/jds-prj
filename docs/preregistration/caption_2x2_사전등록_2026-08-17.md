# caption model×prompt 2×2 contemporaneous batch — 사전 등록 (2026-08-17)

**작성 시점에 이 실험의 수치는 존재하지 않는다.** 신규 arm(`3B/P1`, `4B/P0`)은 아직
생성되지 않았고, 재생성분(`3B/P0`, `4B/P1`)도 아직 돌지 않았다. 그래서 지금 박는다.

**이 문서는 커밋 이후 고치지 않는다.** 임계를 낮추거나 새 지표를 추가하지 않는다.

---

## 0. 왜 하는가

현재 캡션 판정의 핵심 수치 `+0.0377`은 **`3B/P0` vs `4B/P1`** 비교다. 모델과
프롬프트가 함께 바뀌어 **configuration effect로만 읽을 수 있다**(감사_2026-08-17 §1-2,
재분석_전달분해_2026-08-17 §2). 2026-08-17 재분석에서 CI 유효성은 해소됐지만
**귀속은 남았다.**

이번 사이클이 묻는 것은 두 가지다.

1. **귀속** — `+0.0377`의 얼마가 모델이고 얼마가 프롬프트인가.
2. **채택성** — **다음에 실제로 채택 가능한 캡션 configuration이 무엇인가.**

특히 `4B/P0`가 중요하다. P0에는 **화면 글자 전사 금지 문구**가 있고 P1에는 없다.
`4B/P0`가 `4B/P1`과 비슷한 retrieval을 내면서 오염이 적으면 **채택 후보는 `4B/P1`이
아니라 `4B/P0`**다. 반대로 `4B/P0`가 떨어지면, 성능 이득이 scene text 허용과 얽혀
있어 **I1 검출기 재설계 없이는 채택할 수 없다**는 결론이 된다.

**이것은 새 실험 사이클이다.** 8회차 HOLD 판정을 고치거나 test를 여는 근거로
소급하지 않는다. 8회차는 I1/A2 실패로 닫혔고 test 미접촉으로 고정됐다.

## 1. 설계 — 2×2, 전 arm 동시 생성

| | **P0** (배포 프롬프트, 글자 전사 금지 있음) | **P1** (dev 격자 승자, 금지 문구 없음) |
|---|---|---|
| **Qwen2.5-VL-3B** | `3B/P0` | `3B/P1` |
| **Qwen3-VL-4B** | `4B/P0` | `4B/P1` |

**정밀도는 전 arm bf16으로 고정한다.** 귀속 질문은 model×prompt 구조이므로 양자화를
섞지 않는다. 배포가 3B **4bit**라는 사실은 별개의 운영 판단이고, 기존 4bit 대조는
**보조로만 병기**한다(§5-3).

### 1-1. 네 arm을 **전부 이 배치에서 새로 생성한다**

기존 `3B/P0`(2026-08-11)·`4B/P1`(2026-08-10)을 재사용하면 2×2가 배치를 가로지른다.
그때 prompt 효과 두 개가 **서로 반대 방향으로** 배치 효과를 받아 interaction에
**2배로 실린다**.

```
prompt 효과 at 3B = 3B/P1(신규) − 3B/P0(구)    ← 신규 − 구
prompt 효과 at 4B = 4B/P1(구)   − 4B/P0(신규)  ← 구 − 신규
```

실측 run-to-run 발산은 dev 655구간에서 8건(1.2%)·캡션 단독 MRR 0.0124였다. 재려는
대비가 +0.02~0.04라 **같은 자릿수다.** 규약 4항(동시점 대조군)을 그대로 적용한다.

> **기존 `3B/P0`와 `4B/P1` 산출물은 재사용하지 않는다. 같은 arm의 과거 산출물은
> run-to-run divergence를 측정하는 부수 분석에만 사용한다. 주분석은 동일 시점·동일
> 코드·동일 라이브러리·동일 하드웨어·동일 evaluation path에서 생성한 4 arm으로
> 제한한다.**

**기존 산출물은 지우지 않는다.** 같은 arm의 구·신 비교로 **run-to-run 발산을
n=1,086에서 처음 정량화**한다(§5-4, 보조). 주효과 추정에는 섞지 않는다.

### 1-1-a. 주분석에 쓰는 대비는 전부 신규 4 arm 내부에서만 계산한다

```
prompt 효과 at 3B   = new(3B/P1) − new(3B/P0)
prompt 효과 at 4B   = new(4B/P1) − new(4B/P0)
model 효과 under P0 = new(4B/P0) − new(3B/P0)
model 효과 under P1 = new(4B/P1) − new(3B/P1)
interaction         = [new(4B/P1) − new(3B/P1)] − [new(4B/P0) − new(3B/P0)]
```

기존 산출물이 들어가는 계산은 **§5-3(배포 4bit 보조)과 §5-4(run-to-run)뿐**이고,
둘 다 판정에 쓰지 않는다.

### 1-2. 표본

AI Hub **194영상 · 2,328구간 · 1,086질의**(제3자 작성). 기존 확증과 같은 표본이다.

> **이 표본은 이미 `4B/P1` vs `3B/P0` 확증에 1회 사용됐다.** 재사용이므로 이번
> 결과는 **확증이 아니라 추정·선택**으로만 보고한다. 새 확증에는 새 표본이 필요하다.
> 이 사실을 결과 문서와 자문 문서에 명시한다.

### 1-3. 내부 반복 점검 — A/B 절반 분할

표본 재사용을 완화하기 위해, **결과를 보기 전에** 194영상을 `video_id` 정렬 후
`sha256(video_id)` 짝수/홀수로 A/B 절반에 배정한다(고정 규칙, 재현 가능).

- **선택은 A-half에서** 한다(§4의 선택 규칙).
- 선택된 configuration의 `vs 3B/P0` 대비를 **B-half에서 보고**한다.
- **B-half는 독립 확증이 아니다** — 같은 194영상 코퍼스의 분할이다. **내부 반복
  점검**으로만 쓴다. 부호가 갈리면 그 사실을 그대로 적는다.

## 2. 지표

**주지표: 캡션 단독(α=0.0) MRR.** 기존 사이클과 동일. 후보가 바꾸는 채널만 본다.

**보조지표(판정에 쓰지 않음):** 융합 α=0.5 MRR, hit@1, hit@5, 도메인별 분해,
캡션 길이 평균.

**α는 `results/alpha_search_dev.json`의 `alpha_star`(=0.5)를 쓴다.** 이 실험에서
α를 재탐색하지 않는다.

## 3. 사전 등록 대비 — 5개, 다중성 보정 명시

전부 캡션 단독 MRR 기준. **결과를 보고 대비를 추가하지 않는다.**

| # | 이름 | 계산 |
|---|---|---|
| C1 | **prompt 효과 at 3B** | `3B/P1 − 3B/P0` |
| C2 | **prompt 효과 at 4B** | `4B/P1 − 4B/P0` |
| C3 | **model 효과 under P0** | `4B/P0 − 3B/P0` |
| C4 | **model 효과 under P1** | `4B/P1 − 3B/P1` |
| C5 | **interaction** | `(4B/P1 − 3B/P1) − (4B/P0 − 3B/P0)` |

**다중성:** 5개 대비에 **Benjamini-Hochberg FDR q=0.05**를 적용한다. 보정 전후를
모두 보고하고, **보정 후 기준으로 서술한다.** 이번 사이클은 선택·추정이므로
어느 대비도 "확증"이라 쓰지 않는다.

**부트스트랩:** `seed=42`, `B=2000`. 재표집 단위 **세 가지를 전부 산출한다** —
질의 단위 / video-cluster / video-macro. 셋의 부호가 갈리면 그대로 적는다.
ICC(1)과 설계효과도 함께 낸다.

**per_query 저장은 필수다.** arm별 질의 순위·RR·hit@1·`video_id`·도메인을 전량
저장한다. 이 항목이 빠진 결과 파일은 무효로 본다(감사_2026-08-17 §3의 재발 방지).

## 4. 판정 — 세 질문, 결과 보기 전에 규칙을 박는다

### 4-1. 귀속 (질문 1)

| 관측 | 결론 |
|---|---|
| C4가 0을 배제하고 C1이 0을 포함 | `+0.0377`은 **주로 모델 효과** |
| C1이 0을 배제하고 C4가 0을 포함 | `+0.0377`은 **주로 프롬프트 효과** |
| 둘 다 0을 배제 | **둘 다 기여.** 각 크기를 병기 |
| 둘 다 0을 포함 | **분리 실패.** 표본이 부족하다고 적고 `+0.0377`은 configuration effect로 유지 |
| C5가 0을 배제 | **상호작용 있음.** 모델 효과를 프롬프트와 분리해 서술하지 않는다 |

### 4-2. 안정성 (질문 2) — I1

arm별로 전량 판정해 표로 낸다. **원인을 귀속하지 않는다.**

| 항목 | 측정 |
|---|---|
| I1-a | `common.is_corrupted_caption` 적중 건수 (arm별) |
| I1-b | CJK 문자 포함 캡션 건수 (검출기와 별개로 원자료) |
| I1-c | 한국어 외 언어 이탈로 보이는 건 (I1-a 중 CJK 아닌 것) |

**P0에는 글자 전사 금지 문구가 있다.** `4B/P0`의 I1-a가 `4B/P1`보다 낮으면
"프롬프트로 완화 가능"이라 쓸 수 있다. **프레임 실물 검증은 이 사이클에서 하지
않으므로, scene text인지 언어 이탈인지는 판정하지 않는다**(잠정으로 적는다).

### 4-3. 채택성 (질문 3) — 이 사이클에서 채택을 결정하지 않는다

**어떤 결과가 나와도 이 사이클은 배포를 바꾸지 않고 test를 열지 않는다.**
산출물은 "다음 test 재평가를 요청할 근거가 생겼는가"에 대한 입력일 뿐이다.

**다음 사이클로 넘길 후보의 조건 (전부 충족):**

| # | 조건 |
|---|---|
| A1 | 캡션 단독 대비가 **BH 보정 후에도** 0을 배제 |
| A2 | 세 재표집 단위에서 **부호가 일치** |
| A3 | 융합 α=0.5 점추정이 **양수** (유의는 요구하지 않음) |
| A4 | I1-a가 **`3B/P0`(현행) 이하** — 오염을 늘리면서 채택하지 않는다 |
| A5 | A-half 선택 결과가 **B-half에서 부호 유지** |

**하나라도 실패하면 후보로 올리지 않는다.** "거의 통과"는 없다.

## 6. 실행 규약 — PLAN → CANARY → FULL

`.claude/skills/gpu-batch` · CLAUDE.md 실무 규칙을 따른다. **git에 등록된 스크립트만
쓴다.** 결과 생성 전에 이 문서와 실행 스크립트를 커밋한다.

### 6-1. PLAN (GPU 0)

기존 캡션 파일 경로·신규 산출물 경로·provenance 저장 위치·**기존 인덱스 불변 조건**을
확인하고 기록한다. `git status --porcelain`이 비어 있지 않으면 실행하지 않는다.

### 6-2. CANARY — **4 arm 전부**, 소수 프레임

**전부 통과해야 FULL로 간다.** 신규 2 arm만이 아니라 **네 arm 모두** 돌린다 —
주분석이 4 arm 동시 생성이므로 canary도 같은 경로여야 한다.

| # | 확인 |
|---|---|
| K1 | 네 arm 출력이 전부 **한국어** 문장인가 |
| K2 | **arm별 프롬프트 SHA256이 기대대로 다른가** (P0 2개는 동일, P1 2개는 동일, P0≠P1) |
| K3 | **P0 프롬프트에 "그 글자를 그대로 옮겨 적지 말고"가 실제로 들어 있는가.** P1에는 **없는가** — 문자열로 직접 확인 |
| K4 | provenance에 `entrypoint`·**3B/4B model id와 revision**·dtype·양자화·생성 kwargs가 **실효값**으로 기록됐는가 |
| K5 | `is_corrupted_caption` 결과가 **arm별로 저장**되는가 |
| K6 | **per_query가 저장**되는가 (arm별, `video_id` 포함) |
| K7 | 저장 스키마가 기존 평가 경로(`VideoIndex`·`evaluate`)와 **호환**되는가 |
| K8 | **기존 `work/`·`work_aihub/` 인덱스를 덮지 않는가** — 재임베딩은 메모리에서만 |
| K9 | **처리량 실측** — arm별 초/구간. FULL 소요를 여기서 산출한다 |

**canary 산출물은 별도 파일명(`_canary_`)으로 쓰고 보고하지 않는다.**

### 6-3. FULL

**canary 결과와 예상 소요를 사용자에게 보고하고 승인을 받은 뒤 실행한다.**
진행 판정은 "프로세스가 사라졌는가"가 아니라 **완료 마커 + validator PASS**로 한다.
콘솔 수치는 cp949로 깨지므로 **최종 수치는 UTF-8 JSON에서만** 읽는다.

## 7. 이 문서가 금지하는 것

- 결과를 보고 대비·지표·표본을 바꾸는 것
- BH 보정 없이 5개 대비 중 유리한 것만 인용하는 것
- 이 사이클 결과로 **배포를 바꾸거나 test를 여는 것**
- 8회차 HOLD 판정을 이 결과로 소급 수정하는 것
- 기존 `3B/P0`·`4B/P1` 산출물을 **삭제·덮어쓰는 것**
- 기존 산출물을 **주분석 대비에 넣는 것** (§1-1-a 밖의 계산)
- 이 실험을 **test 개방 실험으로 취급하는 것** — AI Hub/probe 실험으로만 남는다
- `results/` 아래 확정 산출물(`alpha_search_dev.json`·`eval_test.json`)을 건드리는 것
- 본 `config.yaml`·본 인덱스(`work/`)를 건드리는 것
