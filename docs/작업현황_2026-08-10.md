### 2-c. 왜 이득이 사라지는가 — 회계

```
후보의 bf16 우위          +0.0913   (서버 대 서버)
양자화 손실               −0.0604   (6GB에 올리려면 4bit 강제)
현행이 더 받은 환경 이득   −0.0429   (3B +0.0926 vs qwen3vl +0.0497)
                          ─────────
노트북에서의 실제 차이     −0.0120   ← 실측값과 일치
```

앞의 −0.0604는 **압축의 대가**이고, 뒤의 −0.0429는 **기계가 바뀌면서 잃는 것**이다.
성격이 다르다. 뒤쪽은 아직 검증되지 않은 전제다(§7).

**양자화가 공짜라는 전제가 깨졌다.** 2026-08-07에 Qwen2.5-VL-3B로 잰 Δ+0.0024를
근거로 "4bit는 손해 없다"고 했는데, Qwen3-VL-4B에서는 **−0.0604**(p=0.068)다.
유의하지 않지만 "공짜"라고 할 근거도 없다. 오염 캡션도 늘었다(bf16 2건 → 서버
4bit 5건 → 노트북 4bit 11건).

## 6. M9 판정자 — coverage 지표를 신뢰할 수 없다

새 생성 없이 8/6 리포트(396문장)와 segments만 재배열해 답을 아는 문항을 만들었다.

| 과제 | 양성 정답률 | 음성 정답률 | 예비율 | 판정 |
|---|---|---|---|---|
| groundedness | 0.817 | 1.000 | 0.408 | **통과** |
| coverage | **0.550** | 0.983 | 0.283 | **탈락** |

coverage 판정자는 리포트가 실제로 인용한 세그먼트의 45%를 "커버 안 됐다"고 답한다.
음성이 0.983이므로 아무거나 covered라 하는 게 아니라 **덜 잡는 방향**이다.

**단서.** 양성 대조가 "리포트가 `cites`에 넣었는가"라 "내용이 담겼는가"의 대리
지표다. M8이 인용을 느슨하게 달았다면 양성 대조 자체가 오염이다. 현재 설계로는
둘을 못 가른다. 어느 쪽이든 coverage 해석에 문제가 된다는 결론은 같다.

**영향.** M9는 이미 test에서 두 번 돌았다(공식 평가 7회 중 리포트 2회). 그 coverage
수치는 하한이고 하한의 폭이 설계 가정보다 크다(코드 주석의 합성 검증셋 재현 0.80
vs 실측 0.550). **재평가와 무관하게 문서에 한계를 명시해야 한다.**

`judge_model`의 "다른 패밀리 1순위는 서버 GPU 확정 대기"라는 잠정 조치도 낡았다 —
서버는 2026-08-06에 확보됐다. **판정자 교체가 별도 안건으로 열렸다.**

## 7. 남은 미결 하나 — 생성 환경 효과

### 7-a. 지금까지 배제된 것

| 가설 | 결과 |
|---|---|
| 프레임 파일이 다르다 | **배제** — 198장 sha 동일 |
| 전처리·토큰화·리사이즈가 다르다 | **배제** — `pixel_values`·`grid_thw` 비트 단위 동일 |
| config가 다르다 | **배제** — `llm_4bit`만 다르고 캡션 무관 |
| 실행 간 무작위성 | **배제** — 같은 환경에서 98.0% 재현 |
| attention 커널 | **배제** — sdpa 27.5 / eager 13.3 / sdpa+math 30.8%, 최고 +3.3%p |

남은 후보는 **라이브러리 버전**(torch 2.12/2.13, transformers 5.9/5.14)과
**GPU 아키텍처**(Ampere sm_86 vs Ada sm_89)다. 서버 torch를 바꾸면 기존 23 arm과
비교가 불가능해지므로 건드리지 않는다.

부수 확인: 커널을 바꾸면 캡션의 14%가 뒤집힌다. **생성이 미세 수치차에 민감하다**는
것이 실측됐다.

### 7-b. 왜 이게 전부를 규정하는가

```
환경 효과 0.09 (dev 96건, 미검증)
   → 노트북에서 생성해야 한다
      → 6GB 제약
         → 후보군이 4B 이하로 잘리고 4bit가 강제된다
            → 후보의 이득이 소멸한다
```

맨 위가 **아직 검증 안 된 전제**인데 아래를 전부 규정한다. 그리고 CLAUDE.md 판단
기준("정확도 손실은 되돌릴 수 없다")의 취지와도 어긋난다 — 지금은 하드웨어가
정확도 후보를 자르고 있다.

### 7-c. 지금 돌고 있는 검증

AI Hub A 절반(97영상·562질의)에서 **같은 모델·같은 4bit·같은 프롬프트**로
노트북 캡션을 만들어 저장된 서버 캡션과 쌍체 비교한다. n=562면 MDE ±0.036이라
재려는 0.09는 여유 있게 검출된다.

**판정 규칙(결과 전 확정):** CI가 0을 배제하고 부호가 dev와 같으면 재현됨.
0을 포함하면 재현 실패 — 노트북 제약을 후보 선정 기준으로 쓸 근거가 사라진다.

### 7-d. 편향 감사

**편향 없음이 확인된 것**: 프롬프트 문자열(sha256 동일), 프레임 파일(서버에서 그대로
전송해 같은 파일), 전처리(비트 단위 동일), 생성 설정(4bit·max_new 128·rep_penalty
1.1·max_pixels 602112), **임베딩**(두 arm 모두 노트북에서 KURE로 — 환경 공통),
평가 코드·질의·라벨, A/B 분할(시드 42, 결과 전 고정).

**노트북에 유리한 편향 — 실재한다.** `caption_prompt`(P0)·`vlm_rep_penalty`·
`vlm_max_pixels`를 고를 때 본 것이 전부 노트북 생성 캡션이었다. 방증: 튜닝된
조합일수록 환경 이득이 크다(3B+P0 +0.093 vs qwen3vl+P1 +0.050). 다만 둘 다 점추정,
차이는 노이즈 범위.

반증도 있다. 표면 품질은 거의 같다 — 길이 130.5 vs 127.1, 오염 0 vs 1, 문장
미완결 13.6% vs 15.0%. **노트북 캡션이 눈에 띄게 잘 만들어진 게 아니다.**

**해석 규칙:** 재현되면 "환경 효과 + 설정 튜닝 편향"의 합이므로 순수 환경 효과는
그보다 작다. **재현 안 되면 노트북에 유리한 편향이 있는데도 안 나온 것이라
단순 음성보다 강한 증거다.**

### 7-e. 사전 등록한 후속 설계 (1차 결과 보기 전 확정)

편향을 분리하려면 **튜닝 안 된 조합(qwen3vl_4b + P1)**을 같은 A 절반에서 노트북
생성해 비교한다.

- 튜닝 안 된 조합의 환경 효과가 튜닝된 조합의 **60% 이상** → 환경 효과가 주다
- **30% 이하** → 설정 튜닝 편향이 주다
- 사이 → 혼재. 순수 환경 효과를 하한으로 보고

비용 노트북 GPU 약 15시간. **1차가 0 근처면 돌릴 필요 없다**(편향이 유리한데도
효과가 없었다는 뜻이므로).

## 8. 결과에 따른 분기 (내일 판단)

| 1차 결과 | 확률(내 추정) | 다음 |
|---|---|---|
| 재현됨 | 약 40% | 노트북 제약 확정. **"최고 시스템이 재현 불가능한 기계에 의존한다"는 문제를 발표에서 다뤄야 한다.** 편향 분리(§7-e) 착수 |
| 0 근처 | 약 50% | **서버 통일 + bf16 채택 권고.** 6GB 제약이 풀려 8B·14B·32B가 정상 후보가 되고, 재현성·속도(9.5배)를 얻는다 |
| 역전 | 약 10% | 서버가 낫다는 뜻이라 결론은 같고 이유를 따로 규명 |

**서버 통일 시 대가**: M3 재생성(7편) → m4 → α 재탐색 → τ 재캘리브레이션 →
**test 재평가(접촉 8회차, 승인 필요)**. 성능은 본전(0.5522 vs 0.5535)이지만
재현성·확장성을 얻는 거래다.

## 10. 오늘 낸 실수 (재발 방지)

- **파일 미동기화.** `caption_model_sweep.py`에 8B를 커밋하고 **서버 scp를 빠뜨려**
  6개 arm이 `KeyError`로 즉사했다. 스크립트 수정은 **커밋과 동기화를 한 동작으로**
  묶어야 한다.
- **실행 순서.** AI Hub 2단계가 "dev 상위 3개"를 뽑는데 8B가 dev에 없는 상태로
  시작했다. 정지 후 8B dev → 2단계로 바로잡았다.
- **stdout 이중 래핑.** `aihub_stage2`가 stdout을 감싸는 모듈 둘을 임포트해
  첫 래퍼가 GC되며 공유 버퍼를 닫았다. **무인 실행이었으면 즉사했다.**
- **"상위 K개 모델"을 arm 기준으로 셈.** `qwen3vl_4b`와 `qwen3vl_4b_q4`가 슬롯을
  둘 차지했다. HF id 기준 중복 제거로 수정.
- **q4 플래그 무시.** `qwen3vl` 로더가 `dtype`을 하드코딩해 4bit arm이 조용히
  bf16으로 돌았다. VRAM 11.4GB로 발각.
- **추정 근거 부실 — 세 번 연속.** 노트북 프레임당 시간을 10장으로 재서 3.84초로
  추정했으나 실측 32초(dev), 52초(AI Hub)다. **대표성 없는 표본으로 외삽하지 마라.**
  원인은 프레임 크기가 아니라 **출력 길이**였다(3B+P0 135자 vs qwen3vl+P1 95자).
  비전 토큰은 양쪽 다 720개로 동일했다.
- **영상마다 모델 재적재.** 환경 검증이 97회 재적재하고 있었다. 1회 적재로 수정.
- **스모크의 `sec_per_frame`이 적재 시간 포함.** 2프레임에 나눠 넣어 크게 부풀린다.
  배치 소요 추정에 쓰면 안 된다.
