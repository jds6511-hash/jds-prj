### 1-2. 32B — "졌다"가 아니라 "판정 불가"

dev 격차 +0.080인데 그 표본의 검출 한계가 ±0.086이다. **차이가 있어도 없어도 같은
수치가 나온다.** 생성 비용은 4B의 3.5배(97.1분 vs 27.7분).

논문 표기: `promising but unresolved due to insufficient power`

재실험 조건도 미리 박아뒀다 — 독립 표본에서 **4B 대비**(3B 대비가 아니다) +0.03 이상의
추가 개선 근거가 생길 때만 재개한다.

### 1-3. M8 리포트 — 병목은 map이 아니라 reduce

구간별 요약(map)은 294문장을 냈는데 통합(reduce)에서 150문장으로 잘렸다. 원인 사슬을
끝까지 팠다.

> 한 청크가 1,506자를 한 줄에 씀 → reduce가 같은 말 반복 → 반복 억제 장치 발동 →
> **모델이 중국어로 이탈** → 커버리지 30.7%

**대응.** 자유 형식 reduce를 없애고, map이 **사건 레코드(JSON)**를 내면 병합·중복 제거를
파이썬이 한다. **판정을 생성 모델에게 맡기지 않는다** — 검증자가 모델이면 검증자도 같이
무너진다.

구현은 끝났지만 **8회차에는 넣지 않는다.** 8회차는 이미 다섯 가지를 동시에 바꾼다
(캡션 모델·정밀도·기계·표본·판정자). 여기에 M8 구조까지 얹으면 결과가 좋아져도 나빠져도
**원인 귀속이 불가능하다.**

## 3. test 8회차 — 성능이 아니라 무결성으로 연다

test 39건은 지금까지 공식 평가 7회(검색 5 + 리포트 2), **튜닝 목적 접촉 0회**다.
한 번 보면 되돌릴 수 없으므로 여는 문턱을 결과 보기 **전에** 커밋했다
(`docs/preregistration/8회차_개방게이트_2026-08-16.md`).

| 게이트 | 기준 | 성격 |
|---|---|---|
| **P0** | 자막 해시 전편 불변 | 하드 |
| **I1~I4** | 오염 캡션 0 · 해시 10/10 · 벡터 형상 · 공백 영상 0 | 하드 |
| **A1** | α 동률 집합 ≥ 2개 | 하드 |
| **A2** | α\* 이웃의 MRR 하락 ≤ 0.06 | 하드 |
| **T1·T2** | 오배제 0/96 · 무관 감지 ≥ 11/20 | 하드 |
| **T3** | 판정 여유 | 기록 의무 |

**왜 성능을 기준으로 안 쓰나.** dev 96·영상 3편의 검출 한계가 ±0.086이다. 그 표본에서
"좋아졌으니 열자"는 근거가 될 수 없다.

**α는 최적점 위치가 아니라 곡선의 평탄성으로 본다.** 캡션이 바뀌었으니 α\*가 움직이는
것은 자연스럽다. 위험한 것은 최적이 한 점에 뾰족하게 몰리는 경우 — 그건 dev 96의 우연에
끌려간 것이고 test에서 재현되지 않는다.

**게이트를 통과 못 했다고 임계를 낮추지 않는다.**

### 3-1. 판정 결과 — **HOLD** (2026-08-17 15:43)

| | 기준 | 결과 | |
|---|---|---|---|
| **P0** 자막 불변 | 10/10 | **10/10** | PASS |
| **I1** 오염 캡션 | 0건 | **5건** | **FAIL** |
| I2·I3·I4 | 10/10 · 10/10 · 0편 | 전부 충족 | PASS |
| **A1** tie_set | ≥2 | **4** | PASS |
| **A2** 최대 이웃 하락 | ≤0.06 | **0.0665** | **FAIL** |
| T1·T2 | 0/96 · ≥11/20 | 0/96 · 12/20 | PASS |
| T3 여유 | 기록 | 0.0082 | 기록 |

**test를 열지 않았다.** 임계도 손대지 않았고 새 기준도 추가하지 않았다.

**I1 실패가 뜻밖의 발견을 냈다.** 오염 5건 중 3건은 진짜 언어 이탈이지만, 2건은
화면에 실제로 있는 문자를 모델이 읽은 것으로 보인다 — 중국 쇼핑몰 상점명과
비석 각자 한자다(**프레임 실물은 아직 확인 못 했다 — 잠정 판단**).

**다만 원인 귀속은 불가능하다.** 이번 재생성은 모델만 바꾼 게 아니라 **프롬프트도
함께 바뀌었고**, 배포 프롬프트에 있던 **"화면 글자를 그대로 옮겨 적지 마라"가 새
프롬프트에는 없다.** 따라서 "4B가 더 잘 읽어서 걸렸다"고 말할 수 없다.

> **정확한 문장:** ① 검출기가 scene text와 language drift를 구분하지 못하고,
> ② 모델과 프롬프트가 함께 바뀌어 원인 귀속도 불가능하다.

**다음 프로토콜에서 detector와 prompt를 같이 재설계해야 한다는 발견**이지,
이번 게이트를 통과시킬 근거가 아니다. 소급 적용하지 않는다.

**A2는 0.0065 차이지만 그대로 FAIL이다.** "거의 통과"로 취급하면 사전등록이 무의미해진다.
α\*는 0.5에서 안 움직였고 곡선도 단봉이라 완전히 무너진 것은 아니다 — 봉우리 오른쪽
어깨가 0.0504에서 0.0665로 가팔라졌다.

## 4. 사고 보고 — 3건, 전부 실행 절차 문제

| 사고 | 원인 | 손실 | 대응 |
|---|---|---|---|
| 유령 프로세스 대기 | 대기 조건이 **자기 런처 셸**까지 매칭 | GPU 8.5시간 유휴 | 패턴을 실행 파일 경로로 앵커 |
| 배타 플래그 조합 | `--captions-only --force` 동시 지정 | 배치 즉시 종료 | 코드가 이미 차단 중 |
| 편집본 ≠ 실행본 | `/tmp` 경로가 도구마다 다르게 해석됨 | 보강 단계 누락 | 임시 경로 폐기 |
| (추가) 대기 스크립트 거짓 실패 | `grep -c`의 exit 1을 줄 위치 파싱이 오독 | 없음 | 라벨 파싱 + 연속 관측 |

**세 번째가 가장 위험한 유형이다** — "고쳤다고 생각한 코드"와 "서버가 실행한 코드"가
달랐다. 하나도 연구 결과를 오염시키지는 않았지만, 셋 다 정식 실험 중이었으면 오염됐다.

**구조적 대응.** 연구 규율을 사람이 지키는 주의사항이 아니라 **코드 검사**로 옮긴다.
"자막이 바뀌면 안 된다"를 문서에 적는 대신, 재캡셔닝 전후 자막 해시를 비교해 불일치면
즉시 중단하는 스크립트를 만들었다(위 P0). 정식 실험은 git에 등록된 스크립트로만 돌리고,
장시간 배치는 계획 → 소규모 시험 → 본 실행 순서로 나눈다.

## 5. 상의드릴 것

**5-1. 평가 규모.** 현재 dev 3편·96질의로는 ±0.086보다 작은 개선을 **검출 자체가
불가능**하다. 실제 개선폭이 +0.03~0.04대라 지금 규모로는 계속 "비유의"만 나온다.
영상을 8~12편으로 늘리는 것이 유일한 해법인데, 라벨링 인력·일정이 필요하다.

**5-2. 리포트 평가 지표 교체.** 현행 `segment coverage`(몇 %의 구간이 인용됐나)는
**번호만 많이 달면 올라간다.** 실제로 새 구조가 커버 100%를 찍으면서 인용당 서술량은
6.2자였다. 사건 목록 기준(사건 재현율·근거성·중복도)으로 바꾸려 하는데, **사람이 정답
사건 목록을 만들어야 한다.** 4편 시범 → 1편은 2인 이중 작성으로 일치도 측정 계획.

**5-3. 8회차 개방 판정.** 배치가 끝나면 위 게이트 수치가 나온다. 전부 통과하면 test를
열고, 하나라도 실패하면 보류하고 원인을 먼저 규명한다. **판정 자체는 사전 등록한 규칙이
하므로 재량이 들어갈 자리는 없다.**
