# 8회차 개방 게이트 — 추가 사전 등록 (2026-08-16 23:5x)

**작성 시점에 새 α·τ 수치는 존재하지 않는다.** 배치는 1단계(캡션 재생성 10편)를
돌고 있고, α 재탐색(3단계)·τ 재캘리브레이션(4단계)은 아직 시작하지도 않았다.
그래서 지금 이 기준을 박는다.

---

## 0. 이 문서의 위치

`docs/test_재평가_프로토콜_2026-08-13.md`는 **고치지 않는다.** 그 문서는
"커밋 이후 고치지 않는다"로 닫혀 있다.

이 문서는 그 위에 **조건을 더 거는** 부록이다. 프로토콜을 완화하지 않으며,
8회차를 여는 문턱만 높인다.

**왜 더 거는가.** 원 프로토콜은 "무엇을 바꾸고 무엇으로 판정하는가"는 고정했지만
**"어떤 상태일 때 test를 열어도 되는가"** 는 명시하지 않았다. test 접촉은 되돌릴 수
없으므로 그 문턱이 필요하다. 2026-08-16 검토에서 지적된 항목이다.

**개방 판단은 성능이 아니라 무결성으로 한다.** dev에서 몇 점 올랐는지는 개방 근거가
아니다 — dev 검출 한계가 ±0.086이라 그 수치로는 아무것도 못 말한다.

## 1. 개방 게이트 (전부 통과해야 5단계로 간다)

### 1-1. 인덱스 무결성 — 하드 게이트

| # | 기준 |
|---|---|
| I1 | 오염 캡션 잔존 **0건** (`common.is_corrupted_caption` 전수) |
| I2 | `text_hash` **10/10 일치** (meta.json ↔ segments.json) |
| I3 | emb shape 전편 `(n_segments, 1024) × 2` |
| I4 | 캡션 전량 공백 영상 **0편** |

하나라도 실패하면 **중단하고 백업에서 되돌린다**. 백업은 재캡셔닝 전에 떠 뒀다
(`/ssd/<SERVER_USER>/backup_pre_8th_*`).

### 1-2. α 곡선 — 최적점 위치가 아니라 **주변 평탄성**

캡션 모델이 바뀌었으니 α\*가 0.5에서 움직이는 것은 자연스럽다. **움직였다는 사실
자체는 게이트가 아니다.** 위험한 것은 최적이 한 점에 날카롭게 몰리는 경우다 —
그러면 dev 96의 우연에 α가 끌려간 것이고, test에서 재현되지 않는다.

| # | 기준 | 현행 값 |
|---|---|---|
| **A1** | `len(tie_set) ≥ 2` | **3** (`[0.2, 0.4, 0.5]`) |
| **A2** | α\* 양 이웃(±0.1)의 MRR 하락 ≤ **0.06** | 최대 **0.0476** |

`tie_set`은 쌍체 부트스트랩 CI가 0을 포함하는 α들이다. 곡선이 한 점에 몰리면
1로 줄어든다 — 이미 있는 기전을 그대로 쓴다.

**두 기준 모두 현행 확정 config가 통과한다.** 현행을 부정하는 문턱을 새로 만들지
않기 위해 현행 값에서 여유를 두고 잡았다.

*현행 dev 곡선(참고): 0.0 .5535 / 0.1 .5737 / 0.2 .6237 / 0.3 .6465 /
**0.4 .6941** / 0.5 .6692 / 0.6 .6188 / 0.7 .5402 / 0.8 .4891 / 0.9 .4417 / 1.0 .4144*

### 1-3. τ — 값의 이동이 아니라 **판정 여유**

| # | 기준 | 현행 값 | 성격 |
|---|---|---|---|
| **T1** | 오배제 **0/96** | 0/96 | 하드 |
| **T2** | 무관 감지 **≥ 11/20** | 14/20 | 하드 |
| **T3** | 여유(유관 최솟값 − τ) | **0.008** | **기록 의무** |

**T3를 하드 게이트로 걸지 않는 이유를 미리 적는다.** τ 격자가 0.01이고 선택 규칙이
"오배제 0을 유지하는 최대 τ"라, 여유는 구조적으로 0~0.01 사이에 갇힌다. 여기에
문턱을 걸면 동전 던지기에 8회차가 막힌다. 대신 **값을 반드시 병기**하고, 0.005
미만이면 "한 건만 움직여도 오배제가 난다"를 한계로 명시한다.

**분리도는 게이트로 쓰지 않는다.** 현행이 이미 **−0.0505**다(무관 최댓값 0.6085가
유관 최솟값 0.558보다 높다 — 두 분포가 겹친다). 양수를 요구하면 현행 config가
탈락한다. 이 겹침은 알려진 한계이며 이번에 해결하려는 문제가 아니다.

### 1-4. 절차 무결성

| # | 기준 |
|---|---|
| P1 | α·τ 재탐색이 **dev에서만** 돌았다 (test 질의 미접촉) |
| P2 | 재탐색 **규칙**이 현행과 동일하다 (tie_set + tiebreak=larger / 오배제 0 유지 최대 τ) |
| P3 | 질의 병합(5단계)이 M6 실행 **직전**에 일어난다 |

## 3. 8회차에 **넣지 않는 것** — M8 새 구조

2026-08-16 결정. 8회차는 이미 다섯 가지를 동시에 바꾼다(캡션 모델·정밀도·기계·
표본·판정자). 여기에 M8 구조까지 얹으면 결과가 좋아져도 나빠져도 **원인 귀속이
불가능하다.**

> **8회차 = 검색·캡션 계열 변경의 마지막 깨끗한 test 평가**
> **새 M8 = 별도 실험 트랙**

M8 예비 실행에서 공학적 게이트(JSON 파싱·파국 실패)를 통과하더라도 **8회차에 넣지
않는다.** 그건 "안 망가진다"는 증거이지 "기존보다 낫다"는 증거가 아니다.
8회차의 M8은 **현행 구조**로 생성한다.

## 4. 32B — 재실험 조건과 채택 조건을 분리한다

한 문장으로 묶으면 "+0.03 나왔으니 3.5배 느린 모델을 써야 한다"가 된다.

> **재실험 조건.** 독립 외부 표본에서 Qwen3-VL-4B 대비 캡션 단독 MRR이 최소
> **+0.03** 개선될 합리적 근거가 생길 때만 32B 평가를 재개한다.

> **채택 조건(별개).** 외부 표본에서 캡션 검색 개선이 확인되고, **그 개선이 최종
> 융합에서도 의미 있는 이득으로 이어질 근거**가 있을 때만 채택한다.

근거: 4B는 외부 표본 캡션 단독 **+0.038 CI[0.013, 0.061]** 로 유의했지만 최종 융합에서는
**+0.019 CI[−0.002, +0.040]** 로 유의하지 않았다. 캡션 단독의 이득은 융합에서 줄어든다.

**현재 상태: 32B 동결.** dev 격차 +0.080이 검출 한계 ±0.086과 거의 같고,
4B 대비 3.5배 느리다(97.1분 vs 27.7분). 추가 GPU 투입을 정당화할 근거가 없다.
표에는 `promising but unresolved due to insufficient power`로 남긴다.
