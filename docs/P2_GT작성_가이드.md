# P2 질의·GT 작성 가이드 (315건)

## 0. 시작하기

```bash
python scripts/p2_gt_labeler.py
```

브라우저에서 `http://127.0.0.1:8788` 을 열면 한 화면에서 다 된다. 종료는 `Ctrl+C`,
작성분은 CSV에 그때그때 저장돼 있다.

```
할 일     질의문 · 시작 시각 · 끝 시각 — 315건
안 할 일   query_id · video_id · query_type은 이미 정해져 있다. 도구가 수정을 거부한다
근거      시트로 후보를 찾고, 경계는 원본 영상으로 확인
검증      python scripts/p2_label_intake.py build   ← 최종 권위는 여기다
```

**절대 규칙 하나**: 캡션·검색 결과를 보지 않는다. 보고 나면 그 GT로는 검색 성능을 잴 수
없다(시스템이 자기 답안을 채점하는 셈이다). 라벨러 UI는 그 경로를 아예 열지 않는다.

## 1. 화면 구성

```
상단      진행률 (137 / 315) · 현재 query_id · 유형 · 영상 id · 구간 수
왼쪽 위    원본 영상 플레이어
왼쪽 중간   시각 지정 버튼 · 시작/끝 입력칸 · 질의문 입력 · 저장
왼쪽 아래   이 영상의 9건 목록 (초록 테두리 = 작성 완료, 파란 배경 = 현재)
오른쪽     컨택트시트 (페이지 넘기기 ◀ ▶). **타일을 클릭하면 영상이 그 시각으로 이동**
```

## 2. 한 건 쓰는 순서 — 입력 6번

```
1  오른쪽 시트를 훑는다 (◀ ▶로 페이지 이동)
2  후보 장면 타일을 클릭            → 영상이 그 구간 시작으로 이동
3  재생/미세 이동으로 시작점을 찾고  → I   (시작 = 현재 위치)
4  끝점을 찾고                      → O   (끝 = 현재 위치)
5  질의문을 타이핑
6  Ctrl+S                           → 저장 후 다음 미완료 질의로 자동 이동
```

시작·끝은 숫자칸에 직접 입력해도 된다.

## 3. 단축키

| 키 | 동작 |
|---|---|
| `I` / `O` | 현재 재생 위치를 시작 / 끝으로 지정 |
| `J` / `L` | −1초 / +1초 |
| `,` / `.` | −0.1초 / +0.1초 |
| `←` / `→` | −5초 / +5초 |
| `P` | 지정한 시작 시각부터 재생 (경계 확인용) |
| `Space` | 재생 / 일시정지 |
| `Ctrl+S` | 저장하고 다음 질의 |
| `Alt+←` / `Alt+→` | 이전 / 다음 질의 (순서는 동결돼 있고 바뀌지 않는다) |

입력칸에 커서가 있으면 글자 단축키는 동작하지 않는다(오타 방지). 화면 빈 곳을 한 번
클릭하면 다시 먹는다.

## 4. 타일 클릭은 seek 도움일 뿐이다

**타일을 눌러도 GT 경계가 자동으로 입력되지 않는다.** 일부러 그렇게 만들었다. 대표
프레임은 5초 구간의 **한 시점**이라 그 구간이 사건의 시작·끝과 일치하지 않는다.

```
타일 클릭   그 구간 시작(= idx × 5초)으로 영상을 이동시킨다. 그게 전부다
경계 확정   재생해서 보고 I·O로 지정한다
```

## 5. 유형은 이미 정해져 있다 — 거기에 맞는 질의를 만든다

기존 라벨링과 방향이 반대다. 전에는 질의를 쓰고 유형을 붙였지만, P2는 **유형 배정이
먼저 동결**됐다(영상당 9건의 유형 구성이 사전등록돼 있다). 화면 상단의 유형을 보고 **그
유형이 성립하는 질의**를 찾는다.

| 유형 | 조건 |
|---|---|
| **자막형** | 말소리에 답이 있다. 화면을 안 보고 소리만 들어도 이 구간이라고 알 수 있다 |
| **장면형** | 화면에 답이 있다. 소리를 끄고 봐도 알 수 있고, 발화만으로는 알 수 없다 |
| **복합형** | 발화와 화면 양쪽이 필요하거나, 양쪽 모두로 알 수 있다 |

경계 판단:

```
화면에 박힌 글자(편집 자막·간판·표지판)는 **화면**으로 본다 → 장면형 쪽
발화는 있지만 질의가 가리키는 게 화면 속 사물이면 → 장면형
발화와 화면이 질의의 서로 다른 부분을 담당하면 → 복합형
애매하면 복합형으로 몰지 말고 더 결정적인 쪽을 고른다
```

장면형이 많은 영상은 **시트에서 먼저 고르는 편이 빠르다**(말로 언급되지 않는 장면을
찾아야 하므로). 해당 유형의 질의를 그 영상에서 도저히 만들 수 없으면 억지로 만들지 말고
메모칸에 사유를 적고 알려라 — 유형을 바꾸는 것은 동결된 배정을 흔드는 것이다.

## 6. 시각 지정 요령

```
좁게 잡는다        사건이 5초면 5초. 60초를 적으면 세그먼트 12개가 정답이 되어
                 "찾았다"의 기준이 느슨해진다
격자에 맞추지 않는다  5초 배수로 반올림할 필요 없다. 실제 경계를 적으면
                 파생 규칙이 알아서 처리한다
파생 규칙          1초 이상 겹치는 모든 세그먼트, 없으면 가장 많이 겹치는 1개
```

`gt_seg_idx`는 최종 검증(build)이 자동으로 만든다. **세그먼트 번호를 손으로 적지
않는다** — 그래서 UI에도 그 칸이 없다.

## 7. 질의문 쓰는 법

사람이 실제로 검색할 문장을 쓴다. 정답 구간을 **묘사하는 설명문**이 아니라 **찾을 때 칠
말**이다. 자동 생성·추천은 없다(있으면 그 GT는 오염된다).

```
좋다   철판에 반죽을 붓고 뒤집는 장면
좋다   숙소 도착해서 짐 풀면서 방 구조 설명하는 부분
좋다   지도 펼쳐놓고 다음 목적지 정하는 대화

나쁘다  장면 (너무 짧다 — 아무 구간이나 맞는다)
나쁘다  영상 12분 34초 부분 (시각으로 찾는 건 검색이 아니다)
나쁘다  화자가 "이제 반죽을 부어볼게요"라고 말하는 장면
        (발화를 그대로 옮기면 문자열 일치 문제로 변한다)
나쁘다  파란 옷 입은 사람이 왼쪽에서 세 번째 그릇을 드는 장면
        (사람이 이렇게 검색하지 않는다)
```

길이는 **10~30자 한 문장**이 적당하다. 같은 영상 안에서 두 질의가 같은 구간을 가리키지
않게 한다.

## 8. 저장·이어하기

```
저장       Ctrl+S. 세 칸(질의문·시작·끝)이 다 있어야 완료로 저장된다
임시 저장   입력칸을 벗어날 때마다 자동으로 CSV에 써 둔다 — 창을 닫아도 잃지 않는다.
          단 **완료로 세지 않는다**(진행률은 세 칸이 다 찬 행만 센다)
이어하기    다시 실행하면 첫 미완료 행에서 시작한다
목록 이동   왼쪽 아래 9건 목록을 클릭하면 그 질의로 바로 간다
```

## 9. 하지 말 것

```
캡션·자막 산출물 보기     UI에 그 경로가 없다. 따로 찾아 열지도 마라
검색 돌려서 위치 찾기      순위로 후보를 고르면 선정 자체가 오염이다
frame_human_kit 사용     rank로 항목을 고르는 도구다. 라벨용이 아니다
유형·query_id 변경        동결된 배정이다 (도구가 거부한다)
부분 평가                80건 썼다고 먼저 돌려보지 않는다 (build가 거부한다)
```

시트·영상에 글자가 보이는 것은 **영상 자체에 박힌 자막·간판**이다. 원본 증거이고
파이프라인 산출물이 아니므로 봐도 된다.

## 10. 최종 검증 — `build`

315건 전부 쓴 뒤:

```bash
python scripts/p2_label_intake.py build
```

통과하면 `label_kit/p2/p2_queries_staging.jsonl`이 생긴다(315행, `split="p2"`).
**본 질의 파일에 자동 병합하지 않는다.** UI는 이 단계를 자동으로 실행하지 않는다.

오류별 대처:

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `text가 비어 있다` | 미완료 행이 있다 | 315행 전부 채운다. 부분 제출은 받지 않는다 |
| `gt_start < gt_end여야 한다` | 시작 ≥ 끝 | 값을 고친다 |
| `영상 길이 …s를 넘는다` | 끝이 영상 밖 | 시각을 다시 확인한다 |
| `query_type을 바꿀 수 없다` | 유형 칸이 수정됐다 | 원래 값으로 되돌린다 |
| `배정에 없다` | query_id가 변경됐다 | 원래 값으로 되돌린다 |
| `query_id 중복` / `…행이다` | 행이 복사·추가·삭제됐다 | 행 구성을 원래대로 |

UI를 쓰면 위 오류는 대부분 저장 시점에 먼저 걸린다.

## 11. 다 쓴 뒤 (내가 한다)

```
1  build PASS 확인
2  staging JSONL sha256 동결
3  그 이후에만 최초 검색·평가 (scripts/p2_evaluate.py)
4  판정은 사전등록대로 — CI가 0을 포함하거나 half-width > 0.04면 "판정 불가"로 멈춘다
```

**평가 결과를 보고 질의·유형·경계를 고치지 않는다.** 고치면 그 표본은 확증용이 아니다.

## 12. 자주 나오는 실수

```
정답 범위를 넉넉하게 잡는다     → 좁게. 사건이 5초면 5초
5초 격자에 맞춰 반올림한다      → 실제 경계를 적으면 된다
발화를 그대로 옮겨 질의로 쓴다   → 검색할 말로 바꿔 쓴다
장면형인데 말로도 알 수 있는 곳  → 소리를 끄고도 알 수 있고 발화로는 알 수 없는 곳
한 영상에서 비슷한 질의 9개     → 서로 다른 구간·다른 사건으로 흩는다
시트만 보고 경계를 정한다       → 대표 프레임은 5초의 한 시점이다. 영상으로 확인
```

## 13. CSV를 직접 편집하고 싶다면

UI 없이 `label_kit/p2/p2_label_intake.csv`를 열어 써도 된다. 같은 파일이다. 단 인코딩이
**UTF-8**이라 엑셀에서 두 번 클릭하면 한글이 깨진다 — VS Code, 구글 시트, 또는 엑셀의
"데이터 → 텍스트/CSV 가져오기"(원본 형식 UTF-8)를 쓰고 저장할 때도 "CSV UTF-8"로
저장한다. 질의문에 쉼표를 쓰지 않는 게 안전하다. UI와 동시에 열어 두면 서로 덮어쓸 수
있으니 한쪽만 쓴다.
