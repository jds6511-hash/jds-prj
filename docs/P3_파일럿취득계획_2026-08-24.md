# P3 annotation logistics pilot — 취득 계획 (pilot-only 10편)

**상태:** 계획. 취득·반출·라벨 생성 전부 미실행.
**승인 범위:** rights-clearable 후보 탐색 + evidence 기록까지 GO. **외부 annotator에게
실제 전달은 HOLD.**

---

## 1. 이것이 무엇이고 무엇이 아닌가

목적은 하나다 — **외부 annotator 경로가 1,500행까지 확장 가능한지**를 50행으로 먼저 본다.
retrieval 결과를 만드는 것이 아니고 P3-A의 표본도 아니다.

```
이 계획      P3 annotation logistics pilot acquisition (별도 사건)
이 계획 아님   P3 main sample acquisition — **계속 HOLD**
```

**용어를 섞지 않는다.** HOLD 목록의 "표본 수집"은 main 300편을 뜻한다. 파일럿 10편은
별도 승인 사건이고, 승인 문구에도 그렇게 적는다.

**순서를 뒤집지 않는 이유.** 기존 35편의 권리를 전수 역추적하는 것을 먼저 하지 않는다.
파일럿에서 작업 시간이 너무 길거나 QC가 감당 안 되면 **외부 annotator 경로 자체를 버릴 수
있고**, 그러면 35편 역추적 노동이 전부 낭비된다. logistics feasibility가 먼저다.

---

## 2. 파일럿 10편이 만족해야 하는 것

**(A) 권리 — 이것이 선정의 1차 기준이다**

`docs/P3_반출권한감사_2026-08-24.json`의 7개 항목이 **증거와 함께** 기록돼야 한다.

```
basis                            직접 제작 / 명시적 라이선스 / 제공기관 약관 (근거 문서 링크·사본)
third_party_viewing_right        제3자가 원본을 열람할 수 있는가 (VDI·원격 경로)
third_party_delivery_right       제3자에게 사본을 전달할 수 있는가 (파일 전송 경로)
retention_redistribution_limit   사본 보관 기간·재배포 금지 조항
deletion_required_after_work     작업 후 삭제 요구가 있는가
identifiable_person_constraint   식별 가능 인물의 추가 제약
attribution_requirement          출처 표시 의무
```

**yes로 올라가지 않는 것** — 이건 도구가 막는다(`inference_allowed: false`).

```
공개 플랫폼에 올라와 있다는 사실만으로            → yes 아님
다운로드가 기술적으로 가능하다는 사실만으로       → yes 아님
연구 목적이라는 사실만으로                      → yes 아님
NDA·외주계약을 맺었다는 사실만으로               → yes 아님 (없던 권리가 생기지 않는다)
애매하면                                     → unclear 유지, 보내지 않는다
```

**(B) 작업 재현성 — 2차 기준**

deployment corpus와 동일한 표본일 필요는 없다. 다만 **작업 난이도와 workflow는 재현해야**
파일럿 수치가 1,500행 판단에 쓸 만하다.

```
길이       long-form (수십 분급). 짧은 클립은 탐색 부담을 재현하지 못한다
한국어 발화  있어야 한다 — 자막형·복합형 작업이 성립하려면 음성이 필요하다
장면 다양성  시각적으로 구분되는 장면이 여러 개 (장면형 질의 작성 가능)
유형 커버리지 10편에서 장면형·자막형·복합형 50행을 모두 배치할 수 있어야 한다
```

**(C) 격리 — 3차 기준**

```
pilot_only = true · eligible_for_p3_main = false   (도구가 동시 true를 거부한다)
main 300편·dev·P2·test·AI Hub 재사용분과 중복 금지
파일럿에서 본 영상은 이후 라벨이 오염되므로 영구 제외한다
```

## 3. 후보 소스 클래스 — 권리 명확성 순

**법적 판단은 이 문서가 하지 않는다.** 아래는 "어디를 먼저 확인할지"의 우선순위이고,
각 편은 실제 약관·라이선스 표기를 확인해 evidence로 기록해야 `yes`가 된다.

| 우선 | 소스 클래스 | 권리 명확성 | 취득 난이도 | 작업 재현성 |
|---|---|---|---|---|
| 1 | **직접 촬영·제작 영상** | 가장 명확 (보유자가 우리다) | 높음 (제작 노동) | 조절 가능 |
| 2 | **공공누리 제1유형 공공기관 영상** | 명확 (출처표시, 상업·변형 허용) | 낮음 | 좋음 (해설 발화 있음) |
| 3 | **CC BY / CC BY-SA 표기 영상** | 명확하나 표기 확인 필수 | 낮음 | 소스마다 다름 |
| 4 | **퍼블릭 도메인 아카이브** | 명확 | 낮음 | 한국어 long-form이 드물다 |
| 5 | 일반 플랫폼 표준 라이선스 영상 | **불명 — 후보 아님** | — | — |

**공공누리 유형을 반드시 확인한다.** 제1유형만 상업적 이용·변형이 열려 있고,
제2·3·4유형은 각각 상업적 이용 금지 / 변형 금지 / 둘 다 금지가 붙는다. 유형 번호를
evidence의 `basis`에 그대로 적는다.

**CC·공공누리는 저작권 라이선스이고 초상권·개인정보는 별개다.** 라이선스가 열려 있어도
식별 가능한 인물이 등장하면 `identifiable_person_constraint`에 그 사실을 적는다. 여기서
`unclear`면 그 편은 쓰지 않는다.

**공공기관 영상이라도 제3자 제공·재배포 조항을 따로 본다.** 이용허락 범위가 "열람"까지인지
"사본 전달"까지인지 갈리고, 그것이 곧 VDI 경로 대 파일 전송 경로의 선택이다.

---

## 4. 절차

```
1  후보 탐색           클래스 1~4에서 조건 (A)(B)(C)를 만족할 후보를 모은다
   → 검증: 후보 목록에 각 편의 라이선스·약관 URL과 유형 번호가 붙어 있다

2  evidence 기록        planning/rights_clearance.json에 편당 7개 항목 + 근거 링크·사본
   → 검증: 항목 미기록이 하나라도 있으면 audit이 unclear로 내린다 (fail-closed)

3  rights audit         python scripts/p3_rights_audit.py --out docs/P3_반출권한감사_*.json
   → 검증: pilot_only_cleared 10건 · pilot_gate(mode) allowed true

4  접근 경로 확정        delivery 10/10이면 파일 전달, viewing만 10/10이면 VDI 경로
   → 검증: 두 경로 모두 10/10이 아니면 편을 교체하거나 파일럿을 다시 HOLD

5  파일럿 실행 승인 요청  50행 사양(§7-2)·contract·QC 규약과 함께 사용자 승인
   → **여기서 멈춘다.** 승인 없이 전달·라벨 생성 없음
```

`pilot_gate`는 `require_pilot_only=True`로 호출한다 — 본 표본 후보를 파일럿에 끌어오는
것을 도구가 막는다.

---

## 5. 파일럿 규모와 기록 항목

50행 사양은 이미 동결됐다 — `docs/작업현황_2026-08-24.md` §7-2, 초안 §9-3(4).

```
10 영상 × 5 질의 = 50 GT 행 · 20%(10행) 2인 독립 중복 · 세 유형 분산
기록: minutes/row (median·p75·p90) · 유형별 시간 · manual replay · 제출 오류율 ·
     adjudication 필요율 · 규약 애매함 · 영상당 turnaround · 중단·실패
판단: "1,500행 수행 가능한가?" 하나
```

**시간이 길게 나와도 1,500 → 500으로 줄이지 않는다.** 그때는 P3-A 실행 가능성을 다시
묻는다 — 라벨 부담을 보고 최소 가치 효과나 정밀도 목표를 낮추는 것은 금지된 역방향
결정이다(초안 §11).

---

## 6. 경계

```
이 계획으로 하지 않는 것
  main 300편 수집 · 1,500 GT · 3B/4B 추론 · retrieval/evaluation
  파일럿 영상의 인덱싱(캡션·STT 생성) — 파일럿은 라벨 workflow만 본다
  파일럿 라벨을 P3-A GT로 쓰는 것
  권리 불명 영상의 외부 전달
  test 접촉 · M9 · 4B 채택 · deployment 변경

법적 판단
  이 문서와 도구는 **상태를 기록할 뿐 적법성을 판단하지 않는다.**
  증거가 있는 행만 yes로 간다. 출처명만 보고 추정하지 않는다.
```

파일럿 영상은 **인덱싱하지 않는다.** 캡션·STT를 만들면 blind bundle 규약에 걸리는 산출물이
같은 작업 디렉터리에 생기고, 파일럿의 목적(작업 시간 측정)에는 필요가 없다.

---

## 7. 승인 상태

```
GO         pilot-only 10편 rights-clearable 후보 탐색 · evidence 기록 · audit 실행
조건부 GO   50행 파일럿 실행 — pilot 10/10이 external_annotation_allowed=yes이고
           선택한 접근 경로(viewing 또는 delivery)로 gate PASS한 뒤
HOLD       외부 annotator에게 실제 전달 · main 300편 수집 · 1,500 GT ·
           inference·retrieval·evaluation · 4B 채택 · test/M9
```

**현재 audit 상태: 35편 전부 `unclear`, 파일럿 코호트 0/10.** 조건부 GO의 조건은 아직
하나도 충족되지 않았다.
