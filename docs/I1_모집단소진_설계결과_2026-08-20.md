# I1 — baseline-positive 층 소진. **어디까지가 fresh evidence인가** (2026-08-20)

이 문서는 실패 보고가 아니다. **어디까지 fresh하게 검증할 수 있고 어디부터는 할 수
없는지를 정확히 드러낸 설계 결과**다.

## 0. 무엇이 소진됐나

AI Hub 2×2 캡션 모집단 9,312 arm-instances에서 A116을 제외한 잔여:

| 셀 | 정의 | 전체 | A116 제외 후 |
|---|---|---|---|
| C0 | CJK 0 · 현행 미적중 | 8,430 | 8,114 |
| C2 | CJK 1–2 · 현행 미적중 | 800 | 734 |
| **C1** | CJK 0 · **현행 적중** | 1 | **0** |
| C3 | CJK 1–2 · 현행 적중 | 0 | 0 |
| **C4** | CJK 3–9 | 78 | **0** |
| **C5** | CJK 10+ | 3 | **0** |

**현행 detector가 적중하는 인스턴스는 이 모집단에 82건이 전부였고, A116이 그것을
전수 표집했다.** 즉 `baseline-positive strata`가 development에서 소진됐다.

## 1. 장기 결론 — 같은 모집단에서 추가 표집으로는 안 된다

> **whole-detector precision을 완전히 fresh하게 재검증하려면 같은 AI Hub 9,312
> 모집단에서 추가 표집하는 것으로는 불가능하다.** baseline-positive 층이 이미
> development에서 소진됐으므로 **새 모집단이 필요하다.**

이유는 산술이다. precision의 분모는 **규칙이 발동한 인스턴스**다. 현행 규칙의 발동은
정의상 C1·C4·C5뿐이고 그 잔여가 0이다. **현행 규칙의 fresh precision을 잴 표본이
존재하지 않는다.**

후보 규칙은 사정이 조금 다르다 — C2에서도 발동하므로 **C2에 한해 fresh precision을
잴 수 있다.** 그것이 이번 validation이 실제로 재는 것이다.

## 2. 그래서 이번 validation이 fresh하게 말할 수 있는 것

```
✅ fresh   C2(CJK 1–2)에서 후보 발동이 진짜 drift인가 — 새 규칙이 새로 건드리는 구역
✅ fresh   C0에서 신규 FP가 생기는가 — 구조적으로 0이어야 한다(불변식으로 검사)
❌ fresh 아님   현행 규칙의 precision — 발동 층 잔여 0
❌ fresh 아님   C4·C5 구역의 recall 성분
❌ fresh 아님   primary vs fallback 구분 — 차이가 C4 1건이었고 잔여 0
```

**전체 모집단 precision·recall을 내려면 C1·C4·C5의 development census를 이어받아야
한다.** 그 계산은 하되 **이름을 분리한다.**

```
fresh_strata_only            C0 · C2만
combined_with_carried_over   C1·C4·C5를 더한 값 — contains_carried_over: true
```

> **`fully fresh validation estimate` 같은 이름을 붙이지 않는다.**
> 코드가 그 문자열을 소스 검사로 금지한다.

## 3. 이 사실이 바꾸지 않는 것

**후보 freeze는 유효하다.** 후보는 development set에서 선언된 격자·선택 규칙으로
골랐고, 그 절차는 소진 여부와 무관하다.

**C2 validation은 표적을 벗어나지 않는다.** development 실측에서 세 규칙의 셀별
발동이 이랬다.

```
C4   현행 68/68 · primary 68/68 · fallback 67/68
C5   현행 3/3   · primary 3/3   · fallback 3/3
C2   현행 0/20  · primary 15/20 · fallback 15/20
```

**규칙 간 차이가 사실상 전부 C2에 있다.** 소진된 층은 세 규칙이 거의 일치하는
구역이다.

## 4. 새 모집단이 필요해지는 조건

다음 중 하나를 하려면 새 캡션 모집단이 필요하다.

```
현행 규칙의 fresh precision 재측정
C4·C5 구역(CJK 3자 이상)에서 후보의 fresh 성능 측정
primary vs fallback을 데이터로 구분
```

**후보 모집단** — `prec3_0818b` dev 3-arm 산출물(dev 3편 × 612세그 × 3 arm)이나 신규
영상의 캡션. 어느 쪽이든 **표집틀 변경이므로 새 사전등록이 필요하고 이 사이클에서는
하지 않는다.**

## 5. 재발 방지 — 앞으로 층을 소진시키지 않는 규칙

이번에는 A116에서 **C4를 24 → 전수로 바꾼 이탈**이 소진의 직접 원인이었다. 그 결정
자체는 당시 합리적이었다(모집단 78건, 표집오차 0, 사람 라벨 생성 전). **문제는 그
결정이 미래의 fresh validation 가능성을 소비한다는 점을 그때 적지 않은 것이다.**

> **모집단이 작은 층을 전수 표집하기 전에, 그것이 이후 fresh 재검증 가능성을
> 소진시키는지 확인하고 결과 문서에 적는다.**

전수 표집이 나쁜 것이 아니다. **소진된다는 사실을 그때 기록해야 나중에 설계가
막히지 않는다.**

## 6. 현재 상태

```
표집 완료   C2 60 · C0 24 = 84 인스턴스 / 83 프레임 / 65 영상, A116 겹침 0
라벨 대기   label_kit/i1_validation/  (README·시트 3장·full 83장·labels_v.csv)
메타 분리   label_kit/i1_validation_meta/manifest_v.json
분석 동결   docs/probes/i1_validation_analysis.py — 라벨 도착 전 커밋, 계약 20건
```

**라벨 완료 후 한 번만 평가한다.** 결과가 기대와 달라도 `R=1` 추가·새 특징·임계
재조정·C4 census 재사용을 하지 않는다. **C2 결과가 낮게 나와도 그것은 추가 튜닝
신호가 아니라 frozen candidate의 validation 결과다.**
