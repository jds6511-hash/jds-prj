## 1. STT — 계측기가 못 잰다는 것을 먼저 증명하고 접었다

**문제.** 빔5→그리디의 이득은 **ΔCER −0.0093**(KconfSpeech 실측, 유의)이다. 그런데
우리가 알아야 할 것은 CER이 아니라 검색 성능이고, 둘 사이 환산을 몰랐다. dev
재전사로 확인하려면 GPU를 쓰는데, **그 전에 "그만한 CER 변화가 검색 지표로 검출
가능한 크기인가"를 먼저 알 수 있다.**

**방법.** 자막에 알려진 크기의 문자 오류를 주입해 ΔCER 대비 ΔMRR 기울기를 냈다
(`docs/probes/stt_metric_sensitivity.py`, 생성 비용 0).

```
환산 계수 ΔMRR/ΔCER = 0.400
빔 이득 ΔCER 0.0093 → 기대 ΔMRR +0.0037 (자막단독 검출 한계 ±0.0911)
판정: 검출 불가 — dev 재전사로는 확인되지 않는다
```

검정력 4%다. **돌려도 "차이 없음"이라는 정보 없는 결과만 나온다.**

**따라서 취소한 것 2건.** ① 빔5→그리디 dev 검증, ② STT 하이브리드(Whisper 경계 +
Qwen 텍스트). 후자는 어제 CER에서 Qwen3-ASR이 현행을 유의하게 이겼기 때문에 계획한
것인데, 같은 환산을 대면 최고 후보로 갈아타도 기대 ΔMRR이 0.011 수준이라 역시
검출 한계 아래다.

**주의 — 이 환산은 상한이 아니라 근사다.** 주입 오류는 무작위로 흩어지지만 실제 ASR
오류는 고유명사·전문용어에 몰린다. 질의가 그런 단어를 담으면 같은 CER이라도 영향이
더 크다. **실제 효과가 이 추정보다 클 수 있다.** 방향을 단정하지 말고 자릿수만 봐라.

**같이 말해야 할 단서 3건.**

1. **다중비교 보정을 하면 주지표는 비유의다.** 사전 등록에 "보정 없음"을 명시했으므로

   Bonferroni(K=9, 99.44%)로 재면 **[−0.0310, +0.2131]로 넘어간다.** 발표에서
   물으면 이대로 답한다. 경합 부분집합은 하한 +0.0621이라 보정에도 버틴다.
2. **"Qwen3-VL이 낫다"가 아니라 "Qwen3-VL + P1이 낫다"다.** 같은 모델의 P0은
   유의하게 **나쁘다**(−0.0920). 프롬프트 하나로 Δ0.183이 움직이는데 이건 어떤
   모델 간 차이보다도 크다. 모델 효과와 프롬프트 효과가 아직 분리되지 않았다.
   (다만 3개 중 2개가 대조군을 넘었으므로 프롬프트 운만은 아닌 쪽으로 기운다.)
3. **경합 부분집합의 정의를 틀리면 안 된다.** 부분집합을 **기준 arm 성적**으로
   정의하면 "기준이 못한 질의"를 고르는 것이라 평균회귀가 붙어 다른 arm이
   자동으로 좋아 보인다(실제로 그렇게 계산했다가 Δ+0.2528이 나왔다). 사전 등록
   정의는 **노트북 현행분** 기준이고 그 값이 +0.1479다.

**아직 채택 판단을 하지 않는다.** 남은 arm(qwen3vl P3, varco 4, kanana 4)과
2단계 P4 5개가 더 나온다. **P4가 결정적이다** — 길이 제한을 없앤 대칭 조건에서
이 우위가 유지되는지가 "모델이 나은가"의 답이다.

**7B bf16이 3B-4bit보다 3배 빠르다**(14.3분 vs 43.3분). 4bit 역양자화 오버헤드다.
속도는 채택 기준이 아니지만(CLAUDE.md), 실험 처리량에는 영향이 크다.

### 길이 혼입 — "7B가 진 것"이 아니라 "7B는 시키는 만큼만 쓴다"

7B의 **절단율이 0.0~1.1%다. 토큰 상한에 안 걸린다.** P0의 "한 문장으로 묘사하라"를
곧이곧대로 지켜 스스로 멈춘다(P3에서는 37.9자까지). 3B는 같은 지시에서 계속 쓴다
(절단율 15~44%). 즉 1단계 비교는 **시각 이해력**과 **길이 지시 순응도**가 섞여 있다.

§2의 대조군이 혼입 크기를 준다 — **길이만으로 0.155가 움직인다.** 모델 간 차이
(0.03 수준)의 5배다.

**그래서 길이를 맞추고 다시 붙였다**(`docs/probes/caption_length_matched.py`,
판정 규칙을 **결과 생성 전에** 커밋 — `44f9057`, `meeting_purity.py` 선례).
GPU 미사용, 저장된 캡션을 자르고 재임베딩만 한다.

`qwen25_7b/P0` vs `qwen25_3b_4bit/P0` (동일 서버 생성분):

| 조건 | Δ MRR | 95% CI |

| 자연 길이 (64.9자 vs 127.1자) | **−0.0275** | [−0.1142, 0.0590] |

모델에게 불리하다. 그래서 `cut`(하한)과 `sent`(마지막 완결 문장까지, 운영 함수
`common.truncate_to_sentence`)를 같이 냈다.*

### 2단계 — 사전 등록 규칙이 발동했다

규칙: *"공통 길이에서 순위가 뒤집히면 → 1단계 우위는 길이 산물 → 길이를 여는
프롬프트를 전 모델 대칭으로 추가해 2단계 재측정."* 뒤집혔으므로 발동.

**P4** = 문장 수 제한 없음, 나머지 제약(보이지 않는 것 금지, 화면 글자 전사 금지)은
P0과 동일. `--max-new 256`으로 상한도 같이 연다.

격자 오염 방지 2건:
- `STAGE1_PROMPTS = [P0..P3]`을 기본값으로 고정. **P4는 사후 가설이라 기본 격자에
  넣지 않는다** — 섞으면 사전 등록 격자의 다중비교 구조가 바뀐다.
- arm 키가 `P4@256`으로 갈린다(`arm_key()`). 안 갈리면 128토큰 캡션을 256 arm이
  조용히 재사용해 "상한을 올려도 안 변한다"는 틀린 결론이 나온다. 회귀 테스트 있음.

**인정하는 혼입:** P4는 프롬프트와 토큰 상한이 같이 바뀐다. P4-vs-P0을 "프롬프트
비교"로 읽으면 안 된다. 전 모델에 대칭이므로 **모델 간 비교만** 유효하다.

## 4. 생성 환경 효과가 재현됐다

`3b_4bit/P0`은 현행과 **같은 모델·양자화·프롬프트·그리디**인데 0.4609다.
노트북 생성분(`cur_laptop`)은 0.5535. **차이 −0.093.**

2026-08-07에 잰 환경 효과(Δ−0.0879 CI [−0.158, −0.023])와 거의 같다. **재현됐다.**

따라서 **후보 arm을 `cur_laptop`과 직접 비교하면 안 된다.** 대비 기준선은
같은 서버에서 현행 설정으로 새로 만든 `3b_4bit/P0`이다(규약 4항). 확정 인덱스의
캡션을 다른 환경에서 재생성하지 마라 — 새 영상만 그 영상만 돌린다.

## 5. 2인 라벨링 일치도 — 도구 완성, 라벨러 대기

구현가이드 9-1(c)가 약속만 하고 미이행이던 항목. 사용자가 **선택지 B**(유형 태그만
제2 라벨러)를 택했고, 표본은 예시의 30~40건 대신 **test 39건 전량**으로 했다 —
지적 대상이 test 라벨이고 39건이면 표집 편향 없이 전수로 끝난다.

`scripts/labeling_agreement.py` (커밋 `8cdcd32`, 테스트 16건):
- `kit` — GT 구간 ±2초 클립 39개 + 맹검 CSV + 판정 가이드. **CSV에 `query_id`도
  안 넣는다**(정답 파일과 육안 대조 차단). seed 고정 셔플, `_keymap.json` 분리.
  클립은 **재인코딩** — `-c copy`는 컷이 키프레임으로 밀려 구간이 어긋난다.
- `score` — Cohen's kappa(주지표) + percent agreement(병기) + 혼동행렬 + 불일치 목록.
  미기입 1건이라도 있으면 중단(부분 채점 = 사후 표본 선택).
  **양쪽 다 단일 범주면 kappa `None`** — 1.0을 주면 "완벽한 일치"로 읽히는 오보다.

산출물 `label_kit/`은 추적하지 않는다(클립 123MB, seed 고정이라 재생성 가능).

**한계로 보고할 것:** 유형 판정 가이드가 **원 라벨 작성 후에 성문화**됐다. 사후성은
kappa를 낙관 쪽으로 민다.

**상태: 제2 라벨러 배정 대기.** 확보 전까지 (c)항을 이행한 것으로 쓰지 마라.

## 7. 외부 벤치마크 — 예상질문 Q18에 정리, 불리한 결과 포함

**불리한 결과를 먼저 적었다.** 외부 사후 α 곡선이 **단조 감소**다 — α=0.0에서

묘사문이라 사실상 전부 장면형이고 60초 클립에 발화가 적기 때문이다.

어느 코퍼스에나 최적이다. α가 config가 아니라 CLI 주입값인 것이 여기서 방어가 된다.

절대값 비교 금지도 명시(외부 60초·12세그먼트 vs 본 test 122~357세그먼트).

## 10. 채택이 걸리면 딸려오는 것 (미리 알고 있을 것)

캡션 모델을 바꾸면 단독으로 끝나지 않는다. **한 묶음으로 처리한다:**
α 재탐색 → abstention τ 재캘리브레이션(임베더·인덱스 종속) → M8/M9 재실행 →
**test 재평가(접촉 8회차)**. test 재평가는 **사용자 승인 필수**다(CLAUDE.md 절대규칙 1).

그래서 채택 판단은 개별 arm이 나올 때마다 하지 않고 **전 arm 종료 후 한 번에** 한다.
