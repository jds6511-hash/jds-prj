## 1. 이번 작업에서 한 것

### 1-1. 감사 (코드 변경 전)

`docs/finalization/END_TO_END_AUDIT_2026-08-25.md` — M1~M9 단계별 entrypoint · 필요 입력 ·
산출물 · 의존 · 실패 조건 · 상태 · 노출 · 테스트를 표로 정리했다. 새 수치를 계산하지 않았다.

감사에서 나온 실질 gap은 **preflight 부재 하나**였다. 검색 UX·재생·근거 표시는 이미
구현돼 있었다(`/api/search` 응답에 점수·자막·캡션·raw 통계·abstention 경고, 프런트에
순위·seek·Range 재생).

`scripts/demo.py` · 테스트 23건. 시작 전 11항목을 확인하고 하나라도 어긋나면 **실행하지
않는다.**

### 1-3. 검색 결과 스키마 보완

`/api/search` 응답에 `rank` · `seek_to` · `video_id` · `query` · `alpha` · `top_k` ·
`n_segments` · `duration_sec`를 추가했다. 배열 순서에 의존하지 않고 결과를 파일·보고서로
옮길 수 있다. `top_k`는 요청 가능(기본 3, 구간 수 상한, 0 이하는 400) — **표시 계층
파라미터이고 랭킹·점수·평가에 영향이 없다.** 프런트는 서버가 준 `rank`·`seek_to`를 쓰고
구간 종료시각도 함께 표시한다.

### 1-4. AAR 추적 렌더러 (신규)

`scripts/aar_view.py` · 테스트 13건. **LLM을 부르지 않는다.** `report.json`을 읽어
문장마다 `cites → spans(start~end) → time_range → seek_to → evidence(자막·캡션)`를 잇고,
잇지 못하면 `TraceError`로 막는다(범위 밖 인용 · 인용 없는 문장 · video_id 불일치 ·
schema_version 미지원). 새 서술을 만들지 않는다.

`cited_fraction`은 기술값이고 **M9 coverage 지표가 아니다.** 산출물에
`m9_evaluated: false` · `test_split_used: false`를 박았다.
