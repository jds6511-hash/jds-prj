## 4. 보강 3건 (리뷰 반영)

**4-1. M8 실행의 두 이름을 분리했다.** 발표 문서만 보면 "M8 HOLD라면서 M8을 돌렸다"로
읽힐 수 있어서 이름을 갈랐다.

```
AAR demo generation using existing M8 pipeline = finalization functional run   가능
M8 research evaluation / taxonomy / human review = HOLD
```

`aar_view` 산출물에 `run_kind: "aar_demo_render"` · `m8_research_evaluation: false`를
박아 파일만 봐도 구분되게 했다. demo generation은 dev/demo 영상만 · 목적은 기능 확인과
발표 fallback · 그 결과를 연구 결론·M8 PRIMARY·6분류 라벨로 쓰지 않는다.

**4-2. `abstention` 표현을 실제 동작에 맞췄다.** 확인 결과 거부 규칙이 없다 —
DESIGN_SPEC 8-2 표에 **"abstention | max(sub,cap) 채널·τ=0.55 (UI 배너만, 랭킹 불변)"**.
결과를 숨기거나 "결과 없음"을 반환하지 않는다. 따라서 사용자 대면 문구를
**low-relevance 경고 / low-relevance robustness 예시**로 바꿨다. config 키
`abstention_tau`는 동결값이라 그대로 둔다.

**4-3. 발표 AAR fallback을 구조로 만들었다.** 서버·20GB GPU가 발표 당일 죽어도 데모가
무너지지 않게 한다.

```
aar_view.check_precomputed()   예외 대신 사용 가능 여부만 보고 (시연 직전 점검용)
n_segments 대조                 리포트 생성 시점 ≠ 현재 인덱스면 TraceError
                              (인용 번호가 다른 구간을 가리키는 것을 막는다)
preflight의 aar 필드            사전 생성물 상태를 함께 찍는다. 없거나 낡아도
                              **검색 데모는 막지 않는다** — 경고만
```

절차와 3단 fallback은 `docs/finalization/DEMO_REHEARSAL_2026-08-25.md`.
