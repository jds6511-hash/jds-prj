### 8-5. [B] 중간 결과 — 4B는 현행을 이겼다 (dev, 캡션 단독 α=0.0)

| arm | 생성 환경 | MRR | 비고 |
|---|---|---|---|
| 현행 3B-4bit (노트북 저장분) | 노트북 | 0.5535 | **대비 기준선으로 쓰지 않는다**(규약 4항) |
| **현행 3B-4bit (서버 재생성)** | 서버 | **0.4609** | ← 동일 환경 대조군 |
| Qwen3-VL-4B bf16 / P1 | 서버 | **0.5590** | 대조군 대비 **+0.098** |
| Qwen3-VL-4B 4bit / P1 | 서버 | 0.4915 | bf16 대비 **−0.068** |

- **동일 환경 대조군 대비 +0.098은 dev 96의 검출 한계 ±0.086을 넘는다.** 4B bf16은
  현행보다 낫다고 말할 수 있다. `cur_laptop`(0.5535)과 비교하면 +0.006이라 아무것도
  아닌 것처럼 보인다 — 규약 4항이 왜 있는지 보여주는 사례다.
- **재현 확인**: 같은 서버·같은 설정으로 8월 10일과 오늘 두 번 생성했다.
  4B P1 0.5522 → 0.5590, 4B 4bit 0.4918 → 0.4915. 오염 캡션 재시도가 샘플링이라
  완전 동일하지는 않지만 결론은 흔들리지 않는다.
  *다만 이건 같은 표본 재측정이라 **R3 기준으로 재현이 아니다**. 독립 표본(AI Hub
  562)에서는 3B 0.4872 vs 4B 0.5127로 Δ+0.026이고 그쪽 검출 한계는 ±0.036이라
  **판정 불가**다. 채택 근거를 dev 하나로 쓰지 마라.*
- **4bit 손실 −0.068이 남은 arm의 해석을 좌우한다.** 32B·30B-A3B는 24GB에서 4bit로만
  올라간다. 그 arm이 4B bf16에 못 미쳐도 "모델이 작아서"가 아니라 "양자화 때문"일 수
  있다. 결과에 반드시 병기한다.
