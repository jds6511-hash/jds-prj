# `4B − 3B` 부호 역전 — heterogeneity localization (2026-08-18)

사전등록: `docs/preregistration/부호역전_조사_사전등록_2026-08-18.md` (`0f1b0cc`).
분석 코드: `docs/probes/sign_reversal_diag.py` — **결과를 보기 전에 커밋됐다.**
산출: `docs/probes/_scratch/sign_reversal_diag.json`.

> **이 문서는 원인을 확정하지 않는다.** 산출은 국소화 + 확증 설계다(사전등록 §1).
> 기존 두 표본만으로 참 효과의 부호를 확정할 수 없다 — AI Hub는 이미 선택에
> 사용됐고(장벽 1번) dev는 영상 3편이다.

## 0. 관측 — 두 평가의 구간이 서로를 배제한다

캡션 단독(α 미개입) `4B/P0 − 3B/P0`:

| 표본 | Δ | CI | 단위 |
|---|---|---|---|
| AI Hub 1,086질의 (`85e47f7`, C3_model_under_P0) | **+0.0310** | [0.0101, 0.0533] p=0.004 | 194 video-cluster |
| dev 96질의 (`prec3_0818b`) | **−0.0903** | [−0.2112, −0.0276] | 3 video-cluster — **진단용만** |

**AI Hub 구간은 194 cluster에서 0을 배제한다.** dev 구간도 0을 배제하지만 cluster가
3이므로 사용자 제약에 따라 **formal gate로 쓰지 않는다**. 그래도 점추정 부호가
반대라는 사실은 남는다. 정밀도는 원인이 아니다 — `Δ_quant = +0.0091`(§5-9).

## 1. pipeline parity audit — 기록된 필드는 전부 일치

`sign_reversal_diag.json:parity_audit`, dev 3-arm 내부 대조:

| 필드 | 값 | 일치 |
|---|---|---|
| `prompt_sha256` | `b7c2598a…` 양쪽 동일 | ✅ |
| `attn_implementation` | `sdpa` | ✅ |
| `dtype` | `torch.bfloat16` | ✅ |
| `config_vlm_max_pixels` | 602112 | ✅ |
| `config_vlm_max_new_tokens` | 128 | ✅ |
| `config_vlm_rep_penalty` | 1.1 | ✅ |
| `effective_quantized` | 양쪽 `true` | ✅ (arm마다 달라도 정상인 축) |

**dev 3-arm 내부에서는 조건 차이로 부호를 설명할 수 없다.** 추가로 SECONDARY §7-(4)-1에서
**α=1.0(자막 단독)이 세 arm 전부 0.4144로 동일**했다 — 자막 채널·index·evaluator가
동일하고 바뀐 것은 캡션뿐이라는 기계적 확인이다.

### 1-1. 코드가 못 본 parity 항목 2건 — 여기서 적는다

**(a) `effective_model_revision`이 어느 arm에도 기록돼 있지 않다.** 전부 `None`이라
`_parity()`가 항목을 건너뛰었다. 사전등록 §2-(1)이 명시한 항목인데 **측정 자체가 없다.**
→ 확증 설계의 필수 기록 항목으로 올린다.

**(b) 두 표본의 후보 풀 크기가 한 자릿수 대 세 자릿수다.** 이것이 이번 조사에서 나온
가장 큰 비교 가능성 결함이다.

| | AI Hub | dev |
|---|---|---|
| 질의당 후보 세그먼트 | **12개 (전 질의 동일)** | **149 / 314 / 149** |
| 영상 수 · 총 세그먼트 | 194편 · 2,328 | 3편 · 612 |
| GT 세그먼트 수 (median) | — | 1 |
| 정답 1개 가정 무작위 MRR | **0.2586** | **0.0375 / 0.0202** |

AI Hub 영상은 12세그먼트(=60초)다. **같은 MRR 0.47이 두 표본에서 같은 난이도를 뜻하지
않는다** — 무작위 기준선이 0.26 대 0.02~0.04다. 자막 단독 MRR이 우연히 비슷한 것도
(0.4107 vs 0.4144) 난이도가 같다는 증거가 아니다.

> **이것을 부호 역전의 원인으로 단정하지 않는다.** 후보 풀이 12개면 캡션 품질 차이가
> 순위에 반영될 여지 자체가 좁다는 것은 **가설**이고, 이 배치로 검증되지 않았다.

## 2. paired RR 분포 — 소수 질의가 만든 것이 아니다

`4B q4 − 3B 4bit`, dev 96질의:

```
n=96   mean −0.0903   median 0.0000
부호   양수 32   음수 47   0 17
합     양수 +10.2527   음수 −18.9227
극단   min −0.9900   max +0.8571
```

**음수 질의가 47건이다.** 상위 몇 건을 빼도 남는다는 뜻이고, 단일 이상치 가설은 여기서
지지되지 않는다. 동시에 **양수도 32건**이라 일방적 열세도 아니다.

bf16 참고 대비(`4B bf16 − 3B 4bit`)는 −0.0994, 양수 33 / 음수 48. **양자화와 무관하게
같은 패턴**이고 `Δ_quant ≈ 0`과 방향이 같다.

## 3. 영상 분해 + LOVO — 한 영상이 크기를 지배하지만 부호는 아니다

| 영상 | n | Δ | 4B MRR | 3B MRR | +/−/0 |
|---|---|---|---|---|---|
| `kheritage_grave_excavation` | 30 | **−0.2112** | 0.1922 | 0.4033 | 7/21/2 |
| `_10_000_…Wilderness` | 36 | −0.0418 | 0.4510 | 0.4928 | 15/12/9 |
| `gwaktube_soviet_apartment` | 30 | −0.0276 | 0.4636 | 0.4913 | 10/14/6 |

leave-one-video-out:

```
kheritage 제외 → −0.0354   (부호 유지, 크기 1/6)
_10_000   제외 → −0.1194
gwaktube  제외 → −0.1188
sign_flips_vs_overall: 세 영상 모두 false
```

**kheritage가 −0.0903의 크기를 지배한다** — 그 영상에서 4B 캡션 MRR이 0.1922로
현행 0.4033의 절반 아래다. 하지만 **어느 영상을 빼도 부호는 뒤집히지 않는다.**
즉 dev 안에서는 "한 영상 탓"으로 부호를 지울 수 없다. 영상 3편이므로 **LOVO가
사실상 유일한 민감도 분석**이라는 한계도 그대로다.

## 4. query type 층 — `queries.jsonl:type` 값 그대로

| type | n | Δ | +/− |
|---|---|---|---|
| 복합형 | 34 | **−0.2407** | 7/20 |
| 자막형 | 24 | −0.0412 | 10/13 |
| 장면형 | 38 | **+0.0132** | 15/14 |

**장면형에서는 4B가 근소하게 앞선다.** 캡션 채널에 가장 의존하는 층에서 열세가 없고,
`복합형`이 −0.0903 전체를 끌고 간다.

> **층을 결과를 보고 만들지 않았다** — 세 값은 라벨 파일에 원래 있던 것이고,
> 코드가 `ALLOWED_STRATA = ("type",)`로 막고 있다.

이 표는 **확증 설계에서 반드시 층으로 유지해야 할 축**을 지목한다. 새 표본이 장면형에
치우치면 부호가 재현되지 않을 수 있고, 그것을 모델 효과로 오독하게 된다.

## 5. exploratory — 인과 주장 아님

```
corrupted     4B q4 14건   3B 4bit 3건     (4~5배)
len_mean      4B q4 74.6   3B 4bit 127.1   (약 0.59배)
```

`sign_reversal_diag.json:exploratory.label = "exploratory_not_a_cause_claim"`.

**4B 캡션이 짧고 오염이 많다는 것과 Δ가 음수라는 것은 같은 배치의 두 관측이다.**
연관을 인과로 쓰지 않는다. 오염 수는 arm 수준 집계여서 질의 수준 Δ와 직접 연결되지
않는다(사전등록 §2-(5)).

관련 사실 1건 — I1 detector의 CJK-drift recall은 **0.0815**로 추정됐다
(`재분석_I1검증셋B`). **오염 14건은 실제 오염의 하한이고, 두 arm의 실제 오염 격차는
측정되지 않았다.**

## 6. 3B baseline 교차표본 대조 — **차이는 4B arm에 있다**

캡션 단독 MRR:

| | AI Hub 1,086 | dev 96 | 차 |
|---|---|---|---|
| 자막 단독 (α=1.0) | 0.4107 | 0.4144 | +0.0037 |
| **현행 3B 캡션** | 0.4773 (bf16) | 0.4644 (4bit) | −0.0129 |
| **후보 4B 캡션** | 0.5083 (bf16) | 0.3650 (bf16) | **−0.1433** |

**두 표본에서 자막 채널과 현행 3B는 근접한 값에 떨어지는데, 4B만 0.14 떨어진다.**
이번 조사에서 나온 가장 좁은 국소화다 — **부호 역전은 3B baseline이 움직여서 생긴 것이
아니다.**

세 가지 유보를 같이 적는다.

1. **두 표본은 서로 통제된 대조가 아니다.** 절대 MRR이 원래 다를 수 있고(사전등록 §2-(6)),
   §1-1(b)의 후보 풀 12 대 149~314가 그 차이를 크게 만든다. 자막·3B가 비슷하게
   떨어진 것은 **우연일 수 있다.**
2. **AI Hub 3B arm은 bf16, dev 3B arm은 4bit**다. 표본이 다르므로 이 차이를 분리할 수 없다.
3. **AI Hub에는 `type` 라벨이 없다**(`domain` 3종: 드라마·여행·요리음식). §4의 층을
   교차표본으로 대조할 수 없다.

## 7. 국소화 요약 — 무엇이 좁혀졌고 무엇이 남았나

**좁혀진 것**

```
✅ 정밀도(4bit)가 원인이 아니다 — Δ_quant +0.0091, bf16 참고 대비도 −0.0994
✅ 소수 질의 이상치가 원인이 아니다 — 음수 47건
✅ dev 내부 조건 차이가 원인이 아니다 — 기록된 parity 필드 전부 일치, α=1.0 동일
✅ 3B baseline이 움직인 것이 아니다 — 두 표본에서 3B·자막은 근접, 4B만 −0.1433
✅ 융합·α가 구제하지 않는다 — α 0.0~0.9 전 구간에서 3B가 높다 (§7 SECONDARY)
```

**남은 후보 (전부 미검증)**

```
❓ 후보 풀 크기 (12 vs 149~314) — 캡션 품질이 순위에 반영될 여지의 차이
❓ query type 구성 (장면형 +0.0132 vs 복합형 −0.2407) — AI Hub에는 type 라벨이 없다
❓ 도메인 (AI Hub 드라마·여행·요리 vs dev 다큐·리뷰 계열)
❓ 영상 길이·세그먼트 밀도 (60초 vs 12~26분)
❓ 캡션 길이 74.6 vs 127.1 및 오염 격차 — exploratory
❓ effective_model_revision — 어느 표본에서도 기록되지 않았다
```

**어느 표본이 "맞는지"는 이 배치로 판정하지 않는다.** 확증 설계는
`docs/preregistration/부호역전_확증_사전등록_2026-08-18.md`에 별도로 등록한다.
