## 4. 원인 — 모델이 아니라 설계

```
현재 모델   Qwen2.5-7B-Instruct       저장된 출력 재사용
비교 모델   Kanana-1.5-8B-Instruct    신규 4호출 · 패치 0 · 사전등록 후 실행
EXAONE-3.5  IMPLEMENTATION_BLOCKED · 과학적 결과 없음
```

붕괴 형태는 **경계 번호의 등차 열거**였다.

```
arm                      최장 연속정수   등차열
Qwen   caption chunk3          1        2칸@59     정상
Kanana caption chunk3         52        3칸@2      붕괴
Qwen   full    chunk5         26       16칸@2      붕괴
Kanana caption chunk5         23        2칸@2      붕괴
```

**조건을 바꾸면 어느 모델이든 붕괴한다.** 따라서 추가 모델 비교를 중단했고, 문제를
"LLM에게 시간 경계를 자유롭게 고르게 한 설계"로 특정했다.

보조로 캡션 임베딩 거리 peak로 경계를 잡을 수 있는지 봤으나 `MIXED_SIGNAL`이었고
(`C0_BOUNDARY_SIGNAL_OBSERVATION_2026-08-30.md`), **관찰만 하고 채택하지 않았다.**

## 6. 검증 방식

테스트 통과만으로는 부족하다고 보고, **금지한 변화를 실제로 주입해 테스트가 깨지는지**를
티켓마다 확인했다.

```
Gate A   A-11 가드 mutation 포함
Gate B   실패 주입 9종
C-01 4 · C-02 7 · C-03 7 · C-04 8 · C-05 10 · C-06 10 · C-07 10 · C-08 9 · C-09 8
```

이 과정에서 **가드가 실제로는 아무것도 막지 못하던 경우 8건**을 찾았다. 대부분
같은 부류였다.

```
문서 전체 문자열 검사가 다른 절에 가려진다        C-04 · C-05 · C-06 · C-07
테스트가 실패 사유를 특정하지 않아 다른 검사가 대신 걸린다   C-04 · C-05
테스트가 그 경로를 실제로 태우지 않는다             C-09 4건
```

코드가 아니라 **테스트를 좁혀** RED로 만들었고, 이후에는 처음부터 단위(행·블록·
사유 문자열)로 검사한다.
